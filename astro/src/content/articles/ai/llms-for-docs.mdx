The world is changing. Developers increasingly turn to chatbots, agents, and other LLM-powered assistants for formerly-human tasks like programming and reading documentation. Those assistants need a user manual to use software. And when things get especially tricky (or when developers want to flex their programming muscles manually), humans still read the docs. Now documentation has two audiences: humans, and machines. So how do we build the best documentation for both?

## Metrics

Before we start on any major project, we like to define our metrics of success. In the software world, this is often performance or usability scores. Or you might aim for feature parity with another project.

In the world of documentation, metrics are both easy and hard. On one hand, with logging and tools like Google Analytics, we can keep track of user activity on the docs site. On the other hand, it's very difficult to tell the _quality_ of a visit: did a user open a page, find an answer, and leave? Or did they lose interest because the page was too long?

Fortunately, we don't have to track usage metrics for this. Instead, we used an open-source tool called [afdocs](https://www.afdocs.dev/) to check a few key metrics for our site. Because this tool is open source and runs on the command line, you can locally run the very same metric that we use:

```shell-session
npx afdocs check https://fusionauth.io/docs --format scorecard
```

This metric measures a few important aspects of our AI strategy:

* **content discoverability**: our site should include an llms.txt index that helps agents explore the site
* **markdown availability**: HTML pages are styled for human consumption; agents (and some humans) prefer token-lean markdown alternatives
* **page size and truncation risk**: if nobody has optimized your page size in human memory, you can probably cut out a lot of cruft, even in a static site
* **content structure**: let's ensure that links, code blocks, and other non-prose page contents are well-formatted

AFDocs was a great starting point for us: we originally got an F. Once we maxed out those scores, we turned to more advanced metrics: an internal agent benchmark that demonstrates how FusionAuth measures up against the competition when used to accomplish basic auth tasks like adding a login, enabling SSO, and more.

## Automation

Here at FusionAuth, we have a small team. We only have one dedicated documentation writer. So it doesn't make sense to waste documentation writing/development/review time on anything that we can automate away.

## Skepticism

AI best practices are a moving target. In the industry, in your organization, in professional group, probably even in your friend group, there are many opinions. Some of them are probably even correct. But many contradict. So how do you know what recommendations to follow, and which to ignore?
