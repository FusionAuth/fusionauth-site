This quickstart secures a Ruby on Rails API resource server with FusionAuth using a preconfigured, local version of FusionAuth in the following steps:

1. Run FusionAuth with Docker.
1. Create a new Rails API application.
1. Add routes, JWT-based authentication, and controllers for two protected endpoints.
1. Get a token and call the protected endpoints.

You'll be building the API for ChangeBank, a bank that converts dollars into coins. It has two endpoints:

* `make-change`: Call this with a `total` amount to get back the number of quarters, dimes, nickels, and pennies needed to make change. The `customer` and `teller` roles can both call this endpoint.
* `panic`: Tellers call this endpoint to alert the police in case of an incident. Only the `teller` role can call this endpoint.

Both endpoints require a valid JSON Web Token (JWT) in the `Authorization` header, and the JWT's `roles` claim must contain the role required by the endpoint.

## Prerequisites

This QuickStart requires:

* [Ruby](https://www.ruby-lang.org/en/downloads/) 2.7.x — this quickstart's `Gemfile` pins Ruby 2.7.5, which is [end-of-life](https://www.ruby-lang.org/en/downloads/branches/) and won't be available through most current OS package managers. Install it with a Ruby version manager such as [rbenv](https://github.com/rbenv/rbenv) or [rvm](https://rvm.io/).
* [Rails](https://rubyonrails.org/) 7.0.x
* [SQLite](https://www.sqlite.org/download.html) (macOS includes sqlite3 by default)
* [Docker](https://docs.docker.com/get-started/get-docker/) 23 or later, with [Docker Compose](https://docs.docker.com/compose/)
* On macOS and Windows, one of the following container management tools:
  * [Docker desktop](https://www.docker.com/products/docker-desktop/)
  * [OrbStack](https://docs.orbstack.dev/quick-start) (to use Orbstack for `docker compose` commands after install, run `docker context use orbstack`)
  * [Podman](https://podman.io/docs/installation) (in the commands below, replace `docker` with `podman`)

## Install and run FusionAuth

To begin, clone the [GitHub repository for this Quickstart](https://github.com/FusionAuth/fusionauth-quickstart-ruby-on-rails-api) to your local machine:

```bash
git clone https://github.com/FusionAuth/fusionauth-quickstart-ruby-on-rails-api
cd fusionauth-quickstart-ruby-on-rails-api
```

Open OrbStack or Docker Compose to start the docker daemon, then start a local instance of FusionAuth:

```bash
docker compose up -d
```

If you see an error that reads "Is the docker daemon running?", make sure your container management tool is accepting commands. Depending on your tool:
* to use Docker Compose, Docker Compose must be open
* to use Orbstack, enable OrbStack to run as the docker daemon with `docker context use orbstack`, then open the Orbstack app
* to use Podman, replace `docker` in the above command with `podman`

<Aside type="note">
During the Docker Compose process, the included `kickstart/kickstart.json` file uses the FusionAuth API to configure FusionAuth to a working state, including:

* Generating an API key and configuring CORS
* Creating the ChangeBank application, with a client Id of `e9fdb985-9173-4e01-9d73-ac2d60d1dc8e`
* Creating an admin user (`admin@example.com`, password `password`)
* Creating a teller user (`teller@example.com`, password `password`) with the `teller` role
* Creating a customer user (`customer@example.com`, password `password`) with the `customer` role
</Aside>

Once Docker Compose completes, open a browser window and navigate to the admin UI of your FusionAuth instance at [http://localhost:9011/admin](http://localhost:9011/admin). Log in with the admin credentials above to confirm FusionAuth is running and configured.

<Aside type="note">
If you ever want to reset FusionAuth to this initial state, delete the volumes created by Docker Compose with `docker compose down -v`, then run `docker compose up -d` again.
</Aside>

## Run the API

Start the API resource server. In a terminal window, navigate to the root directory of your application (`your-application`) and run:

```shell
bundle exec rails s -p 4001
```

<Aside type="note">
Leave the server running in this terminal and open a new terminal window for the remaining commands.
</Aside>

### Call the protected endpoints

<Aside type="note">
The code extracts the token from either a cookie or the `Authorization` header, so you can replace `--cookie 'app.at=<your_token>'` with `--header 'Authorization: Bearer <your_token>'` in the commands below if you prefer.
</Aside>

Call `/make-change` with a query parameter `total=1.02`, using the `token` as the `app.at` cookie:

```shell
curl 'http://localhost:4001/make-change?total=1.02' \
--cookie 'app.at=<your_token>'
```

Or pass the token in the `Authorization` header instead:

```shell
curl --location 'http://localhost:4001/make-change?total=1.02' \
--header 'Authorization: Bearer <your_token>'
```

Your response should look like this:

```json
{
  "Message": "We can make change using 4 quarters 0 dimes 0 nickels 2 pennies",
  "Change": [
    {
      "Denomination": "quarters",
      "Count": 4
    },
    {
      "Denomination": "dimes",
      "Count": 0
    },
    {
      "Denomination": "nickels",
      "Count": 0
    },
    {
      "Denomination": "pennies",
      "Count": 2
    }
  ]
}
```

You're authorized, success! Try the request again without `--cookie`, or with an invalid token, and you'll be denied access.

Now call `/panic`, since you're in trouble:

```shell
curl --location --request POST 'http://localhost:4001/panic' \
--cookie 'app.at=<your_token>'
```

This is a `POST`, not a `GET`, because emergency calls should be non-idempotent. Your response should look like this:

```json
{"message":"We've called the police!"}
```

Nice, help is on the way!

## Next steps

This is a quick introduction to using FusionAuth to secure an API. To learn more about integrating FusionAuth with your product, see [Get Started](/docs/get-started).

For a production API, consider:

* Using the [Authorization Code grant](/docs/lifecycle/authenticate-users/oauth/#example-authorization-code-grant) instead of the Login API, which keeps credentials within FusionAuth. You can customize the [hosted login pages](/docs/customize/look-and-feel/).
* Using the [Client Credentials grant](/docs/lifecycle/authenticate-users/oauth/#example-client-credentials-grant) to generate a token when calling the API from another service.
* Customizing [token expiration times and policies](/docs/lifecycle/authenticate-users/oauth/#configure-application-oauth-settings) in FusionAuth.
* Making sure you know how to [securely consume a token](/articles/tokens/building-a-secure-jwt#consuming-a-jwt).
* Securing your API [using an API gateway](/docs/extend/examples/api-gateways/) rather than at the framework layer.

FusionAuth has many other features (including [Social Login](/docs/lifecycle/authenticate-users/identity-providers/#social-identity-providers), [Single Sign-On](/docs/lifecycle/authenticate-users/single-sign-on), [Passwordless](/docs/lifecycle/authenticate-users/passwordless/webauthn-passkeys), [Multi-factor Authentication](/docs/lifecycle/authenticate-users/multi-factor-authentication)), most of which are free. Some require additional licensing. For details, see the [pricing page](/pricing).

You can ask general questions in [the FusionAuth forum](/community/forum).

## Troubleshooting

* I get `This site can't be reached localhost refused to connect.` when I call the Login API.

  Ensure FusionAuth is running in the Docker container. You should be able to log in as the admin user, `admin@example.com` with a password of `password`, at [http://localhost:9011/admin](http://localhost:9011/admin).

* The `/panic` endpoint doesn't work when I call it.

  Make sure you're making a `POST` call and using a token with the `teller` role.

* It still doesn't work.

  Pull down a complete running application and compare what's different:

  ```
  git clone https://github.com/FusionAuth/fusionauth-quickstart-ruby-on-rails-api.git
  cd fusionauth-quickstart-ruby-on-rails-api
  docker compose up -d
  cd complete-application
  bundle install
  bundle exec rails s -p 4001
  ```
