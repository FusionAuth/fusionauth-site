To add or change claims in a JWT, assign a lambda in the JWT configuration. FusionAuth runs the lambda before FusionAuth signs the token and issues the token to the user.

When you create a lambda in the Admin UI, FusionAuth provides an empty function for you to implement.

FusionAuth doesn't run this lambda when you call the Login API directly and omit the **`applicationId`** request parameter.

## Lambda Structure

When you create the lambda with the API, give the function the following signature:

```javascript
function populate(jwt, user, registration, context) {
  // Lambda code goes here
}
```

The lambda must contain a function named `populate` that accepts the following parameters:

* `jwt`: the claims object that FusionAuth signs and returns as the JWT payload. You can modify this object.
* `user`: the FusionAuth User object. This object is read-only.
* `registration`: the FusionAuth UserRegistration object. This parameter is `null` when the user is not registered for the application. This object is read-only.
* `context`: <AvailableSince since="1.59.0"/> an object containing the context of the request, including access to [secrets](/docs/lambdas#secrets). This object is read-only.

### The `jwt` Object

You can add or change any claim in the `jwt` object, except the header and the reserved claims. When adding a custom claim to the JWT, always use a namespace to avoid clashes with future standard or FusionAuth-specific claims. To remove a claim, set the claim to `null`. Deleting a claim with `delete` has no effect.

FusionAuth discards changes to the following reserved claims:

* `act`: <AvailableSince since="1.70.0"/> the actor claim chain, which token exchange manages
* `amr`
* `auth_time`
* `authenticationType`
* `cnf`
* `fa_uid`
* `gty`
* `iat`
* `sub`
* `tid`
* `tty`

Starting in version `1.59.0`, you can lower the `exp` claim to shorten the lifetime of the token. FusionAuth caps `exp` at the lifetime configured for the application, so a lambda can't extend the lifetime. You can't remove `exp`. FusionAuth keeps the original value when you set `exp` to `null`. A shorter lifetime helps when one FusionAuth application issues tokens for several contexts. For example, the requested scopes in `context.scopes` can tell the lambda to issue a short-lived token.

The `authenticationType` claim holds the authentication method, such as `PASSWORD`, `REFRESH_TOKEN`, `PASSWORDLESS`, or `JWT_SSO`. Read `jwt.authenticationType` to change the claims by login method.
