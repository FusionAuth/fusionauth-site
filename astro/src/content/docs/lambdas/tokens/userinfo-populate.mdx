To add or change claims in the UserInfo response, assign a lambda in the Application's OAuth configuration.

When you create a lambda in the Admin UI, FusionAuth provides an empty function for you to implement.

## Lambda Structure

When you create the lambda with the API, give the function the following signature:

```javascript
function populate(userInfo, user, registration, jwt, context) {
  // Lambda code goes here
}
```

The lambda must contain a function named `populate` that accepts the following parameters:

* `userInfo`: the claims object that FusionAuth returns as a JSON payload. You can modify this object.
* `user`: the FusionAuth User object. This object is read-only.
* `registration`: the FusionAuth UserRegistration object. This parameter is `null` when the user is not registered for the application. This object is read-only.
* `jwt`: the claims object from the provided JWT. This object is read-only.
* `context`: <AvailableSince since="1.64.0"/> an object containing the context of the request, including access to [secrets](/docs/lambdas#secrets). This object is read-only.

The [User API](/docs/apis/users) and [Registration API](/docs/apis/registrations) documentation describe the `user` and `registration` objects. For the claims in the `jwt` object, see [OpenID Connect & OAuth 2.0 Token](/docs/authentication/oauth/tokens).

You can add, remove, or change any claim in the `userInfo` object, except the reserved claims. To remove a claim, set the claim to `null`. Deleting a claim with `delete` has no effect. FusionAuth discards changes to the following reserved claims:

* `email`
* `email_verified`
* `phone_number_verified`
* `sub`
* `tid`

## Assigning the Lambda

After you create the lambda, assign the lambda to an Application on the <Breadcrumb>OAuth</Breadcrumb> tab of the Application configuration.
