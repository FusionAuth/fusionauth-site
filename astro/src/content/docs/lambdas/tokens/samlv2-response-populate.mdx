To customize the SAML response for a service provider, assign a lambda to a FusionAuth application that acts as a SAML Identity Provider (IdP). FusionAuth runs the lambda before FusionAuth sends the SAML response to the service provider.

When you create a lambda in the Admin UI, FusionAuth provides an empty function for you to implement.

## Lambda Structure

When you create the lambda with the API, give the function the following signature:

```javascript
function populate(samlResponse, user, registration, context) {
  // Lambda code goes here
}
```

The lambda must contain a function named `populate` that accepts the following parameters:

* `samlResponse`: the SAML v2 response object. You can modify this object.
* `user`: the FusionAuth User object. This object is read-only.
* `registration`: the FusionAuth UserRegistration object. This parameter is `null` when the user is not registered for the application. This object is read-only.
* `context`: <AvailableSince since="1.64.0"/> an object containing the context of the request, including access to [secrets](/docs/lambdas#secrets). This object is read-only.

The [User API](/docs/apis/users) and [Registration API](/docs/apis/registrations) documentation describe the `user` and `registration` objects. ## Assigning the Lambda

After you create the lambda, assign the lambda to one or more Applications on the <Breadcrumb>SAML</Breadcrumb> tab of the Application configuration.

## Example Lambdas

### Map Attributes for a Service Provider

FusionAuth adds default attributes to the assertion, such as `email`, `first_name`, and the `http://schemas.xmlsoap.org/ws/2005/05/identity/claims/emailaddress` form of each name. Many service providers expect their own attribute names instead. The following lambda replaces the default attributes with the names a service provider expects. Some service providers accept one role per user. For a lambda that picks one role from the user's roles, see the [Zendesk](/docs/authentication/act-as-an-idp/saml/zendesk) integration.
