A client credentials JWT populate lambda adds claims to the access token FusionAuth issues for the [Client Credentials grant](/docs/authentication/oauth#example-client-credentials-grant). FusionAuth runs the lambda before signing the token for the Entity.

When you create a lambda in the Admin UI, FusionAuth provides an empty function for you to implement.

## Lambda Structure

When you create the lambda with the API, give the function the following signature:

```javascript
function populate(jwt, recipientEntity, targetEntities, permissions, context) {
  // Lambda code goes here
}
```

The lambda must contain a function named `populate` that accepts the following parameters:

* `jwt`: the claims object that FusionAuth signs and returns as the JWT payload. You can modify this object.
* `recipientEntity`: the Entity requesting the token. This object is read-only.
* `targetEntities`: the Entities the token grants access to, keyed by Entity Id. This object is read-only.
* `permissions`: the granted permission names, keyed by target Entity Id. This object is read-only.
* `context`: <AvailableSince since="1.64.0"/> an object containing the context of the request, including access to [secrets](/docs/lambdas#secrets). This object is read-only.

The [Permissions & Entity Types APIs](/docs/apis/entities/entity-types) and [Entities API](/docs/apis/entities/entities) documentation describe the `recipientEntity` and `targetEntities` objects. For the claims in the JWT payload, see [OpenID Connect & OAuth 2.0 Token](/docs/authentication/oauth/tokens).

You can add or change any claim in the `jwt` object, except the header and the reserved claims. FusionAuth discards changes to the following reserved claims, including removals:

* `act`: <AvailableSince since="1.70.0"/> the actor claim chain, which token exchange manages
* `amr`
* `aud`
* `authenticationType`
* `cnf`
* `exp`
* `gty`
* `iat`
* `permissions`
* `sub`
* `tid`
* `tty`
* `use`

To remove a claim that isn't reserved, set the claim to `null`. FusionAuth also sets the `scope` claim to the requested scopes. The `scope` claim isn't reserved, but resource servers rely on `scope`, so don't overwrite the claim.

<Aside type="danger">
The `recipientEntity` object includes the **`clientSecret`** of the Entity. Don't copy the whole `recipientEntity` object, or the **`clientSecret`**, into a claim.
</Aside>

## Assigning the Lambda

After you create the lambda, assign the lambda in the Admin UI. Navigate to <Breadcrumb>Tenants -> Your Tenant -> OAuth</Breadcrumb> and update the **Client credentials populate lambda** setting.
