A Token Exchange Policy lambda decides whether FusionAuth allows a [token exchange](/docs/authorization/token-exchange) request, and which audiences, scopes, and lifetime the issued token receives. FusionAuth runs this lambda for every exchange in a Tenant that uses the Lambda policy engine. The lambda runs after FusionAuth authenticates the exchanger and validates the subject token. When a requested audience matches the client Id of an Entity in another Tenant, FusionAuth denies the exchange with an `invalid_target` error before the lambda runs.

## Lambda Structure

The lambda must contain a function named `policy` with the following signature:

```javascript
function policy(result, exchange, context) {
  // Lambda code goes here
}
```

The function must declare all three parameters, even if it doesn't use them:

* `result`: the object the lambda populates with its decision. This object is mutable.
* `exchange`: information about the exchange request. This object is read-only.
* `context`: information about the Tenant, plus access to [secrets](/docs/lambdas#secrets). This object is read-only.

The Admin UI fills a new lambda of this type with an example implementation.

### The `exchange` Object

  <APIField name="clientId" type="String">
    The client Id of the exchanger Entity.
  </APIField>
  <APIField name="requestedAudiencesAndResources" type="Array<String>">
    The values of the `audience` and `resource` request parameters, in that order. Empty when the request includes neither.
  </APIField>
  <APIField name="requestedScopes" type="Array<String>">
    The scopes from the `scope` request parameter. Empty when the request doesn't include `scope`.
  </APIField>
  <APIField name="subjectTokenClaims" type="Object">
    The claims of the validated subject token, such as `sub`, `iss`, `aud`, `scope`, and `act`. Claim values keep the types they have in the token. For example, `scope` is a space-delimited string.
  </APIField>
  <APIField name="subjectTokenValidationStatus" type="String">
    How FusionAuth validated the subject token. The possible values are:

    * `AUTHORITATIVE`: the subject token is an access token that this Tenant issued, verified with FusionAuth's own keys. FusionAuth uses this value when `subject_token_type` is `urn:ietf:params:oauth:token-type:access_token`.
    * `BEST_EFFORT`: the subject token is a JWT from an issuer in the Tenant's **Allowed issuers**, verified with keys from the issuer's OpenID Connect discovery document. FusionAuth uses this value when `subject_token_type` is `urn:ietf:params:oauth:token-type:jwt`.
  </APIField>
</APIBlock>

### The `result` Object

The lambda sets **`result.decision`** to `ALLOW` or `DENY`, then populates **`result.granted`** or **`result.denial`**.

To allow an exchange, set all three fields of **`result.granted`**:

<APIBlock>
  <APIField name="granted.aud" type="String or Array<String>" required>
    The audiences of the issued token.
  </APIField>
  <APIField name="granted.scope" type="String or Array<String>" required>
    The scopes of the issued token, as a space-delimited string or an array. To grant no scopes, use an empty array.
  </APIField>
  <APIField name="granted.expires_in" type="Integer" required>
    The lifetime of the issued token, in seconds.
  </APIField>
</APIBlock>

```javascript title="Allow an exchange"
result.decision = 'ALLOW';
result.granted = {
  aud: ['email-service'],
  scope: ['email:send'],
  expires_in: 300
};
```

To deny an exchange, set both fields of **`result.denial`**:

<APIBlock>
  <APIField name="denial.error_code" type="String" required>
    The OAuth error code to return to the client. The possible values are `invalid_request`, `invalid_target`, and `unauthorized_client`.
  </APIField>
  <APIField name="denial.error_description" type="String" required>
    A description of the denial to return to the client.
  </APIField>
</APIBlock>

```javascript title="Deny an exchange"
result.decision = 'DENY';
result.denial = {
  error_code: 'unauthorized_client',
  error_description: 'This client may not exchange tokens for the requested audience.'
};
```

FusionAuth responds to a denied exchange with a `403` status code. The response contains the **`error_code`** value in **`error`**, the **`error_description`** value, and an **`error_reason`** of `lambda_denied`.

### Limits on the Grant

FusionAuth applies the following rules to an `ALLOW` decision before it builds the token:

* FusionAuth drops any value in **`granted.aud`** that isn't in **`exchange.requestedAudiencesAndResources`**. If no values remain, FusionAuth denies the exchange with an `invalid_target` error.
* When the subject token has a `scope` claim, FusionAuth drops any value in **`granted.scope`** that the subject token's `scope` claim doesn't contain. If the lambda granted scopes and FusionAuth drops all of them, FusionAuth denies the exchange with an `invalid_scope` error.
* When the subject token's `scope` claim is present but empty, FusionAuth drops every value in **`granted.scope`** and issues the token without scopes.
* When the subject token has no `scope` claim, FusionAuth keeps every value in **`granted.scope`**.
* FusionAuth sets the token lifetime to **`granted.expires_in`** or the default lifetime, whichever is shorter. The default lifetime is the exchanger's Entity Type JWT duration when the Entity Type has JWT configuration enabled, and the Tenant's JWT duration otherwise.

Because FusionAuth drops every audience outside the request, FusionAuth can't allow a request that includes neither `audience` nor `resource`.

When FusionAuth drops audiences or scopes, FusionAuth writes an Information entry to the [Event Log](/docs/deploy/troubleshoot/troubleshooting#event-log) that lists the dropped values.

### Errors

FusionAuth treats the following as a lambda error and rejects the exchange:

* The lambda throws an exception.
* **`result.decision`** is neither `ALLOW` nor `DENY`.
* An `ALLOW` decision is missing **`granted`** or any of its fields.
* A `DENY` decision is missing **`denial`** or either of its fields, or uses an unsupported **`error_code`**.

FusionAuth responds to a lambda error with a `400` status code and an `invalid_request` error, and records the attempt in the token exchange audit log with the `POLICY_LAMBDA_ERROR` outcome. The response doesn't include exception details. FusionAuth writes the exception to the [Event Log](/docs/deploy/troubleshoot/troubleshooting#event-log) as an Error entry.

## Assigning the Lambda

To assign the lambda in the Admin UI:

1. Navigate to <Breadcrumb>Tenants</Breadcrumb> and click <IconButton icon="edit" /> on the Tenant.
1. Select the <Breadcrumb>OAuth</Breadcrumb> tab.
1. In the <Breadcrumb>Token exchange settings</Breadcrumb> section, set **Token exchange policy engine** to `Lambda`.
1. Select the lambda in **Token exchange policy lambda**.
1. Click <IconButton icon="save" />.

To assign the lambda with the [Tenant API](/docs/apis/tenants), set **`tenant.tokenExchangeConfiguration.policyEngine`** to `LAMBDA` and **`tenant.tokenExchangeConfiguration.policyEngineLambdaId`** to the lambda's Id.

## Debugging

To troubleshoot a policy lambda:

* Enable debugging on the lambda to write `console.debug()` output to the [Event Log](/docs/deploy/troubleshoot/troubleshooting#event-log). See [Console](/docs/lambdas#console).
* Enable **Enable debug logging** in the Tenant's token exchange settings to write the reason for each failed exchange to the Event Log.
* Review the outcome and policy decision for each attempt in the Admin UI under <Breadcrumb>System -> Token Exchange Log</Breadcrumb>, or with the [Search the Token Exchange Audit Log](/docs/apis/system/search-the-token-exchange-audit-log) API.
