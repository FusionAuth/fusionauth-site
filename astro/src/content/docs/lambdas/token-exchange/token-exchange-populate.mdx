A Token Exchange Populate lambda modifies the claims of an access token issued through [token exchange](/docs/authorization/token-exchange). FusionAuth runs this lambda after the policy engine allows an exchange and before FusionAuth signs the token. The lambda is optional.

## Lambda Structure

The lambda must contain a function named `populate` with the following signature:

```javascript
function populate(jwt, exchange, context) {
  // Lambda code goes here
}
```

The function accepts the following parameters:

* `jwt`: the claims of the token FusionAuth is about to sign. This object is mutable.
* `exchange`: information about the exchange. This object is read-only.
* `context`: access to [secrets](/docs/lambdas#secrets). This object is read-only.

### The `jwt` Object

Before the lambda runs, the `jwt` object contains the claims FusionAuth built from the policy decision and the subject token, including `sub`, `aud`, `scope`, `act`, `client_id`, `gty`, `exp`, and `tid`. The lambda can add and change claims, and remove a claim by setting the claim to `null`. The following restrictions apply.

FusionAuth discards any changes to the following reserved claims:

* `act`
* `amr`
* `applicationId`
* `auth_time`
* `authenticationType`
* `client_id`
* `cnf`
* `gty`
* `iat`
* `iss`
* `jti`
* `may_act`
* `sid`
* `sub`
* `tid`
* `tty`

FusionAuth also removes any `fa_uid` claim the lambda adds.

The lambda can only narrow the following claims:

* `aud`: FusionAuth keeps only the values that the policy engine granted. If no granted values remain, or the lambda removes the claim, FusionAuth restores the granted audiences. When the policy engine granted no audiences, FusionAuth removes `aud`.
* `scope`: FusionAuth keeps only the scopes that the policy engine granted. If no granted scopes remain, or the lambda removes the claim, FusionAuth restores the granted scopes. When the policy engine granted no scopes, FusionAuth removes `scope`.
* `exp`: FusionAuth caps `exp` at the original expiration, so the lambda can shorten the token lifetime but not extend the lifetime. Setting `exp` to `null` keeps the original value.

FusionAuth copies the `amr`, `applicationId`, `auth_time`, `authenticationType`, and `sid` claims from the subject token when they are present. FusionAuth doesn't copy any other claims from the subject token. To carry over another claim, copy the claim from **`exchange.subjectToken`**.

To avoid conflicts with registered claims and claims FusionAuth adds in the future, give custom claims a namespaced name, such as `https://example.com/department`.

### Errors

If the lambda throws an exception, FusionAuth rejects the exchange with a `422` status code and a `server_error` error, and records the attempt in the audit log with the `POPULATE_LAMBDA_ERROR` outcome. To keep an exchange from failing because of an optional step, such as a call to an external service, catch exceptions in the lambda.

## Assigning the Lambda

To assign the lambda in the Admin UI:

1. Navigate to <Breadcrumb>Tenants</Breadcrumb> and click <IconButton icon="edit" /> on the Tenant.
1. Select the <Breadcrumb>OAuth</Breadcrumb> tab.
1. In the <Breadcrumb>Token exchange settings</Breadcrumb> section, turn on **Enable token exchange grant**.
1. Select the lambda in **Token exchange populate lambda**.
1. Click <IconButton icon="save" />.

To assign the lambda with the [Tenant API](/docs/apis/tenants), set **`tenant.tokenExchangeConfiguration.populateLambdaId`** to the lambda's Id.
