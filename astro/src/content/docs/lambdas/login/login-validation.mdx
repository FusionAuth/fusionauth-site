During a login request, FusionAuth runs validations such as checking credentials, or checking a one-time code during a multi-factor login. With this lambda, you can add your own validation to a login request.

The login validation lambda has access to the user record, to the user's registration for the application when one exists, and to metadata about the request. You can use Lambda HTTP Connect in this lambda to validate against external resources. Any latency you add slows the login for your users.

When you create a lambda in the Admin UI, FusionAuth provides an empty function for you to implement.

## Lambda Structure

When you create the lambda with the API, make sure the function has the following signature:

```javascript
function validate(result, user, registration, context) {
  // Lambda code goes here
}
```

This lambda must contain a function named `validate` that accepts the following parameters:

* `result`: an object used for returning validation errors. You can modify this object.
* `user`: the FusionAuth User object. This object is read-only.
* `registration`: the FusionAuth UserRegistration object. This object is read-only.
* `context`: an object containing context for the current request. This object is read-only.

The `result` object contains an [Errors](/docs/apis/errors) object. For more information about the `user` and `registration` objects, see the [User API](/docs/apis/users) and [Registration API](/docs/apis/registrations).

To deny a login attempt, add one or more field or general errors to the result. For the error schema, see the [API Errors](/docs/apis/errors) documentation.

## Assigning The Lambda

After you create the lambda, assign the lambda to a Tenant. In the Admin UI, find the **Login validation lambda** field on the <Breadcrumb>Security</Breadcrumb> tab of the Tenant configuration.

With the Tenant API, set **`tenant.lambdaConfiguration.loginValidationId`** to the lambda Id.

### Require Single Sign-On for Employees

The following lambda makes users with a `piedpiper.com` email address log in through the company Identity Provider. The lambda rejects password, passwordless, and one-time password logins for those users, and logins through any other Identity Provider.

FusionAuth runs the lambda again when the user completes an MFA challenge. During that second run, **`authenticationType`** keeps the value from the first step, but **`identityProvider`** is absent. The lambda accepts that case, so an employee who logs in through the company Identity Provider can finish MFA.

## Localization

When you call a Login API directly and the lambda adds errors to `result`, the API responds with a `400` status code. The JSON response contains the errors object the lambda returned.

The FusionAuth hosted login pages can localize the message. FusionAuth chooses the message in the following order:

1. When your theme defines the message key from the **`code`** field, FusionAuth displays the localized message from the theme.
1. Otherwise, FusionAuth displays the **`message`** the lambda set.
1. When the lambda set no **`message`**, FusionAuth displays the message key from the **`code`** field.

With the past due example, the user sees the message `Account is past due, please contact accounts payable.` by default.

To localize the message, or to make the message friendlier, add the following message to your theme:

```
[LoginRestricted]=Looks like you forgot to pay your bill. Please call 1-800-555-5555 for assistance.
```

With this change, the user sees `Looks like you forgot to pay your bill. Please call 1-800-555-5555 for assistance.`.
