## Lambda Structure

When you create the lambda with the API, give the function the following signature:

```javascript
function reconcile(user, registration, idToken, context) {
  // Lambda code goes here
}
```

This lambda must contain a function named `reconcile` that accepts the following parameters:

<ReconcileLambdaUserRegistrationParameters />
* `idToken`: the JSON payload of the validated and decoded Id Token returned from Apple. This object is read-only.
* `context`: <AvailableSince since="1.64.0"/> an object containing the context of the request, including access to [secrets](/docs/lambdas#secrets). This object is read-only.

The [User API](/docs/apis/users) and [Registration API](/docs/apis/registrations) documentation describe the `user` and `registration` objects. The `idToken` object holds the payload from Apple. The payload can include registered OpenID Connect claims and custom Apple claims.

## Assigning The Lambda

After you create the lambda, assign the lambda to the Apple identity provider.

Navigate to <Breadcrumb>Settings -> Identity Providers</Breadcrumb>. Select your existing Apple configuration. If you haven't configured Apple yet, click <Breadcrumb>Add provider</Breadcrumb> and select Apple.

## Default Lambda

FusionAuth includes a default Apple reconcile lambda. You can use the default lambda as is or change the lambda:

```javascript
// This is the default Apple reconcile, modify this to your liking.
function reconcile(user, registration, idToken) {
  // Un-comment this line to see the idToken object printed to the event log
  // console.info(JSON.stringify(idToken, null, 2));

  // During the first login attempt, the user object will be available which may contain first and last name.
  if (idToken.user && idToken.user.name) {
    user.firstName = idToken.user.name.firstName || user.firstName;
    user.lastName = idToken.user.name.lastName || user.lastName;
  }
}
```

## Example Lambda

Apple sends the user's name only during the first login, in the **`user`** claim. The following lambda saves the name and builds **`fullName`** from the name. On later logins, the lambda keeps the saved name.

When a user chooses Hide My Email, Apple sends a private relay address and sets the **`is_private_email`** claim. The lambda stores the flag in **`user.data.applePrivateEmail`**, so your application can ask for a direct address later. Apple sends **`is_private_email`** as a string or a boolean, and the lambda handles both.
