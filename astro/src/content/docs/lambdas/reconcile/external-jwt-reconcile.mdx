## Lambda Structure

When you create the lambda with the API, give the function the following signature:

```javascript
function reconcile(user, registration, jwt, context)  {
  // Lambda code goes here
}
```

This lambda must contain a function named `reconcile` that accepts the following parameters:

<ReconcileLambdaUserRegistrationParameters />
* `jwt`: the JSON payload returned by the external identity provider JWT. This object is read-only.
* `context`: <AvailableSince since="1.64.0"/> an object containing the context of the request, including access to [secrets](/docs/lambdas#secrets). This object is read-only.

The [User API](/docs/apis/users) and [Registration API](/docs/apis/registrations) documentation describe the `user` and `registration` objects. The `jwt` object can include user claims for the lambda to read.

## Assigning The Lambda

After you create the lambda, assign the lambda to the External JWT identity provider.

Navigate to <Breadcrumb>Settings -> Identity Providers</Breadcrumb>. Select your existing External JWT configuration. If you haven't configured External JWT yet, click <Breadcrumb>Add provider</Breadcrumb> and select External JWT.

## Example Lambda

The following lambda copies the name and picture claims to the user, and keeps the saved value when a claim is missing. The lambda stores the **`iss`** claim in **`registration.data.issuer`**.

The lambda also sets the registration roles from the **`roles`** claim, but accepts only the roles in the `allowedRoles` list. Without the list, the other system could grant any role in your application, including an administrator role. When the JWT has no **`roles`** claim, the lambda leaves the roles unchanged.
