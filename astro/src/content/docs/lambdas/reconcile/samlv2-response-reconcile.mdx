## Lambda Structure

When you create the lambda with the API, give the function the following signature:

```javascript
function reconcile(user, registration, samlResponse, context) {
  // Lambda code goes here
}
```

This lambda must contain a function named `reconcile` that accepts the following parameters:

<ReconcileLambdaUserRegistrationParameters />
* `samlResponse`: the SAML v2 response object. This object is read-only.
* `context`: <AvailableSince since="1.64.0"/> an object containing the context of the request, including access to [secrets](/docs/lambdas#secrets). This object is read-only.

The [User API](/docs/apis/users) and [Registration API](/docs/apis/registrations) documentation describe the `user` and `registration` objects. The SAML response object follows the structure of the XML document, without the DOM object model. The SAML response has the following fields:

## Assigning The Lambda

After you create the lambda, assign the lambda to one or more SAML v2 identity providers.

Navigate to <Breadcrumb>Settings -> Identity Providers</Breadcrumb>. Select your existing SAML v2 configuration. If you haven't configured SAML v2 yet, click <Breadcrumb>Add provider</Breadcrumb> and select SAML v2.

## Example Lambda

The **`samlResponse.assertion.attributes`** map holds a list of values for every attribute, even when the attribute has one value. The following lambda reads the first value of the name and department attributes. The attribute names in the example are the claim URIs that Azure AD sends. When an attribute is missing, the lambda keeps the saved value.

The lambda also sets the registration roles from the **`groups`** attribute. The `groupRoles` map lists the IdP groups that grant a role, and the lambda drops groups with no mapping. When the response has no **`groups`** attribute, the lambda leaves the roles unchanged.
