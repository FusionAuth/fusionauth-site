A SCIM User Response Converter lambda converts a FusionAuth user into the SCIM User response, and optionally the SCIM EnterpriseUser extension, that FusionAuth returns to the SCIM client. FusionAuth runs the lambda after FusionAuth acts on the user.

When you create a lambda in the Admin UI, FusionAuth provides an empty function for you to implement.

## Lambda Structure

If you create the lambda with the API, the function must have the following signature:

```javascript
function convert(scimUser, user, context) {
  // Lambda code goes here
}
```

The lambda must contain a function named `convert` that accepts the following parameters:

* `scimUser`: the SCIM response. You can modify this object.
* `user`: the FusionAuth user. This object is read-only.
* `context`: <AvailableSince since="1.64.0"/> the context of the request, including access to [secrets](/docs/lambdas#secrets). This object is read-only.

The [User API](/docs/apis/users) documents the FusionAuth user. The `scimUser` object holds the SCIM User response JSON, plus the SCIM EnterpriseUser extension. See [SCIM User](https://datatracker.ietf.org/doc/html/rfc7643#section-4.1) and [SCIM EnterpriseUser extension](https://datatracker.ietf.org/doc/html/rfc7643#section-4.3).

Before the lambda runs, FusionAuth fills in the following `scimUser` fields:

* **`id`**: the FusionAuth user Id.
* **`externalId`**
* **`active`**
* **`schemas`**: the core User schema. For requests to the EnterpriseUsers endpoint, FusionAuth adds the enterprise extension schema.
* **`meta`**: **`created`**, **`lastModified`**, **`resourceType`**, and **`location`**, the URI of the user resource.

The lambda can add to or change any field in `scimUser`.

## Assign the Lambda

After you create the lambda, assign the lambda to a tenant on the <Breadcrumb>SCIM</Breadcrumb> tab of the tenant configuration.

## Default Lambda

FusionAuth provides a default SCIM User Response Converter lambda. The default lambda copies the FusionAuth user to the core SCIM User attributes. The lambda returns each extension stored under **`user.data.extensions`** and adds the extension schema to **`schemas`**. The default SCIM User Request Converter lambda stores extensions in the same place.

The default lambda always returns one email and one phone number. When the user has no mobile phone, the phone number entry has no **`value`**.

## Example: Return Enterprise Attributes From User Data

The following lambda reverses the [enterprise attributes example](/docs/lambdas/scim/scim-user-request-converter#example-store-enterprise-attributes-in-user-data) for the SCIM User Request Converter. The lambda makes these changes to the default lambda:

* The lambda builds the enterprise extension from the **`user.data`** fields that the request converter wrote. When the user has none of those fields, the lambda leaves out the extension.
* The lambda builds the manager **`$ref`** from **`scimUser.meta.location`**, by swapping the user Id at the end of the URI for the manager Id.
* The lambda adds the enterprise schema to **`schemas`** when the SCIM client called the core Users endpoint.
* The lambda returns **`emails`** and **`phoneNumbers`** only when the user has an email or mobile phone.
