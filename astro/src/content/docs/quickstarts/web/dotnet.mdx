This QuickStart explains how to add a login page and authentication to a website built with [ASP.NET Core Razor Pages](https://learn.microsoft.com/en-us/aspnet/core/razor-pages/). You'll begin with a simple Razor Pages app that allows visitors to edit a file. Then, you'll add authentication to the app with a FusionAuth instance. Finally, you'll extend the app to handle multiple independent users with user data provided by FusionAuth.

This tutorial should take between 5 and 15 minutes; less if you already have prerequisites like Docker installed.

## Prerequisites

This QuickStart requires:

* [.NET SDK](https://dotnet.microsoft.com/en-us/download/dotnet/10.0) 10 or later
* [Docker](https://docs.docker.com/get-started/get-docker/) 23 or later

If you use macOS or Windows, you need one of the following container management tools:
  * [Docker Desktop](https://www.docker.com/products/docker-desktop/)
  * [OrbStack](https://docs.orbstack.dev/quick-start) (to use OrbStack for `docker compose` commands after installation, run `docker context use orbstack`)
  * [Podman](https://podman.io/docs/installation) (in the commands below, replace `docker` with `podman`)

## Install and Run FusionAuth

Before we can add authentication to our .NET app, we need a local FusionAuth instance:

<Steps>
1. Open your container management tool (listed in the prerequisites above).

1. From the `dotnet-quickstart` folder, clone the [GitHub repository for the FusionAuth instance you'll use with this QuickStart](https://github.com/FusionAuth/fusionauth-quickstart-app):

   ```shell-session
   git clone https://github.com/FusionAuth/fusionauth-quickstart-app.git
   ```

1. Navigate into the cloned directory:

   ```shell-session
   cd fusionauth-quickstart-app
   ```

1. To start a local instance of FusionAuth, run the following command (omit the `-d` flag to see all Docker logs):

   ```shell-session
   docker compose up -d
   ```

1. Wait until all networks, volumes, and containers show a green status of **Healthy**, **Started**, or **Created**. This may take a few minutes, depending on your network speed and cached dependencies.

1. Open [http://localhost:9011/admin](http://localhost:9011/admin) to access the FusionAuth Admin UI.

1. Log in with these credentials:

   * username: `admin@example.com`
   * password: `password`

1. Navigate to <Breadcrumb>Applications -> QuickStart App -> Edit -> OAuth</Breadcrumb>. On this page, you can find your client Id and client secret, and set redirect and logout URLs. In the next part of this QuickStart, we'll use these values to connect our .NET app with FusionAuth.

1. Click the logout icon in the top right to log out of the Admin UI. We'll use a different user account to access our .NET app, and because FusionAuth supports SSO, we need to log out of our admin account before we can log in as a normal user.
</Steps>

## Summary

In this QuickStart, FusionAuth handled login for your .NET app:

* The ASP.NET Core OpenID Connect handler sent users to the FusionAuth login page and exchanged the authorization code for tokens, so the app never saw their passwords.
* The `[Authorize]` attribute kept logged-out users away from the notes page.
* The ID token gave the app each user's unique Id and name. The app used the Id to keep each note separate and the name to greet the user.
* FusionAuth's self-service registration let new users create their own accounts, with no sign-up code in the app.
