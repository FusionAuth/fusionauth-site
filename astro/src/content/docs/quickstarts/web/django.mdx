This QuickStart explains how to add a login page and authentication to a website built with [Django](https://www.djangoproject.com/). You'll begin with a simple Django app that allows visitors to edit a file. Then, you'll add authentication to the app with a FusionAuth instance. Finally, you'll extend the app to handle multiple independent users with user data provided by FusionAuth.

This tutorial should take between 5 and 15 minutes; less if you already have prerequisites like Docker installed.

## Prerequisites

This QuickStart requires:

* [Python](https://www.python.org/downloads/) 3.12 or later
* [Docker](https://docs.docker.com/get-started/get-docker/) 23 or later

If you use macOS or Windows, you need one of the following container management tools:
  * [Docker Desktop](https://www.docker.com/products/docker-desktop/)
  * [OrbStack](https://docs.orbstack.dev/quick-start) (to use OrbStack for `docker compose` commands after installation, run `docker context use orbstack`)
  * [Podman](https://podman.io/docs/installation) (in the commands below, replace `docker` with `podman`)

## Install and Run FusionAuth

Before we can add authentication to our Django app, we need a local FusionAuth instance:

<Steps>
1. Open your container management tool (listed in the prerequisites above).

1. From the `django-quickstart` folder, clone the [GitHub repository for the FusionAuth instance you'll use with this QuickStart](https://github.com/FusionAuth/fusionauth-quickstart-app):

   ```shell-session
   git clone https://github.com/FusionAuth/fusionauth-quickstart-app.git
   ```

1. Navigate into the cloned directory:

   ```shell-session
   cd fusionauth-quickstart-app
   ```

1. To start a local instance of FusionAuth, run the following command (omit the `-d` flag to see all Docker logs):

   ```shell-session
   docker compose up -d
   ```

1. Wait until all networks, volumes, and containers show a green status of **Healthy**, **Started**, or **Created**. This may take a few minutes, depending on your network speed and cached dependencies.

1. Open [http://localhost:9011/admin](http://localhost:9011/admin) to access the FusionAuth Admin UI.

1. Log in with these credentials:

   * username: `admin@example.com`
   * password: `password`

1. Navigate to <Breadcrumb>Applications -> QuickStart App -> Edit -> OAuth</Breadcrumb>. On this page, you can find your client ID, your client secret, and specify redirect and logout URLs. In the next part of this QuickStart, we'll use these values to connect our Django app with FusionAuth.

1. Click the logout icon in the top right to log out of the Admin UI. We'll use a different user account to access our Django app, and because FusionAuth supports SSO, we need to log out of our admin account before we can log in as a normal user.
</Steps>

   The new code connects the app to FusionAuth:

   * `load_dotenv()` reads the configuration from the `.env` file.
   * `oauth.register` tells Authlib how to talk to FusionAuth. It uses the client Id, client secret, and [[PKCE]], and finds the login and token endpoints in the OpenID Connect discovery document at `/.well-known/openid-configuration`. With PKCE, Authlib sends a code verifier when it exchanges the authorization code for tokens, so a stolen authorization code is useless on its own.
   * The `login_required` decorator sends users who aren't logged in to `/login`. It's defined in this file, not Django's built-in `login_required`, which works with Django's own user accounts.
   * The `/login` route calls `authorize_redirect`, which sends the user to the FusionAuth login page.
   * The `/oauth-callback` route calls `authorize_access_token`, which exchanges the authorization code from FusionAuth for tokens and validates the [[Id Token::ID token]]. The app then stores the user's Id in the Django session.
   * The `/logout` route clears the Django session, then sends the user to FusionAuth's `/oauth2/logout` endpoint so the FusionAuth session ends too.

## Add Independent Notes for Each User

To see a more realistic example of FusionAuth usage, we can improve the app even more, so every user gets a unique note to edit. To accomplish this, we'll use FusionAuth's user data:

<Steps>
1. Open the FusionAuth Admin UI at [http://localhost:9011/admin](http://localhost:9011/admin).

1. Log in with the following credentials:

   * username: `admin@example.com`
   * password: `password`

1. Navigate to <Breadcrumb>Applications -> QuickStart App -> Edit -> Registration</Breadcrumb>.

   * Under **Self-service registration**, check that **Registration mode** is set to **Create registration**. The QuickStart configuration has already turned on self-service registration.
   * In the **Registration field** list, turn on the **Enabled** and **Required** switches for the following rows:
     * **Birthdate**
     * **First name**
     * **Last name**

1. Click the **Save** button in the top right of the page to save your changes to self-service registration.

1. Navigate to <Breadcrumb>Users -> Richard Hendricks -> Manage</Breadcrumb>.

1. In the **Source** tab, look for the `firstName` and `lastName` fields. That's what we'll use to personalize the UI for each user. We'll use the user's `id` field to generate a unique name for each user's note.

1. Click the logout icon in the top right to log out of the Admin UI. We'll use a different user account to access our Django app.

1. Replace the contents of `notes/views.py` with the following code, which requests the `profile` and `email` scopes, reads the user's name (first and last) and Id from the ID token, and stores each user's note in a separate file:

   <ExtractedCode src="quickstart-django/2-multi-user/notes/views.py" lang="python"/>

   Authlib validates the ID token and decodes its claims into `token['userinfo']`, so we don't need a separate JWT library. The logout route also passes a `post_logout_redirect_uri`, which sends the user back to the login page after FusionAuth ends their session.

1. Open the app at [http://localhost:3000](http://localhost:3000). The Django development server reloads the changed file, so you don't need to restart it.

Your Django app now provides unique notes for each user. Each user can independently edit and save their note. To see all of the notes, look for `note-<id>.txt` files in the `user_data` directory. To identify which note corresponds to which user, compare the `id` in the file name with the `id` field in the user's **Source** tab.

## Summary

In this QuickStart, FusionAuth handled login for your Django app:

* Authlib sent users to the FusionAuth login page and exchanged the authorization code for tokens, so the app never saw their passwords.
* The `login_required` decorator kept logged-out users away from the notes page.
* The ID token gave the app each user's unique Id and name. The app used the Id to keep each note separate and the name to greet the user.
* FusionAuth's self-service registration let new users create their own accounts, with no sign-up code in the app.
