In this QuickStart, you learn how to use FusionAuth for authentication and authorization of an Express.js resource server. FusionAuth will prevent unauthorized clients from calling your API functions.

<Aside type="note">
This API QuickStart shows authorization for business clients, without a graphical user interface. You might instead be looking for the [Express.js web QuickStart](/docs/quickstarts/web/express), which explains how to use FusionAuth on your website for login and authorization for end users.
</Aside>

This QuickStart creates an Express.js server to manage a discussion forum. The API server has a `write` endpoint allowing a premium client to post messages or edit their own messages, and a `read` endpoint allowing both premium and free (but registered) clients to read all forum messages. Only clients with the `premium` role in FusionAuth can use the `write` endpoint, and if a client writes to an existing message (an edit) then the client user Id must match the message user Id. Clients with either `premium` or `free` roles can use the `read` endpoint.

## Prerequisites

This QuickStart requires:

* [Node.js](https://nodejs.org/en/download) 22 or later
* [Docker](https://docs.docker.com/get-started/get-docker) 23 or later
* [curl](https://curl.se/download.html), command line tool and library for making HTTP requests.

If you use macOS or Windows, you need one of the following container management tools:
  * [Docker Desktop](https://www.docker.com/products/docker-desktop/)
  * [OrbStack](https://docs.orbstack.dev/quick-start) (to use OrbStack for `docker compose` commands after installation, run `docker context use orbstack`)
  * [Podman](https://podman.io/docs/installation) (in the commands below, replace `docker` with `podman`)

## Install and Run FusionAuth

To begin, clone the [GitHub repository for this QuickStart](https://github.com/FusionAuth/fusionauth-quickstart-javascript-express-api) to your local machine:

```shell-session
git clone https://github.com/FusionAuth/fusionauth-quickstart-javascript-express-api
```

The repository contains two directories:

* `fusionauth`, a preconfigured version of FusionAuth
* `complete-application`, a finished runnable version of the API you will build in this guide

To start a local instance of FusionAuth, run the following command:

```shell-session
cd fusionauth-quickstart-javascript-express-api/fusionauth
docker compose up
```

<Aside type="note">
During Docker Compose startup, the included `fusionauth/kickstart.json` file uses the FusionAuth API to:

* Generate an API key
* Create an application for your API with appropriate settings (<Breadcrumb>Applications -> Edit Application</Breadcrumb>)
* Create an admin user (`admin@example.com`) and register the user with the FusionAuth application (<Breadcrumb>Users</Breadcrumb>)
* Create three API users (`free@example.com`, `premium@example.com`, and `premium2@example.com`) with the `free` or `premium` role, and register the users with your application
</Aside>

Once Docker Compose initializes all containers, open a browser and navigate to the FusionAuth Admin UI at [http://localhost:9011/admin](http://localhost:9011/admin). Use the following admin account credentials to log in:

* Username: `admin@example.com`
* Password: `password`

After authenticating, you should see the FusionAuth Admin UI, which shows information about active users, logins, registrations, and more:

## Use the API

There are [several ways to acquire a token](/docs/authentication/oauth/) in FusionAuth, but for this example, you will use the [Login API](/docs/apis/login).

<Steps>

1. Get an access token for `free@example.com` by making the following request in a new terminal.
    ```shell-session
    curl --location 'http://localhost:9011/api/login' \
    --header 'Authorization: this_really_should_be_a_long_random_alphanumeric_value_but_this_still_works' \
    --header 'Content-Type: application/json' \
    --data-raw '{
      "loginId": "free@example.com",
      "password": "password",
      "applicationId": "e9fdb985-9173-4e01-9d73-ac2d60d1dc8e"
    }'
    ```
    Here you are submitting your Id and password and getting a temporary access token in return. The API clients will never need to submit their real password anywhere except FusionAuth.

1. Copy the `token` value from the response above, which should look like a longer version of `"token": "eyJhbGciOiJSUz"`. Call the `/read` endpoint, replacing the placeholder `eyJhbGciOiJSUz` token with your token value that you just copied:
    ```shell-session
    curl localhost:3000/read --header 'Authorization: Bearer eyJhbGciOiJSUz'
    ```
    The API returns the only stored message `[ {"uuid":"00000000-0000-0000-0000-000000000001","userId":"00000000-0000-0000-0000-222222222222","text":"Welcome to the forum."} ]`.

1. Call the `/write` endpoint, replacing the placeholder with your token value again:
    ```shell-session
    curl -X POST http://localhost:3000/write -H 'Content-Type: application/json' -d '{"uuid":"00000000-0000-0000-0000-444444444444","text":"Hello from Freda"}' --header 'Authorization: Bearer eyJhbGciOiJSUz'
    ```
    The API returns `{"error":"You do not have a role with permissions to do this."}` because you are trying to access the endpoint while having the free role but not the premium role. The endpoint is secure.

1. Use the command from step one to get a token for the premium user, by replacing `free@example.com` with `premium@example.com`:
    ```shell-session
    curl --location 'http://localhost:9011/api/login' \
    --header 'Authorization: this_really_should_be_a_long_random_alphanumeric_value_but_this_still_works' \
    --header 'Content-Type: application/json' \
    --data-raw '{
      "loginId": "premium@example.com",
      "password": "password",
      "applicationId": "e9fdb985-9173-4e01-9d73-ac2d60d1dc8e"
    }'
    ```

1. Now use the new premium token returned to call the write endpoint again:
    ```shell-session
    curl -X POST http://localhost:3000/write -H 'Content-Type: application/json' -d '{"uuid":"00000000-0000-0000-0000-444444444444","text":"Hello from Peter"}' --header 'Authorization: Bearer eyJhbGciOiJSUz'
    ```
    This time the API should return `"Write successful"`.

1. Finally, call the read endpoint again with the free token:
    ```shell-session
    curl localhost:3000/read --header 'Authorization: Bearer eyJhbGciOiJSUz'
    ```
    The API now returns the two messages.

1. If you want to experiment more, call the `write` endpoint again with the same message Id but a different text to test message editing. You could also log in with the second premium user, `premium2@example.com` and try to edit another user's message to test user-level security.

</Steps>

## Summary

In this tutorial you learnt how to add FusionAuth to a web server in the simplest way possible.

At login, clients submit their username and password directly to FusionAuth, so your server doesn't need to handle low-level protocols.

Thereafter, by using the `jose` library to handle tokens, your `security.mjs` file needs only two functions to guarantee security:
- `verifyJWT` to check the user is authenticated by FusionAuth and
- `hasRole` to check if the user is authorized for the endpoint they are calling.

In your main `api.mjs` endpoints, you can use the `hasRole` middleware to check if a user is authenticated and authorized, and if you need to work with a unique unchanging user Id in your database, use `jose.decodeJwt(req.verifiedToken).sub` to get the user UUID provided by FusionAuth.
