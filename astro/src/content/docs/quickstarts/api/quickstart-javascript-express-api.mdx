In this QuickStart, you learn how to use FusionAuth for authentication and authorization of an Express.js resource server. FusionAuth will prevent unauthorized clients (users) calling your API functions.

<Aside type="note">
This API QuickStart shows authorization for business clients, without a graphical user interface. You might instead be looking for the [Express.js web QuickStart](/docs/quickstarts/web/express), which explains how to use FusionAuth on your website for login and authorization for end users.
</Aside>

This QuickStart creates an Express.js server with a `write` endpoint to store data on the server, and a `read` endpoint to see the data. Only clients with the `writer` role in FusionAuth can use the first endpoint and only clients with `reader` can use the second endpoint.

## Prerequisites

This QuickStart requires:

* [Node.js](https://nodejs.org/en/download) 22 or later
* [Docker](https://docs.docker.com/get-started/get-docker) 23 or later
* [curl](https://curl.se/download.html), command line tool and library for making HTTP requests.

<Aside type="tip">
If you use macOS or Windows, you need one of the following container management tools:
  * [Docker Desktop](https://www.docker.com/products/docker-desktop/)
  * [OrbStack](https://docs.orbstack.dev/quick-start) (to use OrbStack for `docker compose` commands after installation, run `docker context use orbstack`)
  * [Podman](https://podman.io/docs/installation) (in the commands below, replace `docker` with `podman`)

Be sure to open your container management tool to configure and install any dependencies needed by that tool, including Rosetta and Developer Tools on macOS.

If you use Windows, replace `/` with `\` in all file paths.
</Aside>

## Install and Run FusionAuth

To begin, clone the [GitHub repository for this QuickStart](https://github.com/FusionAuth/fusionauth-quickstart-javascript-express-api) to your local machine:

```shell-session
git clone https://github.com/FusionAuth/fusionauth-quickstart-javascript-express-api
```

The repository contains:

* `fusionauth`, a preconfigured version of FusionAuth
* `complete-application`, a finished runnable version of the API you will build in this guide

To start a local instance of FusionAuth, run the following command:

```shell-session
cd fusionauth-quickstart-javascript-express-api/fusionauth
docker compose up
```

<Aside type="note">
During Docker Compose startup, the included `fusionauth/kickstart.json` file uses the FusionAuth API to:

* Generate an API key
* Create an application for your API with appropriate settings (<Breadcrumb>Applications -> Edit Application</Breadcrumb>)
* Create an admin user (`admin@example.com`) and register the user with the FusionAuth application (<Breadcrumb>Users</Breadcrumb>)
* Create two API users (`reader@example.com` and `writer@example.com`) and their roles, and register the users with your application
</Aside>

Once Docker Compose initializes all containers, open a browser and navigate to the FusionAuth Admin UI at [http://localhost:9011/admin](http://localhost:9011/admin). Use the following admin account credentials to log in:

* Username: `admin@example.com`
* Password: `password`

After authenticating, you should see the FusionAuth Admin UI, which shows information about active users, logins, registrations, and more:

## Use the API

There are [several ways to acquire a token](/docs/authentication/oauth/) in FusionAuth, but for this example, you will use the [Login API](/docs/apis/login).

<Steps>

1. Get an access token for `reader@example.com` by making the following request in a new terminal.
    ```shell-session
    curl --location 'http://localhost:9011/api/login' \
    --header 'Authorization: this_really_should_be_a_long_random_alphanumeric_value_but_this_still_works' \
    --header 'Content-Type: application/json' \
    --data-raw '{
      "loginId": "reader@example.com",
      "password": "password",
      "applicationId": "e9fdb985-9173-4e01-9d73-ac2d60d1dc8e"
    }'
    ```

1. Copy the `token` from the response, which should look like the ellipsized token below:
    ```json
    {
      "token": "eyJhbGciOiJSUzI1NiIs...bbkipjKq2peSjG7qA",
      "tokenExpirationInstant": 1689353059670,
      "user": {
          ...
      }
    }
    ```

1. Paste your full token from the previous step over the placeholder token containing the `...` below to call the `/read` endpoint and see what data the API has:
    ```shell-session
    curl localhost:3000/read --header 'Authorization: Bearer eyJhbGciOiJSUzI1NiIs...bbkipjKq2peSjG7qA'
    ```
    The API returns `["1"]`.

1. Call the write endpoint, replacing the token once again:
    ```shell-session
    curl -X POST http://localhost:3000/write -H 'Content-Type: application/json' -d '{"value":"hello"}'  --header 'Authorization: Bearer eyJhbGciOiJSUzI1NiIs...bbkipjKq2peSjG7qA'
    ```
    The API returns `{"error":"You do not have a role with permissions to do this."}` because you are trying to access the endpoint while having the reader role but not the writer role. The endpoint is secure.

1. Use the command from step one to get a token for the writer user, by replacing `reader@example.com` with `writer@example.com`:
    ```shell-session
    curl --location 'http://localhost:9011/api/login' \
    --header 'Authorization: this_really_should_be_a_long_random_alphanumeric_value_but_this_still_works' \
    --header 'Content-Type: application/json' \
    --data-raw '{
      "loginId": "writer@example.com",
      "password": "password",
      "applicationId": "e9fdb985-9173-4e01-9d73-ac2d60d1dc8e"
    }'
    ```

1. Now use the new writer token returned to call the write endpoint again:
    ```shell-session
    curl -X POST http://localhost:3000/write -H 'Content-Type: application/json' -d '{"value":"hello"}'  --header 'Authorization: Bearer eyJhbGciOiJSUzI1NiIs...bbkipjKq2peSjG7qA'
    ```
    This time the API should return `"Write successful"`.

1. Finally, call the read endpoint again with the reader token:
    ```shell-session
    curl localhost:3000/read --header 'Authorization: Bearer eyJhbGciOiJSUzI1NiIs...bbkipjKq2peSjG7qA'
    ```
    The API returns the new saved value: `["1","hello"]`.

</Steps>
