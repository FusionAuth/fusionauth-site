## Create an OpenID Connect Identity Provider

The owner of the OpenID Connect provider supplies the client Id and the client secret. When you don't know the values, contact the owner.

When the provider has a well-known configuration endpoint, FusionAuth discovers the other endpoints from the **Issuer** field. For example, for an **Issuer** of `https://login.piedpiper.com`, FusionAuth requests `https://login.piedpiper.com/.well-known/openid-configuration`. When the provider has no well-known configuration endpoint, turn off **Discover endpoints**, and enter the URL of each endpoint in the three fields that appear.

### Form Fields

<APIBlock>
  <APIField name="Id" optional>

    The Tenant that this Identity Provider belongs to. The field appears only when you select a specific Tenant on the previous page. When you select `Global identity provider` on the previous page, the field doesn't appear.
  </APIField>
  <APIField name="Name" required>
    A unique name for the Identity Provider. FusionAuth uses the name for display only, and you can change the name later.
  </APIField>
  <APIField name="Client Id" required>
    The client Id that FusionAuth uses to authenticate with the provider. The owner of the Identity Provider supplies the value.
  </APIField>
  <APIField name="Client authentication" optional since="1.15.3">
    The client authentication method that FusionAuth uses with the OpenID Connect Identity Provider. For more information, see [Client Authentication in the OpenID Connect specification](https://openid.net/specs/openid-connect-core-1_0.html#ClientAuthentication).

  <APIField name="Client secret" optional>

  </APIField>
  <APIField name="Discover endpoints">

    When turned off, you enter the endpoints by hand. Turn off the field when the OpenID Connect provider doesn't implement the well-known discovery endpoint.
  </APIField>
  <APIField name="Issuer" required>
    The public URL of the Identity Provider. This field is required when **Discover endpoints** is turned on.
  </APIField>
  <APIField name="Authorization endpoint" required>
    The public URL of the OpenID Connect [[authorization endpoint]]. This field is required when **Discover endpoints** is turned off.
  </APIField>
  <APIField name="Token endpoint" required>
    The public URL of the OpenID Connect [[token endpoint]]. This field is required when **Discover endpoints** is turned off.
  </APIField>
  <APIField name="Userinfo endpoint" required>
    The public URL of the OpenID Connect userinfo endpoint. This field is required when **Discover endpoints** is turned off.
  </APIField>
  <APIField name="Button text" optional defaults="Login with OpenID Connect">
    The text of the button on the login form.
  </APIField>
  <APIField name="Button image" optional>
    The image on the button on the login form. When you leave out the image, the button shows a default OpenID Connect icon.
  </APIField>
  <APIField name="Scope" optional>
    The scope that FusionAuth requests from the user during login. Some OpenID Connect providers require a scope.
  </APIField>
  <APIField name="Linking strategy" optional since="1.28.0">
    How FusionAuth links the external user to a FusionAuth user. For more information, see [Linking Strategies](/docs/authentication/identity-providers/linking-strategies).

  </APIField>
  <APIField name="Reconcile lambda" optional>

  <APIField name="Enable debug logging" optional defaults="false">

## Redirect URLs

An OpenID Connect login uses two [[redirect URL::redirect URLs]]:

* The FusionAuth redirect URL handles the response from the OpenID Connect Identity Provider. The path is always `/oauth2/callback`. For FusionAuth at `login.piedpiper.com`, the FusionAuth redirect URL is `https://login.piedpiper.com/oauth2/callback`. Register this URL with the Identity Provider. FusionAuth processes the response, runs the [configured lambda](/docs/lambdas/reconcile/openid-connect-response-reconcile), if any, and logs the user in to FusionAuth.
* The application redirect URL receives the authorization code from FusionAuth and exchanges the code for a token. You write this route, so you control the URL. Every application that integrates with FusionAuth has this redirect, with or without an OpenID Connect Identity Provider. For more information, see [Authorization Code Grant](/docs/authentication/oauth/authorization-code).

The following diagram shows the requests in an OpenID Connect login. Pied Piper is the application, FusionAuth is the [[authorization server]], and Azure Active Directory/Microsoft Entra ID is the remote Identity Provider:

```mermaid title="Requests and redirects in an OpenID Connect login through FusionAuth."
sequenceDiagram
  participant b as Browser
  participant pp as Pied Piper
  participant f as FusionAuth
  participant aad as Azure AD/Microsoft Entra ID
  b ->> pp : Click Login Link
  pp ->> b : Redirect to FusionAuth
  b ->> f : Request Login Page
  f ->> b : Send Login Page
  b ->> f : Clicks on 'Login With Azure AD'
  f ->> b : Redirects to Azure AD
  b ->> aad : Requests Login Page
  aad ->> b : Sends Login Page
  b ->> aad : Sends Credentials
  aad ->> b : Redirects to FusionAuth Redirect URL
  b ->> f : Requests FusionAuth Redirect URL
  f ->> f : Processes request, runs lambda, logs user into FusionAuth
  f ->> b : Redirects to Pied Piper Redirect URL
  b ->> pp : Requests Pied Piper Redirect URL
  pp ->> f : Requests Token
  f ->> pp : Returns Token
  pp ->> pp : Stores token (could send it to Browser as cookie as well)
  pp ->> b : Redirects to Application pages
  b ->> pp : Makes authenticated request(s)
```

## Proof Key for Code Exchange

<AvailableSince since="1.21.0"/>

[[PKCE]] (pronounced "pixy") is an extension to the [[Authorization Code grant]]. PKCE protects the exchange of an authorization code for tokens. For the specification, see [RFC 7636](https://tools.ietf.org/html/rfc7636).

FusionAuth uses PKCE with every OpenID Connect Identity Provider. You can't turn PKCE off. During a hosted login, FusionAuth generates a code verifier and sends an `S256` code challenge to the authorization endpoint. FusionAuth then sends the code verifier to the token endpoint. A provider without PKCE support ignores the PKCE parameters.

When your app calls the authorization endpoint without the FusionAuth hosted login pages, generate the code verifier in your app. Send the code verifier in **`data.code_verifier`** to the Complete OpenID Connect Login API. For more information, see [Complete an OpenID Connect Login](/docs/apis/identity-providers/openid-connect#complete-an-openid-connect-login).

## Troubleshooting

To troubleshoot an OpenID Connect connection:

* Check the whole configuration, including stray spaces.
* Turn on **Enable debug logging**, and read the Event Log entries during a login.

### User Info as JWT

The [OpenID Connect specification](https://openid.net/specs/openid-connect-core-1_0.html#UserInfoResponse) lets a client request the `userinfo` response in the following formats:

* JSON
* Signed JWT
* Encrypted or nested JWT

FusionAuth supports only the JSON format. When the OpenID Connect endpoint returns the `userinfo` data as a JWT, the Event Log shows an error such as the following:

```plaintext
Request to the [https://example.com/userinfo] endpoint failed. Status code [200].
Exception encountered.com.inversoft.rest.JSONException : Message: Failed to parse the HTTP response as JSON. Actual HTTP response body:
eyJoa...
```

To fix the error, ask the administrators of the OpenID Connect endpoint to return the `userinfo` data as JSON for your client registration.
