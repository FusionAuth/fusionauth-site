The External JWT Identity Provider logs a user in to FusionAuth with a JWT from a third-party identity provider. Your application gets the JWT from the third party and sends the JWT to the [Reconcile API](/docs/apis/jwt/reconcile-a-jwt-using-the-external-jwt-provider). FusionAuth verifies the JWT signature and reads the user's identity from the JWT claims. FusionAuth then finds or creates the user and returns the same response as the [Login API](/docs/apis/login/authenticate).

```mermaid title="Your application exchanges a third-party JWT for a FusionAuth login."
sequenceDiagram
    participant App as Your Application
    participant IdP as Third-Party Identity Provider
    participant FusionAuth
    App ->> IdP : Authenticate the user
    IdP ->> App : Return a signed JWT
    App ->> FusionAuth : Send the JWT to the Reconcile API
    FusionAuth ->> FusionAuth : Verify the signature and read the claims
    FusionAuth ->> App : Return the user and FusionAuth tokens
```

The External JWT Identity Provider adds no login button to the FusionAuth login pages.

## Form Fields

The top of the form holds the following fields:

<APIBlock>
  <APIField name="Enable identity provider" optional>
    Whether this External JWT Identity Provider is enabled.
  </APIField>
  <APIField name="Id" optional>
    An optional UUID. When you leave out the Id, FusionAuth generates a unique Id.
  </APIField>
  <APIField name="Source" optional since="1.65.0" defaults="System">
    The source of this Identity Provider.

    FusionAuth sets the source only when you create the Identity Provider. FusionAuth ignores a new value on update and keeps the existing value.

    The maximum length is `191` characters.
  </APIField>
  <APIField name="Tenant" optional since="1.62.0">
    The Tenant that this Identity Provider belongs to. The field appears only when you select a specific Tenant on the previous page. When you select `Global identity provider` on the previous page, the field doesn't appear.
  </APIField>
  <APIField name="Name" required>
    A unique name for the Identity Provider. FusionAuth uses the name for display only, and you can change the name later.
  </APIField>
  <APIField name="Reconcile lambda" optional since="1.17.0">
    A lambda that maps custom claims from the JWT to the user. The lambda can replace the claim mappings on the <Breadcrumb>Claim mapping</Breadcrumb> tab or run in addition to the claim mappings.

    To create a lambda, navigate to <Breadcrumb>Customizations -> Lambdas</Breadcrumb>.
  </APIField>
  <APIField name="Linking strategy" optional since="1.28.0">
    How FusionAuth links the external user to a FusionAuth user. For more information, see [Linking Strategies](/docs/authentication/identity-providers/linking-strategies).

    <LinkingStrategyEditLimit />
  </APIField>
  <APIField name="Enable debug logging" optional defaults="false">
    Creates Event Log entries that help you debug integration errors. To read the entries, navigate to <Breadcrumb>System -> Event Log</Breadcrumb>.
  </APIField>
</APIBlock>

### Applications

The <Breadcrumb>Applications</Breadcrumb> tab lists each Application and CIMD domain. The `FusionAuth` Application represents the Admin UI. Each row has the following toggles:

<APIBlock>
  <APIField name="Enabled" optional defaults="false">
    Turns on this Identity Provider for the Application.
  </APIField>
  <APIField name="Create registration" optional defaults="true">
    When a user without a registration for the Application reconciles a JWT, FusionAuth registers the user for the Application with the Application's default roles. When you turn off the toggle, register each user for the Application before the user reconciles a JWT.
  </APIField>
</APIBlock>

### JWT

The <Breadcrumb>JWT</Breadcrumb> tab tells FusionAuth how to verify the JWT and where to find the user's identity in the JWT claims.

<Screenshot id="idp-external-jwt-jwt" url="/admin/identity-provider/add/ExternalJWT?identityProvider.tenantId=30663132-6464-6665-3032-326466613934&global=false#jwt" showHash height={900} alt="The JWT tab of the External JWT Identity Provider form, with the claim name fields and the verification keys." />

<APIBlock>
  <APIField name="Unique Id claim" optional defaults="sub">
    The name of the claim that contains the user's unique Id. FusionAuth links the user to this Identity Provider by this value. The Reconcile API rejects a JWT that doesn't contain the claim.
  </APIField>
  <APIField name="Email claim" optional defaults="email">
    The name of the claim that contains the user's email address. When **Linking strategy** links on email, FusionAuth finds or creates the user by this email address. When **Managed domains** has values, the email address must be in one of the domains.

    When **Unique claim** has a value, FusionAuth ignores this field.
  </APIField>
  <APIField name="Email verified claim" optional defaults="email_verified" since="1.48.0">
    The name of the claim that says whether the third party verified the user's email address. When **Linking strategy** links on email and the claim is `false`, the Reconcile API rejects the JWT.
  </APIField>
  <APIField name="Username claim" optional defaults="preferred_username">
    The name of the claim that contains the user's username. When **Linking strategy** links on username, FusionAuth finds or creates the user by this username.
  </APIField>
  <APIField name="Header key identifier" optional defaults="kid">
    The name of the JWT header that identifies the key that signed the JWT. FusionAuth uses the value to choose a key from **Verification keys**.
  </APIField>
  <APIField name="Verification keys" required since="1.69.0">
    The keys in [[Key Master]] that verify the signature of the JWT. Import the public key or certificate of each signing key that the third party uses, and add every key.
  </APIField>
  <APIField name="Unique claim" optional deprecated>
    The name of the claim that contains the user's email address. The field is empty by default. When the field has a value, FusionAuth reads the email address from this claim instead of **Email claim**, and the Reconcile API rejects a JWT that doesn't contain the claim.

    To use **Unique Id claim**, **Email claim**, and **Username claim** instead, clear this field.
  </APIField>
</APIBlock>

### Managed Domains

Managed domains limit the users that this Identity Provider can reconcile. When the field has values, the Reconcile API rejects a JWT whose email address isn't in one of the domains. FusionAuth skips the check for a JWT without an email address. The [Lookup API](/docs/apis/identity-providers/#lookup-an-identity-provider) also uses managed domains to find the Identity Provider for an email address.

<Screenshot id="idp-external-jwt-domains" url="/admin/identity-provider/add/ExternalJWT?identityProvider.tenantId=30663132-6464-6665-3032-326466613934&global=false#managed-domains" height={900} alt="The Managed domains tab of the External JWT Identity Provider form." />

<APIBlock>
  <APIField name="Managed domains" optional>
    The email domains that this Identity Provider manages, one domain on each line. For example, to reconcile JWTs for `jared@piedpiper.com`, add `piedpiper.com`. When you leave the field empty, the Identity Provider accepts any email address.

    Only one Identity Provider in a Tenant can manage a domain. For more information, see [Managed Domains](/docs/authentication/identity-providers/managed-domains).
  </APIField>
</APIBlock>

### Claim Mapping

The <Breadcrumb>Claim mapping</Breadcrumb> tab lists the claim mappings, which copy JWT claims to the user. To add a mapping, click <Breadcrumb>Add Claim</Breadcrumb>. A Reconcile lambda can map claims instead of or in addition to the claim mappings.

<Screenshot id="idp-external-jwt-claim-dialog" url="/admin/identity-provider/add/ExternalJWT?identityProvider.tenantId=30663132-6464-6665-3032-326466613934&global=false#claim-mapping" height={1100} alt="The Add Claim dialog of the External JWT Identity Provider form." />

<APIBlock>
  <APIField name="Incoming claim" required>
    The name of the claim in the JWT.
  </APIField>
  <APIField name="FusionAuth claim" required>
    The user field that receives the value of **Incoming claim**. When you select `UserData` or `RegistrationData`, FusionAuth stores the value in the user data or the registration data, with the claim name as the key.

    For example, when **Incoming claim** is `company` and **FusionAuth claim** is `RegistrationData`, FusionAuth stores the value in the registration data for the Application:

    ```json
    {
      "registration": {
        "data": {
          "company": "Acme Corp."
        }
      }
    }
    ```
  </APIField>
</APIBlock>

### OAuth

FusionAuth doesn't use the fields on the <Breadcrumb>OAuth</Breadcrumb> tab. The [Lookup API](/docs/apis/identity-providers/#lookup-an-identity-provider) returns the values, so your application can find where to send the user to log in with the third party.

<Screenshot id="idp-external-jwt-oauth" url="/admin/identity-provider/add/ExternalJWT?identityProvider.tenantId=30663132-6464-6665-3032-326466613934&global=false#oauth2" showHash height={900} alt="The OAuth tab of the External JWT Identity Provider form." />

<APIBlock>
  <APIField name="Authorization endpoint" optional>
    The URL of the OAuth 2.0 [[Authorization endpoint]] of the third-party identity provider.
  </APIField>
  <APIField name="Token endpoint" optional>
    The URL of the OAuth 2.0 [[Token endpoint]] of the third-party identity provider.
  </APIField>
</APIBlock>
