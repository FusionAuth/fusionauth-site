Configure Azure AD (Microsoft Entra ID) as a SAML v2 Identity Provider. FusionAuth acts as the service provider (SP), and Azure AD acts as the Identity Provider (IdP). The FusionAuth login page then shows a <Breadcrumb>Login with Azure AD</Breadcrumb> button that connects to Azure AD users and applications through SAML.

## Create an Application in Azure

<Aside type="note">
This guide uses the SAML single sign-on feature of Azure.
</Aside>

When you already have an Azure AD Enterprise application, skip this section. Otherwise, create an application:

1. In the [Azure portal](https://portal.azure.com/#home), navigate to <Breadcrumb>Enterprise Applications</Breadcrumb>.
1. Click <Breadcrumb>New application</Breadcrumb>.
1. Click <Breadcrumb>Create your own application</Breadcrumb>.
1. Enter a name for the application.
1. Select `Integrate any other application you don't find in the gallery (Non-gallery)`.
1. Click <Breadcrumb>Create</Breadcrumb>.

![The Azure form to create a non-gallery Enterprise application.](/img/docs/lifecycle/authenticate-users/identity-providers/enterprise/create-non-gallery-application.png)

## Configure Your Azure Application

On the home screen of your application, click <Breadcrumb>Single sign-on</Breadcrumb>. Then select the SAML option.

![The Azure single sign-on options, with SAML available.](/img/docs/lifecycle/authenticate-users/identity-providers/enterprise/configure-single-sign-on-saml.png)

Azure AD needs an [[SAML Entity Id::Entity ID]] from FusionAuth before Azure AD generates an [[X.509]] certificate. FusionAuth needs an X.509 certificate before you can create the Identity Provider that supplies the Entity ID. To work around the dependency, follow these steps:

1. Import a placeholder X.509 certificate into [[Key Master]].
1. Create a SAML Identity Provider in FusionAuth with the placeholder certificate.
1. Update your Azure AD Enterprise application with values from the new Identity Provider. Azure AD then generates a valid X.509 certificate.
1. Update the SAML Identity Provider in FusionAuth with the certificate from Azure AD.
1. Complete the integration.

When you already have a valid X.509 certificate, use the certificate in the second step, and skip the placeholder steps.

## Import a Placeholder X.509 Certificate

FusionAuth never uses the placeholder certificate to verify a login, so any valid X.509 certificate works. To generate a placeholder certificate, run the following command:

```shell
openssl req -x509 -newkey rsa:2048 -nodes -keyout /dev/null -out placeholder.crt -subj "/CN=placeholder" -days 30
```

The command writes the certificate to `placeholder.crt` and discards the private key.

Navigate to <Breadcrumb>Settings -> Key Master</Breadcrumb>, click <Breadcrumb>Import Certificate</Breadcrumb>, and paste the contents of `placeholder.crt`.

<Screenshot id="idp-key-import-certificate" url="/admin/key/" height={1000} alt="The Key Master page in the Admin UI, with the Import Certificate option." />

After you configure Azure AD, Azure AD gives you the X.509 certificate that signs SAML logins.

## Create a SAML v2 Identity Provider

In the FusionAuth Admin UI, navigate to <Breadcrumb>Settings -> Identity Providers -> Add</Breadcrumb>, and select the `SAML V2` Identity Provider.

<Screenshot id="idp-azure-saml-edit" url="/admin/identity-provider/edit/SAMLv2/00000000-0000-0000-0000-f20000000112" height={1100} alt="The SAML v2 Identity Provider form in the Admin UI, configured for Azure AD." />

Complete the following fields:

* **Name**: a name that describes the connection, such as `Pied Piper Azure AD`.
* **IdP endpoint**: the **Login URL** value from your Azure AD application, as shown in the following image.

  ![The Login URL in step four of the Azure AD SAML configuration.](/img/docs/lifecycle/authenticate-users/identity-providers/enterprise/step-four-idp-endpoint.png)

* **Verification keys**: the placeholder certificate that you imported. You replace the placeholder later.

Enable **Enable debug logging**. FusionAuth then writes debug information to the Event Log. To view the Event Log, navigate to <Breadcrumb>System -> Event Log</Breadcrumb>. Turn off debug logging when you run in production.

<Aside type="note">
For more information about the Event Log, see the [Event Logs API](/docs/apis/event-logs) and [Troubleshooting](/docs/deploy/troubleshoot/troubleshooting#event-log).
</Aside>

Then click the <Breadcrumb>Applications</Breadcrumb> tab of your SAML v2 Identity Provider, and enable the Identity Provider for the Application.

<Screenshot id="idp-azure-saml-applications" url="/admin/identity-provider/edit/SAMLv2/00000000-0000-0000-0000-f20000000112#applications" crop="#screenshot-band" cropPadding={0} alt="The Applications tab of the SAML v2 Identity Provider, with the Identity Provider enabled for an Application." />

When you save the Identity Provider, FusionAuth can show a CORS warning. Follow the instructions on the screen. For more information, see [CORS Configuration](/docs/authentication/identity-providers/overview-samlv2#cors-configuration).

### Linking Options

When you [link users by email](/docs/authentication/identity-providers/#linking-strategies), configure the SAML Identity Provider to find the email claim. Navigate to <Breadcrumb>Settings -> Identity Providers -> Your SAML IdP -> Edit</Breadcrumb>, and click the <Breadcrumb>Options</Breadcrumb> tab. Then enter the claim in the **Email claim** field.

<Screenshot id="idp-azure-saml-options" url="/admin/identity-provider/edit/SAMLv2/00000000-0000-0000-0000-f20000000112#options" crop="#screenshot-band" cropPadding={0} alt="The Options tab of the SAML v2 Identity Provider, with a custom email claim." />

The location of the email claim can vary in an existing Azure AD application. A default Azure AD application uses the following email claim:

```plaintext
http://schemas.xmlsoap.org/ws/2005/05/identity/claims/emailaddress
```

<Aside type="note">
When you aren't sure which claim to use, the Event Log shows the SAML response that Azure sends to FusionAuth.
</Aside>

The SAML response in the Event Log contains the claim. In a default Azure AD application, the email claim is nested:

```xml
<AttributeStatement>
    <!-- ... -->
    <Attribute Name="http://schemas.xmlsoap.org/ws/2005/05/identity/claims/emailaddress">
        <AttributeValue>*your*email*</AttributeValue>
    </Attribute>
    <!-- ... -->
</AttributeStatement>
```

## Finish Setup of Azure AD Application

Next, enter the values from the FusionAuth Identity Provider into your Azure AD application.

Navigate to your Azure AD application. Under step one, click the pencil icon to edit the configuration.

![The five steps of the Azure AD SAML configuration.](/img/docs/lifecycle/authenticate-users/identity-providers/enterprise/saml-5-steps-overview.png)

Add the **Entity ID** and **Reply URL**. To find the values, navigate to <Breadcrumb>Settings -> Identity Providers</Breadcrumb>, and click the magnifying glass in the row of your Identity Provider. The Entity ID is the Issuer value in FusionAuth. Enter the **Entity** and **ACS** values from FusionAuth into Azure AD.

## Download and Import the X.509 Certificate

Replace the placeholder certificate with the certificate from Azure AD. On the overview of your SAML application in Azure AD, under step three, download the Certificate (Base64).

![The Certificate (Base64) download in step three of the Azure AD SAML configuration.](/img/docs/lifecycle/authenticate-users/identity-providers/enterprise/generated-certificate.png)

Import the certificate into Key Master: <Breadcrumb>Settings -> Key Master -> Import Certificate</Breadcrumb>.

Then add the new certificate to the Identity Provider: <Breadcrumb>Settings -> Identity Providers -> your SAML IdP -> Verification keys</Breadcrumb>. Remove the placeholder certificate from **Verification keys**, and delete the placeholder certificate from Key Master.

<Aside type="tip">
Azure AD can publish more than one signing certificate in the federation metadata of the application, such as during a certificate rollover. Import each signing certificate, and add each one to **Verification keys**. FusionAuth then verifies a SAML response signed with any of the certificates. For more information, see [Rotate Identity Provider Certificates](/docs/authentication/identity-providers/overview-samlv2#rotate-identity-provider-certificates).
</Aside>

## Configure the FusionAuth Application Redirect URL

Configure where FusionAuth sends users after the Azure AD login. The redirect URL can be any URL.

Navigate to <Breadcrumb>Applications -> Your Application -> OAuth</Breadcrumb>. Update the **Authorized redirect URLs** field, and enable the [[Authorization Code grant]].

<Screenshot id="idp-app-oauth" url="/admin/application/edit?applicationId=00000000-0000-0000-0000-f20000000001&tenantId=30663132-6464-6665-3032-326466613934#oauth" showHash height={1400} alt="The OAuth tab of a FusionAuth Application, with an authorized redirect URL." />

## Assign Users

<Aside type="note">
When your existing Azure AD application already has assigned users, skip this step.
</Aside>

Assign Azure AD users to your Azure AD application. Navigate to <Breadcrumb>Users and groups</Breadcrumb>, click <Breadcrumb>Add user/group</Breadcrumb>, and follow the instructions to add a user.

![The Azure AD form to add a user to an application.](/img/docs/lifecycle/authenticate-users/identity-providers/enterprise/add-user-azure.png)

## Complete the Login

To test the integration, log in to the FusionAuth Admin UI, and navigate to <Breadcrumb>Applications -> Your Application</Breadcrumb>. Choose <Breadcrumb>View</Breadcrumb>, scroll to the <Breadcrumb>OAuth2 & OpenID Connect Integration details</Breadcrumb> section, and copy the Login URL.

<Screenshot id="idp-app-login-url" url="/admin/application/" height={1000} alt="The OAuth2 and OpenID Connect Integration details of a FusionAuth Application, with the Login URL.">
  <Highlight selector="[data-hl='idp-dialog-section']" />
</Screenshot>

Open the Login URL in a new tab. The login page shows the Azure AD button from the beginning of this guide. Click the button, and log in as one of the Azure AD users that you assigned. FusionAuth then sends you to your [[redirect URL]].

When the login fails, review the Event Log at <Breadcrumb>System -> Event Log</Breadcrumb>. For help with an invalid signature error, see [Invalid Signature Errors](/docs/authentication/identity-providers/overview-samlv2#invalid-signature-errors).
