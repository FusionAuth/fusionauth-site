<Aside type="caution">
IdP-initiated SSO with this Identity Provider is less secure than a service provider-initiated login, and FusionAuth doesn't recommend IdP-initiated SSO.

During an IdP-initiated login, the third-party Identity Provider sends FusionAuth a SAML Authentication Response that says a user has authenticated, without any context. FusionAuth didn't start the login, so FusionAuth can verify less. FusionAuth must also allow a cross-site request from the third party.

Enable IdP-initiated SSO only to support a legacy integration, or when the user experience matters more than the risk.
</Aside>

<Aside type="note">
In version `1.43.0` and later, you need this configuration only for an IdP that supports only IdP-initiated login. The [SAML v2 Identity Provider](/docs/authentication/identity-providers/overview-samlv2) supports both IdP-initiated and SP-initiated login.
</Aside>

This Identity Provider lets FusionAuth accept a SAML response that a SAML v2 Identity Provider initiates. FusionAuth acts as the SAML v2 service provider (SP).

A SAML flow usually begins at a service provider such as FusionAuth. In a [[service provider initiated login]], the Identity Provider returns the SAML Authentication Response to the service provider in response to an authentication request. FusionAuth can validate certain parameters, and FusionAuth accepts only a response to a request that FusionAuth initiated.

During an IdP-initiated login, the third-party Identity Provider sends FusionAuth a SAML Authentication Response without a matching request. FusionAuth doesn't have the full context of the login, so FusionAuth can verify less, and FusionAuth must allow a cross-site request from the third party.

Some providers need specific configuration. The following guide covers one of those providers:

* [Configure SAML v2 IdP-Initiated SSO for Okta](/docs/authentication/identity-providers/enterprise/okta-samlv2-idp-initiated)

To request a guide for another provider, open a request on [GitHub](https://github.com/FusionAuth/fusionauth-site/issues).

After you complete the configuration, users can log in to FusionAuth directly from the SAML v2 IdP.

<Aside type="note">
IdP-initiated login doesn't support [CIMD clients](/docs/authentication/oauth/client-registration#client-id-metadata-documents). The Applications list for this Identity Provider doesn't show [[CIMD]] domains. <AvailableSince since="1.70.0" />
</Aside>

## Create a SAML v2 IdP Initiated Identity Provider

To create the Identity Provider, navigate to <Breadcrumb>Settings -> Identity Providers</Breadcrumb>, click <Breadcrumb>Add provider</Breadcrumb>, and select <Breadcrumb>SAML v2 IdP Initiated</Breadcrumb>. Then complete the required fields on the <Breadcrumb>Add SAML v2 IdP Initiated</Breadcrumb> panel.

### Form Fields

<APIBlock>
  <APIField name="Enabled">
    Whether this Identity Provider is enabled. When you disable the Identity Provider, FusionAuth disables the Identity Provider globally.
  </APIField>
  <APIField name="Id" optional>
    An optional UUID. When you leave out the Id, FusionAuth generates a unique Id.
  </APIField>
  <APIField name="Tenant" optional since="1.62.0">
    The Tenant that this Identity Provider belongs to. The field appears only when you select a specific Tenant on the previous page. When you select `Global identity provider` on the previous page, the field doesn't appear.
  </APIField>
  <APIField name="Name" required>
    A unique name for the Identity Provider. FusionAuth uses the name for display only, and you can change the name later.
  </APIField>
  <APIField name="Issuer" required>
    The [[SAML Entity Id::EntityId]] (unique identifier) of the SAML v2 Identity Provider. The Identity Provider gives you this value.
  </APIField>
  <APIField name="Verification keys" required since="1.69.0">
    The keys in [[Key Master]] that verify the signature on SAML responses from the Identity Provider. Import every signing certificate that the Identity Provider publishes, and add all of them. The key marked **Default** verifies responses whose signature doesn't include a certificate. For more information, see [Signature Verification](/docs/authentication/identity-providers/overview-samlv2#signature-verification).
  </APIField>
  <APIField name="Linking strategy" optional since="1.28.0">
    The linking strategy for the SAML v2 Identity Provider. For more information, see [Linking Strategies](/docs/authentication/identity-providers/linking-strategies).

    <LinkingStrategyEditLimit />
  </APIField>
  <APIField name="Reconcile lambda" optional>
    A lambda that maps custom claims from the SAML response to the FusionAuth `User` and `Registration`. For more information, see [SAML v2 Reconcile Lambda](/docs/lambdas/reconcile/samlv2-response-reconcile).

    To configure a lambda, navigate to <Breadcrumb>Customizations -> Lambdas</Breadcrumb>.
  </APIField>
  <APIField name="Enable debug logging" optional>
    Some Identity Providers don't comply with the SAML and XML signing specifications, which makes the integration harder.

    When you enable debug logging, FusionAuth writes debugging information to the Event Log during a SAML login. To view the Event Log, navigate to <Breadcrumb>System -> Event Log</Breadcrumb>.
  </APIField>
</APIBlock>

### Options

#### Form Fields

<APIBlock>
  <APIField name="Unique Id claim" optional>
    The name of the claim in the SAML response that contains the unique Id of the user. When you leave out the claim, FusionAuth uses the `NameID`.
  </APIField>
  <APIField name="Use NameId for email" optional>
    When enabled, FusionAuth reads the email address of the user from the `NameID` in the SAML response.
  </APIField>
  <APIField name="Email claim" required>
    The name of the email claim in the SAML response.

    When **Use NameId for email** is enabled, the Admin UI hides this field, and the field isn't required.
  </APIField>
  <APIField name="Username claim" optional>
    The name of the username claim in the SAML response. FusionAuth never uses the `NameID` as the username. When you leave out the claim, the user has no username unless the reconcile lambda sets one. Set the claim when the **Linking strategy** links by username.
  </APIField>
  <APIField name="Require encrypted assertions" optional since="1.55.1">
    When enabled, FusionAuth requires encrypted assertions in SAML responses from the Identity Provider. FusionAuth rejects a SAML response that contains an unencrypted assertion.
  </APIField>
  <APIField name="Assertion decryption key" optional since="1.55.1">
    The key that decrypts SAML responses. This field is required when **Require encrypted assertions** is enabled. To create, manage, or import a key, navigate to <Breadcrumb>Settings -> Key Master</Breadcrumb>.

    The key must contain an RSA private key. Give the matching public key or certificate to the SAML Identity Provider, which uses the public key to encrypt assertions.
  </APIField>
</APIBlock>

## Integration Details

After you configure the Identity Provider, FusionAuth displays the values that your SAML v2 Identity Provider needs to trust FusionAuth as a [[relying party]]. To view the values, navigate to <Breadcrumb>Settings -> Identity Providers</Breadcrumb>, and click <IconButton icon="view" /> next to your SAML provider.

## CORS Configuration

To complete the login request, the SAML v2 Identity Provider sends an HTTP `POST` request to the [[Assertion Consumer Service::callback URL]] in FusionAuth. To let the request through the [[CORS]] filter, navigate to <Breadcrumb>Settings -> System -> CORS</Breadcrumb>. Then add the origin of the SAML IdP as an **Allowed Origin** in the CORS configuration.

## Troubleshooting

To troubleshoot a SAML flow, enable **Enable debug logging**, and complete the SAML flow. Then navigate to <Breadcrumb>System -> Event Log</Breadcrumb>, and review the entries for configuration issues.

For help with an invalid signature error, see [Invalid Signature Errors](/docs/authentication/identity-providers/overview-samlv2#invalid-signature-errors).
