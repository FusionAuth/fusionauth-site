<AvailableSince since="1.17.0"/>

Add a Sign in with Apple button to the FusionAuth login page. This guide shows how to collect the configuration details from your Apple Developer account and configure the Apple Identity Provider, a [[social login]] option.

After you configure the Identity Provider, you can enable the `Sign in with Apple` button for one or more FusionAuth Applications. The following login page shows the Apple Identity Provider:

## Create an Apple Developer Account

Log in to your [Apple Developer account](https://developer.apple.com/), or create one. Then continue to the next step.

## Configure Your Apple Developer Account

When you already have an App ID, a Services ID, and a key configured for Sign in with Apple, use the existing values. Otherwise, complete the following sections.

### Register a New App ID

![The Identifiers page of an Apple Developer account.](/img/docs/lifecycle/authenticate-users/identity-providers/social/identity-provider-apple-identifiers.png)

<Steps>

1. In your Apple Developer account, navigate to <Breadcrumb>Certificates, Identifiers & Profiles</Breadcrumb> and select <Breadcrumb>Identifiers</Breadcrumb> in the left column.
1. Click the plus icon to add an identifier.

   ![The Apple form to register a new App ID.](/img/docs/lifecycle/authenticate-users/identity-providers/social/identity-provider-apple-add-app-ids.png)

1. Select <Breadcrumb>App IDs</Breadcrumb> and click <Breadcrumb>Continue</Breadcrumb>.
1. Select the type `App` and click <Breadcrumb>Continue</Breadcrumb>.
1. Fill in **Description**, specify the Bundle ID, and select **Sign in with Apple** in the list of capabilities. Click <Breadcrumb>Continue</Breadcrumb>.
1. Confirm your selection, record the App ID Prefix (Team ID), and click <Breadcrumb>Register</Breadcrumb>.

</Steps>

### Register a New Services ID

<Steps>

1. In your Apple Developer account, navigate to <Breadcrumb>Certificates, Identifiers & Profiles</Breadcrumb> and select <Breadcrumb>Identifiers</Breadcrumb> in the left column.
1. Click the plus icon to add an identifier.

   ![The Apple form to register a new Services ID.](/img/docs/lifecycle/authenticate-users/identity-providers/social/identity-provider-apple-add-service-ids.png)

1. Select <Breadcrumb>Services IDs</Breadcrumb> and click <Breadcrumb>Continue</Breadcrumb>.
1. Fill in **Description** and **Identifier**, and click <Breadcrumb>Continue</Breadcrumb>. Click <Breadcrumb>Register</Breadcrumb> on the next panel.
1. Edit the new Services ID, and turn on **Sign In with Apple**. Click <Breadcrumb>Configure</Breadcrumb> to open the Web Authentication Configuration panel.
1. When the panel doesn't show **Domains and Subdomains** and **Return URLs**, click the plus icon next to Website URLs.
1. Enter the domain and the Return URL of your FusionAuth service. For FusionAuth at `https://login.piedpiper.com`, the domain is `login.piedpiper.com`. The Return URL is the FusionAuth URL with a path of `/oauth2/callback`, such as `https://login.piedpiper.com/oauth2/callback`. Apple expects a secure `https` URL, so an `http` endpoint doesn't work, even in development or test environments. You can add more domains and Return URLs later.
1. Save your changes and click <Breadcrumb>Continue</Breadcrumb>. To confirm the changes to the Services ID, click <Breadcrumb>Save</Breadcrumb>.

</Steps>

### Register a New Key

![The Keys page of an Apple Developer account.](/img/docs/lifecycle/authenticate-users/identity-providers/social/identity-provider-apple-keys.png)

<Steps>

1. In your Apple Developer account, navigate to <Breadcrumb>Certificates, Identifiers & Profiles</Breadcrumb> and select <Breadcrumb>Keys</Breadcrumb> in the left column.
1. Click the plus icon to add a key.

   ![The Apple form to register a new key.](/img/docs/lifecycle/authenticate-users/identity-providers/social/identity-provider-apple-new-key.png)

1. Enter a name for the key.

   ![The Apple key form with Sign in with Apple selected.](/img/docs/lifecycle/authenticate-users/identity-providers/social/identity-provider-apple-new-key-signin.png)

1. Check **Sign in with Apple**, and click <Breadcrumb>Configure</Breadcrumb>.
1. Select the App ID that you created and click <Breadcrumb>Save</Breadcrumb>.
1. Click <Breadcrumb>Continue</Breadcrumb>, then click <Breadcrumb>Register</Breadcrumb> to confirm the key registration.
1. Download the key when Apple prompts you, and record the **Key ID**.

</Steps>

## Import the Private Key

Import the private key from the previous step into FusionAuth. Unless Apple says otherwise, the private key uses an elliptic curve.

<Steps>

1. In the Admin UI, navigate to <Breadcrumb>Settings -> Key Master</Breadcrumb>.
1. Select <Breadcrumb>Import Elliptic Private Key</Breadcrumb> in the actions at the top right.
1. Set **Key identifier** to the Key ID from the previous step.
1. Open the downloaded key file in a text editor, and copy the contents into **Private key**.

</Steps>

## Create an Apple Identity Provider in FusionAuth

Create the Apple Identity Provider in FusionAuth. Fill in the required fields with the values from your Apple Developer account. **Button text** is required and defaults to `Sign in with Apple`.

### Form Fields

<APIBlock>
  <APIField name="Id" optional since="1.61.0">
    An optional UUID. When you leave out the Id, FusionAuth generates a unique Id.
  </APIField>
  <APIField name="Tenant" optional since="1.62.0">
    The Tenant that this Identity Provider belongs to. The field appears only when you select a specific Tenant on the previous page. When you select `Global identity provider` on the previous page, the field doesn't appear.
  </APIField>
  <APIField name="Name" required since="1.61.0">
    A unique name for the Identity Provider. FusionAuth uses the name for display only, and you can change the name later.
  </APIField>
  <APIField name="Bundle Id" optional since="1.43.0">
    The Apple Bundle ID configured for Sign in with Apple in your Apple Developer account. To find the Bundle ID, navigate to <Breadcrumb>Certificates, Identifiers & Profiles -> Identifiers -> App IDs</Breadcrumb> in your Apple Developer account.

    The configuration needs **Bundle Id** or **Services Id**. When you leave out **Services Id**, this field is required.
  </APIField>
  <APIField name="Services Id" optional>
    The Apple Services ID configured for Sign in with Apple in your Apple Developer account. To find the Services ID, navigate to <Breadcrumb>Certificates, Identifiers & Profiles -> Identifiers -> Services IDs</Breadcrumb> in your Apple Developer account.

    <AvailableSince since="1.43.0" /> The configuration needs **Bundle Id** or **Services Id**. When you leave out **Bundle Id**, this field is required.
  </APIField>
  <APIField name="Team Id" required>
    The Apple App ID Prefix, or Team ID, configured for Sign in with Apple in your Apple Developer account. To find the Team ID, navigate to <Breadcrumb>Certificates, Identifiers & Profiles -> Identifiers -> App IDs</Breadcrumb> in your Apple Developer account.
  </APIField>
  <APIField name="Button text" required>
    The text of the button on the login form. The default value is `Sign in with Apple`.
  </APIField>
  <APIField name="Scope" optional>
    A space-separated list of the user attributes to request, such as `name email`. You can request the user's name, email address, or both. When **Linking strategy** links on email, request the `email` scope.
  </APIField>
  <APIField name="Signing key" required>
    The private signing key from Apple. FusionAuth signs the client secret with the key when FusionAuth requests an access token from Apple.
  </APIField>
  <APIField name="Linking strategy" required>
    How FusionAuth links an Apple user to a FusionAuth user. For more information, see [Linking Strategies](/docs/authentication/identity-providers/linking-strategies).

    <LinkingStrategyEditLimit />
  </APIField>
  <APIField name="Reconcile Lambda" optional>
    A lambda that maps custom claims from Apple to the user.

    To create a lambda, navigate to <Breadcrumb>Customizations -> Lambdas</Breadcrumb>.
  </APIField>
  <APIField name="Enable debug logging" optional>
    Creates Event Log entries that help you debug integration errors. To read the entries, navigate to <Breadcrumb>System -> Event Log</Breadcrumb>.
  </APIField>
</APIBlock>

## Apple Private Email Relay Configuration

When a user logs in with Apple, Apple lets the user send FusionAuth either the user's real email address or an anonymous email address.

An anonymous email address ends in `@privaterelay.appleid.com`. You can email the user at the anonymous address, and Apple routes the email through the Apple Private Email Relay service. To make sure your email arrives, register your email domain with Apple and configure your SMTP service provider. For more information, see [Communicating Using the Private Email Relay Service](https://developer.apple.com/documentation/sign_in_with_apple/sign_in_with_apple_js/communicating_using_the_private_email_relay_service).

Some email service providers document the configuration. For example, see the SendGrid article [Configuring Sign in with Apple](https://sendgrid.com/docs/ui/account-and-settings/configuring-sign-in-with-apple/).

## CORS Configuration

To complete the login, Apple sends an HTTP `POST` request to the [[callback URL]] in FusionAuth. To let the request through the [[CORS]] filter, navigate to <Breadcrumb>Settings -> System -> CORS</Breadcrumb> and add `https://appleid.apple.com` to **Allowed Origin**.

When the CORS configuration doesn't yet allow the Apple login request, the Admin UI shows the following warning after you configure the Apple Identity Provider:

<Screenshot id="idp-cors-warning-apple" width={1600} url="/admin/identity-provider/" height={1250} alt="The Admin UI warning that the CORS configuration doesn't allow Apple login requests.">
  <Highlight selector="[data-hl='section-box']" />
</Screenshot>

For more information, see the [CORS Filter reference](/docs/security/clients/cors).

### Troubleshooting CORS

When Safari logs a `403` status code in the browser console during login, add more configuration. The redirect flow differs slightly between browsers. Navigate to <Breadcrumb>Settings -> System -> CORS</Breadcrumb> and add the `GET` method to **Allowed methods**.

## Supporting Web and Mobile

<Aside type="version">
FusionAuth `1.43.0` and later supports web and mobile Sign in with Apple with a single Identity Provider configuration.
</Aside>

In FusionAuth `1.43.0` and later, follow [Using Bundle Id](#using-bundle-id). In earlier versions, follow [Using Services Id with Application Overrides](#using-services-id-with-application-overrides).

### Using Bundle Id

In FusionAuth `1.43.0` and later, Sign in with Apple from both web and mobile applications doesn't need more than one Application. The Identity Provider has the following fields:

* **Services Id** is the Apple Services ID for web applications.
* **Bundle Id** is the Apple Bundle ID for native applications.

Fill in the fields that your applications need:

* For a native app only, fill in **Bundle Id** and leave **Services Id** blank.
* For a web app only, fill in **Services Id** and leave **Bundle Id** blank.
* For both a native app and a web app, fill in **Bundle Id** and **Services Id**.

You can still override either field for each Application.

A [[login API]] request from a native application needs **data.isNativeApp** with the string value `"true"`. FusionAuth then uses **Bundle Id** instead of **Services Id**.

### Using Services Id with Application Overrides

Before FusionAuth `1.43.0`, Sign in with Apple from both web and mobile applications needs two configurations with different values:

* For web applications, **Services Id** is the Apple Services ID.
* For mobile applications, **Services Id** is the Apple Bundle ID.

One Application can't have more than one Apple Identity Provider. To support both mobile and web users:

<Steps>

1. Create two Applications in FusionAuth.
1. Enable the Apple Identity Provider for each Application.
1. In the <Breadcrumb>Overrides</Breadcrumb> section, set **Services Id** to the right value for each Application.

</Steps>

<Screenshot id="idp-apple-overrides" url="/admin/identity-provider/edit/Apple/00000000-0000-0000-0000-f20000000131#applications" crop="#screenshot-band" cropPadding={0} alt="The Overrides section of the Apple Identity Provider form.">
  <Highlight selector="[data-hl='idp-overrides']" />
</Screenshot>

Usually you register the user for both Applications when the user signs in with Apple. To do so, use a [User Registration Complete webhook](/docs/events/reference/user/registration/user-registration-create-complete).

## Troubleshooting

### Key Import Error

The UI may show the following error:

```
A request to the Apple Token API has failed. Unable to complete this login request.
```

The Event Log then shows the following error:

```
Status code [400] Error response is { "error" : "invalid_client" }
```

Check that you imported the private key from Apple with the **Key ID** from the Apple Developer account dashboard. When you import the key with the default behavior, FusionAuth generates a key identifier. The generated identifier doesn't match the value that Apple expects, and the integration fails with the error. To fix the error, import the private key again with the correct Id.

### Scope Error When Using the Link on Email Strategy

With a `Link on email` linking strategy, the UI may show the following error:

```
"An email address was not provided for the user. This account cannot be used to login, unable to complete this login request."
```

Check that you requested the `email` scope. For more information, see [Form Fields](/docs/authentication/identity-providers/social/apple#form-fields).

You may still see the error after you request the `email` scope, when an earlier configuration error made a full login or user creation fail. Apple sends the user's email address only on the first login, and only the user Id on later logins. To fix the error, reset access to your app on your Apple device. On a phone, navigate to <Breadcrumb>Phone Settings -> Apple ID -> Password & Security -> Apple ID logins -> Your App -> Stop using Apple ID</Breadcrumb>. On macOS, navigate to <Breadcrumb>System Settings -> Apple ID -> Password & Security -> Apple ID logins -> Your App -> Stop using Apple ID</Breadcrumb>. Then log in again, and Apple sends the email address.
