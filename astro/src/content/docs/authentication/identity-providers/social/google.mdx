Add a Login with Google button to the FusionAuth login page. This guide shows how to collect the credentials from Google and configure the Google Identity Provider, a [[Social login]] option.

After you configure the Identity Provider, you can enable the Google login button for one or more FusionAuth Applications. The following login page shows the Google Identity Provider:

## Create a Google Cloud Account

Log in to Google, or create a Google account. Then open the [Google Cloud console](https://console.cloud.google.com).

## Create Google OAuth Client Credentials

<Steps>

1. In the Google Cloud console, navigate to <Breadcrumb>APIs and Services -> Credentials</Breadcrumb>.
1. When Google asks you to select or create a project, do so. The following example creates a first project named `Pied Piper`:

   ![The Google Cloud form to create a project.](/img/docs/lifecycle/authenticate-users/identity-providers/social/google-cloud-create-project.png)

1. Navigate to <Breadcrumb>APIs & Services -> Credentials</Breadcrumb>. Click <Breadcrumb>Create credentials</Breadcrumb> and select <Breadcrumb>OAuth client ID</Breadcrumb>.

   ![The Create credentials menu in the Google Cloud console.](/img/docs/lifecycle/authenticate-users/identity-providers/social/google-cloud-create-credentials.png)

1. When an alert says you need to configure the consent screen first, click <Breadcrumb>Configure consent screen</Breadcrumb>.

   ![The Google Cloud alert to configure the consent screen.](/img/docs/lifecycle/authenticate-users/identity-providers/social/google-cloud-configure-consent.png)

1. Choose a consent type, usually `External`, and click <Breadcrumb>Create</Breadcrumb>.

   ![The Google Cloud choice between internal and external consent types.](/img/docs/lifecycle/authenticate-users/identity-providers/social/google-cloud-configure-consent-internal-external.png)

1. Fill out the required fields and click <Breadcrumb>Save</Breadcrumb>. The example sets the following fields:

   * **Application name**
   * **User support email** (not shown)
   * **App logo** (not shown)
   * **Authorized domains**
   * **Application Homepage link**
   * **Application Privacy Policy link**
   * **Application Terms of Service link**
   * **Developer contact information** (not shown)

   ![The Google Cloud consent screen configuration.](/img/docs/lifecycle/authenticate-users/identity-providers/social/google-cloud-configure-consent-screen.png)

1. To add or update scopes, click <Breadcrumb>Add or remove scopes</Breadcrumb>. Most applications select `https://www.googleapis.com/auth/userinfo.email`, `https://www.googleapis.com/auth/userinfo.profile`, and `openid`. You can enable any other scopes. Some scopes need more configuration in the Google console. For more information, see [Additional Steps for Your Google Application](#additional-steps-for-your-google-application) and the [full list of Google scopes](https://developers.google.com/identity/protocols/oauth2/scopes).

   Use the same scopes later in the FusionAuth Identity Provider configuration.

   ![The Google Cloud scope selection.](/img/docs/lifecycle/authenticate-users/identity-providers/social/google-cloud-configure-scopes.png)

1. Optionally add test users. Then click <Breadcrumb>Save and continue</Breadcrumb>.
1. Navigate to <Breadcrumb>APIs & Services -> Credentials</Breadcrumb>. Click <Breadcrumb>Create credentials</Breadcrumb> and select <Breadcrumb>OAuth client ID</Breadcrumb>.
1. Set **Application Type** to `Web application`.
1. Add the name of the application to the **Name Type** field.
1. Configure the panel for your login method. The example uses `https://login.piedpiper.com`, the FusionAuth URL for Pied Piper.
   * When you use the redirect method, add an absolute Authorized [[redirect URI]]. For FusionAuth at `login.piedpiper.com`, the value is `https://login.piedpiper.com/oauth2/callback`.
   * When you use the popup method, fill out **Authorized JavaScript origins** with the origin of your application login page.

   The following image shows both the popup origin and the redirect URL. Fill in only the one that your login method needs.

   ![The Google Cloud form to create an OAuth client Id.](/img/docs/lifecycle/authenticate-users/identity-providers/social/google-cloud-create-client-id.png)

1. Click <Breadcrumb>Create</Breadcrumb>.

</Steps>

Select the new credential to see the **Client ID** and **Client secret** for the next step.

![The Google OAuth client credentials.](/img/docs/lifecycle/authenticate-users/identity-providers/social/google-cloud-client-credentials.png)

## Create a Google Identity Provider

Create the Google Identity Provider in FusionAuth. Fill in **Client Id** and **Client secret** with the values from the Google Cloud console. Set **Scope** to the scopes that you configured in the Google console. **Button text** is required and defaults to `Login with Google`.

### Form Fields

<APIBlock>
  <APIField name="Id" optional since="1.61.0">
    An optional UUID. When you leave out the Id, FusionAuth generates a unique Id.
  </APIField>
  <APIField name="Tenant" optional since="1.62.0">
    The Tenant that this Identity Provider belongs to. The field appears only when you select a specific Tenant on the previous page. When you select `Global identity provider` on the previous page, the field doesn't appear.
  </APIField>
  <APIField name="Name" required since="1.61.0">
    A unique name for the Identity Provider. FusionAuth uses the name for display only, and you can change the name later.
  </APIField>
  <APIField name="Client Id" required>
    The **Client ID** from the Google credentials settings.
  </APIField>
  <APIField name="Client secret" required>
    The **Client secret** from the Google credentials settings.
  </APIField>
  <APIField name="Login Method" optional>
    What happens after the user clicks the Identity Provider button, such as `Login with Google`:

    * `Use redirect for login`: FusionAuth redirects the user to a Google login page. After the user authenticates, Google redirects the user back to FusionAuth. Set the redirect URL to an absolute URL in the Google console for your application. For a hostname of `login.piedpiper.com`, the redirect URL is `https://login.piedpiper.com/oauth2/callback`.
    * `Use popup for login`: FusionAuth opens a popup where the user logs in with Google. After the user authenticates, the popup closes. Allow your hostname in **Authorized JavaScript origins** in the Google console for your application, such as `https://login.piedpiper.com`.
    * `Use vendor JavaScript`: The vendor JavaScript library decides the login method.

    When the OAuth [[Authorize endpoint]] request includes an `idp_hint`, FusionAuth uses the redirect method, even when you select `Use popup for login`.

    <AvailableSince since="1.44.0" />

    Before FusionAuth `1.44.0`, `Use popup for login` doesn't work. `UseRedirect` continues to work. For more information, see the [`1.44.0` release notes](/docs/release-notes#version-1-44-0). For a workaround and the update process, see the [forum post about the Google Identity Provider changes](/community/forum/topic/2329/upcoming-google-identity-provider-changes).
  </APIField>
  <APIField name="Button text" required>
    The text of the button on the login form. The default value is `Login with Google`.

    <AvailableSince since="1.44.0" />

    FusionAuth uses **Button text** only when **Login Method** is `Use redirect for login`. Google manages the button text for the other login methods. Google allows minor adjustments through the Google API. To adjust the button, add any valid API parameter to **Button properties**.
  </APIField>
  <APIField name="Scope" optional>
    The scopes that FusionAuth requests from the user during login. Common scopes are `email`, `profile`, and `openid`. For more information, see the Google login documentation.

    <AvailableSince since="1.44.0" />

    FusionAuth uses **Scope** only when **Login Method** is `Use redirect for login`. FusionAuth always requests the `email`, `profile`, and `openid` scopes for the other login methods.
  </APIField>
  <APIField name="Linking strategy" optional>
    How FusionAuth links a Google user to a FusionAuth user. For more information, see [Linking Strategies](/docs/authentication/identity-providers/linking-strategies).

    <LinkingStrategyEditLimit />
  </APIField>
  <APIField name="Reconcile lambda" optional since="1.17.0">
    A lambda that maps custom claims from Google to the user.

    To create a lambda, navigate to <Breadcrumb>Customizations -> Lambdas</Breadcrumb>.
  </APIField>
  <APIField name="Enable debug logging" optional defaults="false">
    Creates Event Log entries that help you debug integration errors. To read the entries, navigate to <Breadcrumb>System -> Event Log</Breadcrumb>.
  </APIField>
</APIBlock>

### Options

The <Breadcrumb>Options</Breadcrumb> tab sets properties for the [Google Identity Services API](https://developers.google.com/identity/gsi/web/reference/html-reference).

<Aside type="note">
FusionAuth applies **API properties** and **Button properties** only when the login uses the Google Identity Services (GIS) API. When **Login Method** is `Use redirect for login`, FusionAuth doesn't use the GIS API or the properties. To style the button in that case, use [Themes](/docs/theme/).
</Aside>

#### Form Fields

<APIBlock>
  <APIField name="API properties" optional since="1.44.0">
    The Google Identity Services login API configuration, as a string in properties file format. You can add any attribute from the [Google Identity Services HTML reference](https://developers.google.com/identity/gsi/web/reference/html-reference#element_with_id_g_id_onload). Templates that support Google login can reference the properties to initialize the API with HTML or JavaScript. Leave the `data-` prefix off the property names.

    When you leave out the value, FusionAuth uses the following properties:

    ```ini title="Default API properties"
    auto_prompt=true
    auto_select=false
    cancel_on_tap_outside=false
    context=signin
    itp_support=true
    ```
  </APIField>
  <APIField name="Button properties" optional since="1.44.0" defaults="'See Description'">
    The Google Identity Services button configuration, as a string in properties file format. You can add any attribute from the [Google Identity Services HTML reference](https://developers.google.com/identity/gsi/web/reference/html-reference#element_with_class_g_id_signin). Templates that support Google login can reference the properties to render the login button with HTML or JavaScript. Leave the `data-` prefix off the property names.

    When you leave out the value, FusionAuth uses the following properties:

    ```ini title="Default button properties"
    logo_alignment=left
    shape=rectangular
    size=large
    text=signin_with
    theme=outline
    type=standard
    ```
  </APIField>
</APIBlock>

### Google One Tap

Google One Tap lets a user register or log in with a single action on applications that support One Tap.

![A Google One Tap prompt.](/img/docs/lifecycle/authenticate-users/identity-providers/social/login-google-one-tap.png)

To turn on Google One Tap in FusionAuth `1.44.0` and later:

* Set **Login Method** to `Use popup for login`.
* Add `auto_prompt=true` to **API properties**.

## Custom Parameters

Some Google functionality needs custom URL parameters when the login starts. Examples include the following parameters:

* `access_type=offline` returns a [[refresh token]] from Google. Google returns the refresh token only the first time the user consents. To get a refresh token on every login, also add `prompt=consent`. For more information, see the [Google offline access documentation](https://developers.google.com/identity/protocols/oauth2/web-server).
* `prompt=select_account` forces an account selection screen.

For more parameters, see the [Google OpenID Connect advanced topics](https://developers.google.com/identity/protocols/oauth2/openid-connect#advancedtopics).

The Google Identity Provider doesn't support custom parameters. Google conforms to OIDC, so an OpenID Connect Identity Provider gives the same functionality with a little more configuration. To use custom parameters:

<Steps>

1. Create an [OpenID Connect Identity Provider](/docs/authentication/identity-providers/overview-oidc).
1. Set **Discover endpoints** to `false`.
1. Enter the endpoints from the [Google Discovery document](https://developers.google.com/identity/protocols/oauth2/openid-connect#discovery).
1. Add the space-separated [Google OAuth2 scopes](https://developers.google.com/identity/protocols/oauth2/scopes) to **Scope**. The most common scopes are `openid`, `profile`, and `email`. When you use the [linking on email](/docs/authentication/identity-providers/linking-strategies) strategy, include `email`.
1. Append the parameters to the **Authorization endpoint** value, such as `https://accounts.google.com/o/oauth2/v2/auth?access_type=offline&prompt=select_account`.

</Steps>

## Limitations

The Google Identity Services (GIS) client supports one configuration per page. FusionAuth therefore can't show more than one GIS configuration on the same login page.

A Google Identity Provider with a **Login Method** of `Use popup for login` or `Use vendor JavaScript` uses the GIS client. The GIS client gives a more dynamic user experience and supports Google One Tap.

When more than one Google Identity Provider that uses the GIS client is available on the same login page, the themed page initializes the button for one configuration. The other GIS Identity Providers show no button.

To work around the limitation, use one of the following options:

* Enable only one Google Identity Provider that uses the GIS client for each Application.
* Set **Login Method** to `Use redirect for login` on the other Google Identity Providers.
