Add a Login with Twitter/X button to the FusionAuth login page. This guide shows how to collect the credentials from Twitter and configure the Twitter Identity Provider, a [[Social login]] option.

After you configure the Identity Provider, you can enable the Twitter login button for one or more FusionAuth Applications. The following login page shows the Twitter Identity Provider:

## Create a Twitter Account

Log in to Twitter, or create a Twitter account. Then open the [Twitter Developer Portal](https://developer.twitter.com).

When you don't have a developer account, apply for access to the Twitter API in the [Twitter Developer Portal](https://developer.twitter.com). After Twitter grants access to a developer account, continue to the next step.

## Create a Twitter App

Twitter creates an application as part of the developer account setup. When you don't have a Twitter app, create one in this step. When you already have a Twitter app for FusionAuth, review this section anyway to check that the app supports Twitter login.

Your level of access in the Twitter project limits app creation. To create more than one app in the project, or to change settings that `Essential` access restricts, apply for elevated access. For more information, see [Twitter access levels and permissions](https://developer.x.com/en/docs/projects/).

The [Twitter Developer Portal dashboard](https://developer.twitter.com/en/portal/projects-and-apps) lists your Twitter apps.

![The Twitter Developer Portal page to create an app.](/img/docs/lifecycle/authenticate-users/identity-providers/social/twitter-home-create.png)

The following sections cover the app settings that let Twitter connect with FusionAuth.

### Record the Keys and Token

Twitter shows the API key and API secret key when you create the app. Record the values for the FusionAuth Identity Provider.

### Authentication Settings

Under <Breadcrumb>User authentication settings</Breadcrumb>, change the app settings as shown:

![The Twitter user authentication settings, with labels for the callback URI and the email request.](/img/docs/lifecycle/authenticate-users/identity-providers/social/twitter-auth-settings.png)

#### Add a Callback URI

The image labels this setting as step 1.

In the <Breadcrumb>App Info</Breadcrumb> section, register a **Callback URI / Redirect URL** and specify your website URL. Set the [[redirect URL]] to an absolute URL. For a FusionAuth hostname of `login.piedpiper.com`, the redirect URL is `https://login.piedpiper.com/oauth2/callback`.

#### Enable Request Email

The image labels this setting as step 2.

To link users by email, check **Request email from users**. Some Twitter users have no email address. When your users may not have one, configure the Identity Provider to link on username, or use a reconcile lambda to map custom claims from Twitter. For workarounds, see [Linking Strategies](/docs/authentication/identity-providers/linking-strategies).

### Keys and Tokens

The <Breadcrumb>Keys and tokens</Breadcrumb> section shows the Consumer API Keys and Secret. The values match the values that Twitter showed when you created the app. The FusionAuth Identity Provider uses the values.

![The Twitter Keys and tokens section.](/img/docs/lifecycle/authenticate-users/identity-providers/social/twitter-keys-tokens.png)

## Create a Twitter Identity Provider

Create the Twitter Identity Provider in FusionAuth. The add menu on the Identity Providers page lists Twitter:

<Screenshot id="idp-add-menu-twitter" url="/admin/identity-provider/" height={1000} alt="The add menu on the Identity Providers page, with Twitter highlighted.">
  <Highlight selector="[data-hl='idp-menu-item']" />
</Screenshot>

Fill in **Consumer key** and **Consumer secret** with the values from the <Breadcrumb>Keys and tokens</Breadcrumb> tab of the Twitter app. **Button text** is required and defaults to `Login with Twitter`.

### Form Fields

<APIBlock>
  <APIField name="Id" optional since="1.61.0">
    An optional UUID. When you leave out the Id, FusionAuth generates a unique Id.
  </APIField>
  <APIField name="Tenant" optional since="1.62.0">
    The Tenant that this Identity Provider belongs to. The field appears only when you select a specific Tenant on the previous page. When you select `Global identity provider` on the previous page, the field doesn't appear.
  </APIField>
  <APIField name="Name" required since="1.61.0">
    A unique name for the Identity Provider. FusionAuth uses the name for display only, and you can change the name later.
  </APIField>
  <APIField name="Consumer key" required>
    The **API key** from the Keys and tokens settings of the Twitter app.
  </APIField>
  <APIField name="Consumer secret" required>
    The **API secret key** from the Keys and tokens settings of the Twitter app.
  </APIField>
  <APIField name="Callback URL" since="1.6.0">
    The callback URL to add to your Twitter configuration.
  </APIField>
  <APIField name="Button text" required>
    The text of the button on the login form. The default value is `Login with Twitter`.
  </APIField>
  <APIField name="Linking strategy" optional>
    How FusionAuth links a Twitter user to a FusionAuth user. For more information, see [Linking Strategies](/docs/authentication/identity-providers/linking-strategies).

    <LinkingStrategyEditLimit />
  </APIField>
  <APIField name="Reconcile lambda" optional since="1.17.0">
    A lambda that maps custom claims from Twitter to the user.

    To create a lambda, navigate to <Breadcrumb>Customizations -> Lambdas</Breadcrumb>.
  </APIField>
  <APIField name="Enable debug logging" optional defaults="false">
    Creates Event Log entries that help you debug integration errors. To read the entries, navigate to <Breadcrumb>System -> Event Log</Breadcrumb>.
  </APIField>
</APIBlock>

## Proxy Details

FusionAuth detects the public URL of the instance at runtime, and sends the URL to Twitter as the callback URL. When FusionAuth runs behind a proxy and the host or protocol behind the proxy differs from the public URL, the proxy must add the `X-Forwarded-Host` and `X-Forwarded-Proto` headers.

For example, a proxy that performs SSL acceleration serves a public `https` URL, while the URL behind the proxy uses `http`. Most proxies add the `X-Forwarded-Proto` header in this case, and FusionAuth then sends the correct URL to Twitter.
