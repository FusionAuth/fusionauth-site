Add a Sign in with LinkedIn button to the FusionAuth login page. This guide shows how to collect the credentials from LinkedIn and configure the LinkedIn Identity Provider, a [[Social login]] option.

After you configure the Identity Provider, you can enable the LinkedIn login button for one or more FusionAuth Applications. The following login page shows the LinkedIn Identity Provider:

## Create a LinkedIn Account

Log in to LinkedIn, or create a LinkedIn account. Then open the [LinkedIn developer portal](https://www.linkedin.com/developers/).

## Create a LinkedIn App

When you have a LinkedIn app to use, skip this step.

Otherwise, fill out the [new application form](https://www.linkedin.com/developer/apps/new). The following example creates an app named `Pied Piper`:

![The LinkedIn form to create an app.](/img/docs/lifecycle/authenticate-users/identity-providers/social/linkedin-create-app.png)

## Grant Your App the Required Permissions

<Steps>

1. In the LinkedIn developer portal, navigate to <Breadcrumb>My apps -> Your Application</Breadcrumb>.
1. Navigate to <Breadcrumb>My apps -> Your Application -> Products</Breadcrumb>. When the application has no <Breadcrumb>Products</Breadcrumb> tab, such as for your first LinkedIn application, navigate to <Breadcrumb>Products</Breadcrumb> in the top-level menu instead.
1. Select `Sign In With LinkedIn` and accept the terms.

</Steps>

<Aside type="note">
  The LinkedIn platform team may review the application before the product is available.
</Aside>

![Adding the Sign In With LinkedIn product to a LinkedIn app.](/img/docs/lifecycle/authenticate-users/identity-providers/social/linkedin-adding-product.png)

## Set Up Your LinkedIn App Client Credentials

<Steps>

1. In the LinkedIn developer portal, navigate to <Breadcrumb>My apps -> Your Application</Breadcrumb>.
1. Navigate to <Breadcrumb>Auth -> Application credentials</Breadcrumb>. Record the **Client ID** and the **Client Secret**.

   ![The LinkedIn application credentials.](/img/docs/lifecycle/authenticate-users/identity-providers/social/linkedin-app-credentials.png)

1. Add your [[redirect URL]] to **Authorized redirect URLs for your app**. The redirect URL is the FusionAuth hostname followed by `/oauth2/callback`. For example, when FusionAuth runs at `https://login.piedpiper.com`, add `https://login.piedpiper.com/oauth2/callback`.
1. Save the setting.

</Steps>

The <Breadcrumb>OAuth 2.0 Scopes</Breadcrumb> section shows the following scopes:

* `openid`
* `profile`
* `email`

When the LinkedIn UI doesn't show the scopes, add the scopes to the FusionAuth configuration and log in through the integration. The first login should make LinkedIn update the configuration in the LinkedIn UI. For more information, see [Create a LinkedIn Identity Provider](#create-a-linkedin-identity-provider).

### LinkedIn Identity Provider Scopes

<Aside type="caution">
  LinkedIn has changed the LinkedIn API programs over time.
</Aside>

The scopes available to your application depend on when you created the application in LinkedIn. An older Compliance program, which no longer registers new apps, uses different scopes than the newer program based on OpenID Connect.

The legacy scopes are `r_emailaddress` for the email address and `r_liteprofile` or `r_basicprofile` for the rest of the user info. The legacy scopes call the LinkedIn [Profile API](https://learn.microsoft.com/en-us/linkedin/shared/integrations/people/profile-api).

Before FusionAuth `1.49.0`, FusionAuth supports only the legacy scopes. The new scopes `openid`, `profile`, and `email` call the LinkedIn [UserInfo API](https://learn.microsoft.com/en-us/linkedin/consumer/integrations/self-serve/sign-in-with-linkedin-v2#api-request-to-retreive-member-details). To use the new scopes, update to FusionAuth `1.49.0` or later.

When the scopes don't appear, check that you added the LinkedIn product to the LinkedIn app. You may also need to reload the app page, or log out of LinkedIn and log back in, so the application shows the right permissions.

## Create a LinkedIn Identity Provider

Create the LinkedIn Identity Provider in FusionAuth. Fill in **Client Id** and **Client secret** with the values you recorded. **Button text** is required and defaults to `Sign in with LinkedIn`.

### Form Fields

<APIBlock>
  <APIField name="Id" optional since="1.61.0">
    An optional UUID. When you leave out the Id, FusionAuth generates a unique Id.
  </APIField>
  <APIField name="Tenant" optional since="1.62.0">
    The Tenant that this Identity Provider belongs to. The field appears only when you select a specific Tenant on the previous page. When you select `Global identity provider` on the previous page, the field doesn't appear.
  </APIField>
  <APIField name="Name" required since="1.61.0">
    A unique name for the Identity Provider. FusionAuth uses the name for display only, and you can change the name later.
  </APIField>
  <APIField name="Client Id" required>
    The **Client ID** from the LinkedIn credentials settings.
  </APIField>
  <APIField name="Client secret" required>
    The **Client Secret** from the LinkedIn credentials settings.
  </APIField>
  <APIField name="Button text" required>
    The text of the button on the login form. The default value is `Sign in with LinkedIn`.
  </APIField>
  <APIField name="Scope" optional>
    The scopes that FusionAuth requests from the user during login. The default scopes are the suggested values. For more information, see the [LinkedIn documentation](https://docs.microsoft.com/en-us/linkedin/).
  </APIField>
  <APIField name="Linking strategy" optional defaults="Link on email. Create the user if they do not exist.">
    How FusionAuth links a LinkedIn user to a FusionAuth user. For more information, see [Linking Strategies](/docs/authentication/identity-providers/linking-strategies).

    <LinkingStrategyEditLimit />

    When **Linking strategy** links on email and the LinkedIn response contains an `email_verified` claim of `false`, FusionAuth doesn't create the link. FusionAuth returns an error that says a link can't use an unverified email address.
  </APIField>
  <APIField name="Reconcile lambda" optional>
    A lambda that maps custom claims from LinkedIn to the user. For more information, see the [LinkedIn Reconcile lambda documentation](/docs/lambdas/reconcile/linkedin-reconcile).

    To create a lambda, navigate to <Breadcrumb>Customizations -> Lambdas</Breadcrumb>.
  </APIField>
  <APIField name="Enable debug logging" optional defaults="false">
    Creates Event Log entries that help you debug integration errors. To read the entries, navigate to <Breadcrumb>System -> Event Log</Breadcrumb>.
  </APIField>
</APIBlock>
