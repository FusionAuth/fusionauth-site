The [[Device Authorization Grant]] logs users in on devices with no browser or keyboard, such as a TV. The device shows a short code. The user enters the code on a phone or a computer and logs in there. The device then gets the tokens. The screenshots come from the [Device Grant example](https://github.com/FusionAuth/fusionauth-example-device-grant), which also works as a code reference.

## Configure the Application

On the <Breadcrumb>OAuth</Breadcrumb> tab of the Application, enable `Device` in **Enabled grants** and set **Device Verification URL**. For the other OAuth settings, see [Configure Application OAuth Settings](/docs/authentication/oauth#configure-application-oauth-settings).

Set **Device Verification URL** to a page in your app, so your app can pass the Tenant Id through the flow. The page can host your own form. The page can also redirect to the themed FusionAuth device page at `/oauth2/device`, which requires the `client_id` and `tenantId` query parameters. After the user submits the code on the FusionAuth device page, FusionAuth logs the user in with an Authorization Code grant and redirects to the **`redirect_uri`**. FusionAuth approves the device when your app exchanges the authorization code for tokens.

To change how long the device code and user code stay valid, or how FusionAuth generates user codes, use the <Breadcrumb>Advanced</Breadcrumb> tab of the [Tenant](/docs/concepts/types/tenants#advanced).

## Start the Flow on the Device

The device sends a request to the [Device Authorize endpoint](/docs/apis/oauth/device). The [OpenID Configuration](/docs/apis/oauth/openid-configuration) also lists the endpoint.

To request scopes on the tokens, send **`scope`**. To get a refresh token, add `offline_access`. FusionAuth applies the scopes when the user enters the code, as described in [Pass the User Code to FusionAuth](#pass-the-user-code-to-fusionauth). For scope policies, custom scopes, and consent, see [Scopes](/docs/authorization/oauth-scopes).

![The device prompts the user to connect.](/img/docs/lifecycle/authenticate-users/oauth/oauth-device-connect.png)

The example adds line breaks for readability.

```plaintext title="Example HTTP Request"
POST /oauth2/device_authorize HTTP/1.1
Host: piedpiper.fusionauth.io
Content-Type: application/x-www-form-urlencoded

client_id=06494b74-a796-4723-af44-1bdb96b48875
    &scope=offline_access
```

The response holds the values the device needs for the rest of the flow:

```json title="Example JSON Response"
{
  "device_code": "e6f_lF1rG_yroI0DxeQB5OrLDKU18lrDhFXeQqIKAjg",
  "expires_in": 600,
  "interval": 5,
  "user_code": "SFYNPV",
  "verification_uri": "https://piedpiper.fusionauth.io/oauth2/device",
  "verification_uri_complete": "https://piedpiper.fusionauth.io/oauth2/device?user_code=SFYNPV"
}
```

## Poll the Token Endpoint

The device sends the **`device_code`** to the [Token endpoint](/docs/apis/oauth/token#complete-the-device-authorization-grant-request) every **`interval`** seconds. Until the user approves the device, FusionAuth returns an `authorization_pending` error. The example adds line breaks for readability.

```plaintext title="Example HTTP Request"
POST /oauth2/token HTTP/1.1
Host: piedpiper.fusionauth.io
Content-Type: application/x-www-form-urlencoded

client_id=06494b74-a796-4723-af44-1bdb96b48875
    &device_code=e6f_lF1rG_yroI0DxeQB5OrLDKU18lrDhFXeQqIKAjg
    &grant_type=urn%3Aietf%3Aparams%3Aoauth%3Agrant-type%3Adevice_code
```

While the user hasn't approved the device, FusionAuth returns the following error:

```json title="Example Pending JSON Error Response"
{
  "error": "authorization_pending",
  "error_description": "The authorization request is still pending"
}
```

After the device code expires, FusionAuth returns the following error, and the device must start over:

```json title="Example Expired JSON Error Response"
{
  "error": "expired_token",
  "error_description": "The device_code has expired, and the device authorization session has concluded."
}
```

For an unknown device code, FusionAuth returns the following error:

```json title="Example Invalid JSON Error Response"
{
  "error": "invalid_request",
  "error_reason": "invalid_device_code",
  "error_description": "The request has an invalid parameter: device_code"
}
```

## Show the Code to the User

The device shows the **`user_code`** and asks the user to visit the **`verification_uri`**. To save the user from typing the code, the device can show a QR code for the **`verification_uri_complete`**, which fills in the code.

## Pass the User Code to FusionAuth

When your app hosts the code form, validate the code with the [Device Validate endpoint](/docs/apis/oauth/device#device-validate). For a valid code, the endpoint returns a `200` response with no body.

After validating the code, log the user in with the [Authorization Code grant](/docs/authentication/oauth/authorization-code). The Implicit and Password grants also work. Send the code in the **`user_code`** parameter, and FusionAuth approves the device when the login completes. See the [Authorize endpoint](/docs/apis/oauth/authorize) and the [Token endpoint](/docs/apis/oauth/token).

![The device confirms that the user connected.](/img/docs/lifecycle/authenticate-users/oauth/oauth-device-success.png)
