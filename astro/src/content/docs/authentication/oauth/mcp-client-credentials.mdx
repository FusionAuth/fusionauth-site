<PlanBlurb plan="starter" />

The MCP [OAuth Client Credentials extension](https://modelcontextprotocol.io/extensions/auth/oauth-client-credentials) (`io.modelcontextprotocol/oauth-client-credentials`) lets a service call an [[MCP]] server with no user present, such as a scheduled job or a CI pipeline. FusionAuth supports the extension through the [Client Credentials grant](/docs/authentication/oauth/client-credentials) between two [[Entity::Entities]]. The MCP server is the target Entity, and each MCP client is a recipient Entity with a Grant to the MCP server.

<Aside type="caution" title="FusionAuth supports client secrets only">
The extension allows two ways to authenticate: a client secret, or a JWT signed with the client's private key (`private_key_jwt`). FusionAuth supports only the client secret. In the MCP TypeScript SDK, use `ClientCredentialsProvider`, not `PrivateKeyJwtProvider`.
</Aside>

## Prerequisites

* FusionAuth with a Starter, Essentials, or Enterprise license. Entities require a paid plan.
* A FusionAuth instance that MCP clients can reach over HTTPS, such as `https://auth.example.com`. The MCP TypeScript SDK refuses to send credentials to a token endpoint that doesn't use HTTPS.
* An MCP server that validates FusionAuth access tokens, such as `https://mcp.example.com/mcp`. To build one, see [Control MCP Server Access](/docs/authorization/mcp-server-access).

## How The Connection Works

When an MCP client connects to the MCP server, the client:

1. Calls the MCP server, gets a `401`, and reads the server's protected resource metadata to find FusionAuth.
1. Reads the FusionAuth discovery document to find the token endpoint.
1. Sends the client Id and client secret of the recipient Entity to the token endpoint, with the `target-entity` scope from the server's metadata.
1. Receives an access token whose **`aud`** claim contains the Id of the MCP server Entity, and sends the token on every MCP request.

```mermaid title="An MCP client gets an access token from FusionAuth with the Client Credentials grant, then calls the MCP server."
sequenceDiagram
    participant Client as MCP Client
    participant FusionAuth
    participant Server as MCP Server
    Client ->> Server : MCP request without a token
    Server -->> Client : 401 with the protected resource metadata URL
    Client ->> FusionAuth : Read the discovery document
    Client ->> FusionAuth : POST /oauth2/token with grant_type=client_credentials
    FusionAuth -->> Client : Access token for the MCP server Entity
    Client ->> Server : MCP request with the access token
```

FusionAuth sets **`aud`** from the `target-entity` scope. FusionAuth ignores the `resource` parameter that MCP clients send with this grant, so the token doesn't contain the MCP server URL. FusionAuth also drops any requested scope that doesn't start with `target-entity:`. A token requested with only other scopes has no **`aud`** or **`permissions`** claim, and the MCP server must reject the token.

## Configure FusionAuth

<Steps>

1. Find the Id of the Tenant for your Entities. Navigate to <Breadcrumb>Tenants</Breadcrumb> and copy the **Id** of the Tenant. This guide uses `<tenantId>` for that value.

1. Set the Tenant's **Issuer** to the URL MCP clients use to find FusionAuth. Edit the Tenant, and on the <Breadcrumb>General</Breadcrumb> tab, set **Issuer** to `https://auth.example.com/<tenantId>`. FusionAuth serves the Tenant's discovery document at `/.well-known/openid-configuration/<tenantId>`, and MCP clients look there for an [[authorization server]] URL with a path.

   <Aside type="caution">
   Changing the Issuer changes the **`iss`** claim of every token the Tenant issues. Applications that validate **`iss`** against the old value reject new tokens until you update the applications.
   </Aside>

1. Create an Entity Type for MCP servers. Navigate to <Breadcrumb>Entity Management -> Entity Types</Breadcrumb> and click <Breadcrumb>Add</Breadcrumb>. Add a permission for each kind of access your MCP server checks, such as `read` and `write`.

1. Create an Entity for the MCP server with the new Entity Type. Navigate to <Breadcrumb>Entity Management -> Entities</Breadcrumb> and click <IconButton icon="add" />. Copy the **Id** of the Entity. This guide uses `<mcpServerEntityId>` for that value.

1. Create an Entity for each MCP client. Copy the **Client Id** and **Client secret** of each client Entity, and store the secret in a secrets manager.

1. Grant each client Entity the permissions the client needs on the MCP server Entity. Manage the MCP server Entity, and add a Grant for the client Entity. To add Grants with the API instead, see [Configure Entities](/docs/authentication/oauth/client-credentials#configure-entities).

1. Check that the client Entity can get a token:

   ```shell-session
   curl -u '<clientId>:<clientSecret>' \
     -d 'grant_type=client_credentials' \
     -d 'scope=target-entity:<mcpServerEntityId>' \
     https://auth.example.com/oauth2/token/<tenantId>
   ```

   FusionAuth returns an access token whose **`aud`** claim contains `<mcpServerEntityId>`. The **`permissions`** claim lists the permissions from the Grant.

</Steps>

## Configure The MCP Server

<Steps>

1. Set `authorization_servers` in the MCP server's protected resource metadata to `https://auth.example.com/<tenantId>`.

1. Set `scopes_supported` in the protected resource metadata to `["target-entity:<mcpServerEntityId>"]`. The MCP TypeScript SDK requests the scopes in `scopes_supported` before the scope set on the client. A scope with no permissions after the Entity Id requests every permission from the Grant. A scope that names several permissions fails when the client Entity lacks any one of them.

1. Validate each access token. Check the signature and the expiration, as [Control MCP Server Access](/docs/authorization/mcp-server-access#step-2-implement-token-validation) does with the [JWT Validate API](/docs/apis/jwt/validate-a-jwt). Then check the following claims:

   * **`iss`** is `https://auth.example.com/<tenantId>`.
   * **`aud`** contains `<mcpServerEntityId>`.
   * **`permissions`** contains the permission each tool requires, under the `<mcpServerEntityId>` key, such as `{"<mcpServerEntityId>": ["read"]}`.

   To check the signature locally with the keys at `/.well-known/jwks.json`, sign the tokens with an RSA or EC key. FusionAuth doesn't publish HMAC keys in the JWKS. Set the key in the **Access token signing key** of the Entity Type, or of the Tenant.

1. Advertise the extension in the server's `server/discover` response. The extension recommends this step, but clients connect without the step:

   ```json
   {
     "capabilities": {
       "extensions": {
         "io.modelcontextprotocol/oauth-client-credentials": {}
       }
     }
   }
   ```

</Steps>

## Connect An MCP Client

The MCP TypeScript SDK handles discovery, the token request, and token renewal. Pass the client Id and client secret of the client Entity to `ClientCredentialsProvider`, and set `expectedIssuer` to the Tenant's Issuer:

```typescript
import {
  Client,
  ClientCredentialsProvider,
  StreamableHTTPClientTransport,
} from '@modelcontextprotocol/client';

const provider = new ClientCredentialsProvider({
  clientId: process.env.FUSIONAUTH_CLIENT_ID,
  clientSecret: process.env.FUSIONAUTH_CLIENT_SECRET,
  expectedIssuer: 'https://auth.example.com/<tenantId>',
});

const client = new Client({ name: 'nightly-report', version: '1.0.0' }, { capabilities: {} });
const transport = new StreamableHTTPClientTransport(new URL('https://mcp.example.com/mcp'), {
  authProvider: provider,
});

await client.connect(transport);
const tools = await client.listTools();
console.log(tools.tools.map((tool) => tool.name));
```

`expectedIssuer` stops the client from sending the secret to any other authorization server that the MCP server's metadata names. Run the client. When the connection works, the client prints the names of the MCP server's tools.

A client secret works until you change the secret. To change a secret, see [Client Secret Rotation](/docs/security/tokens-and-keys/client-secret-rotation).

## Troubleshooting

| Problem | Cause and fix |
|---|---|
| The token has no **`aud`** or **`permissions`** claim. | The client requested no `target-entity` scope. Set `scopes_supported` on the MCP server to `["target-entity:<mcpServerEntityId>"]`. |
| FusionAuth returns `invalid_scope` with `does not have a grant to the target entity`. | The client Entity has no Grant on the MCP server Entity. Add the Grant. |
| FusionAuth returns `invalid_scope` with `The permission names [...] are invalid`. | The scope names a permission that the Grant doesn't include. Add the permission to the Grant, or remove the permission from the scope. |
| The SDK throws an issuer mismatch error. | `expectedIssuer`, `authorization_servers`, and the Tenant's **Issuer** must all be the same URL. |
