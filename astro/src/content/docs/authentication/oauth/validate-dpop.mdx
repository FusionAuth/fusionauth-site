FusionAuth checks DPoP proofs on requests to FusionAuth. Your API must check the proof on every request to your API. Without that check, a bound token works like a bearer token at your API. For background, see [Demonstrating Proof-of-Possession (DPoP)](/docs/authentication/oauth/dpop).

Before you start, you need:

* An API that already validates FusionAuth access tokens. See [Validate An Access Token](/docs/authentication/oauth/tokens#validate-an-access-token).
* A client that sends DPoP requests, such as an app set up with [Use DPoP In A Browser App](/docs/authentication/oauth/use-dpop-in-browser).

## Read The Request

A DPoP request carries the access token in the **Authorization** header with the `DPoP` scheme, and a proof in the **DPoP** header:

```properties
Authorization: DPoP eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
DPoP: eyJhbGciOiJFUzI1NiIsInR5cCI6ImRwb3Arand0IiwiandrIjp7...
```

The proof is a JWT. The proof header holds the client's public key:

```json
{
  "typ": "dpop+jwt",
  "alg": "ES256",
  "jwk": {
    "kty": "EC",
    "crv": "P-256",
    "x": "AHTcLNyra6ThKWfhRkn-79L9hzt71LJD9x3hZEHjW5E",
    "y": "Zfy3_hVtvO0V8ZjQVRuZZIfEZ-31fMfwYFueYQLdI2Q"
  }
}
```

The proof payload describes the request:

```json
{
  "jti": "eb228a3e-e95f-4920-a07a-09a791716075",
  "htm": "GET",
  "htu": "https://api.example.com/data",
  "iat": 1788182460,
  "ath": "fUHyO2r2Z3DZ53EsNrWBb0xWXoaNy59IiKCAqksmQEo"
}
```

If your API serves a browser app on another origin, allow the **Authorization** and **DPoP** request headers in your API's CORS configuration.

## Validate The Request

Run the following checks on every request. Reject the request when any check fails. The checks follow [RFC 9449 section 4.3](https://datatracker.ietf.org/doc/html/rfc9449#section-4.3) and section 7.

<Steps>
1. Check that the request has exactly one **DPoP** header and an **Authorization** header with the `DPoP` scheme. If a token with a **`cnf`** claim arrives with the `Bearer` scheme, reject the request, because the client skipped the proof.
1. Decode the proof header. Check that **`typ`** is `dpop+jwt` and **`alg`** is an asymmetric algorithm. Check that **`jwk`** is a public key with no private key members.
1. Verify the proof signature with the key in **`jwk`**.
1. Check that **`htm`** matches the HTTP method of the request.
1. Check that **`htu`** matches the URL of the request, without the query and fragment. Behind a proxy or load balancer, compare against the URL the client called, not the internal URL.
1. Check that **`iat`** is recent. FusionAuth accepts proofs up to 25 seconds old and up to 15 seconds in the future. Use a similar window.
1. Compute the base64url-encoded SHA-256 hash of the access token, without padding. Check that the result matches **`ath`**.
1. Validate the access token as you do for a bearer token: the signature, **`exp`**, **`iss`**, and **`aud`**.
1. Compute the JWK SHA-256 thumbprint of **`jwk`** as defined in [RFC 7638](https://datatracker.ietf.org/doc/html/rfc7638). Check that the thumbprint matches **`cnf.jkt`** in the access token.
1. To reject replayed proofs, check that you haven't seen the **`jti`** value before. Store each **`jti`** for at least the length of your **`iat`** window. FusionAuth doesn't share **`jti`** values with your API, so your API needs a store of its own.
</Steps>

Some OAuth libraries include DPoP support that runs these checks. When you use a library, confirm that the library checks **`ath`** and **`cnf.jkt`**.

## Respond To A Failed Check

When a check fails, return `401 Unauthorized` with a **WWW-Authenticate** header that uses the `DPoP` scheme, as defined in [RFC 9449 section 7.1](https://datatracker.ietf.org/doc/html/rfc9449#section-7.1):

```properties
WWW-Authenticate: DPoP error="invalid_dpop_proof", algs="ES256 PS256"
```

Use `invalid_dpop_proof` when the proof fails a check. Use `invalid_token` when the access token fails a check.

## Require A Nonce

A nonce limits how long a pre-generated proof works. FusionAuth doesn't issue nonces, but your API can, as described in [RFC 9449 section 9](https://datatracker.ietf.org/doc/html/rfc9449#section-9). To require a nonce, return `401 Unauthorized` with a **DPoP-Nonce** header and a `use_dpop_nonce` error. The client retries with the nonce in the **`nonce`** claim of a new proof. The FusionAuth SDK `dpopFetch` function retries automatically.

For a browser app on another origin, add **DPoP-Nonce** to the exposed headers in your API's CORS configuration. Otherwise the browser hides the header from the client.

## Proof Claims

The following table lists the members of the proof header and payload:

| Member | Location | Description |
|---|---|---|
| **`typ`** | Header | Always `dpop+jwt`. |
| **`alg`** | Header | The signature algorithm. FusionAuth accepts `Ed448`, `Ed25519`, `ES256`, `ES384`, `ES512`, `PS256`, `PS384`, `PS512`, `RS256`, `RS384`, and `RS512`. |
| **`jwk`** | Header | The client's public key, as a JWK. |
| **`jti`** | Payload | A unique Id for the proof. |
| **`htm`** | Payload | The HTTP method of the request. |
| **`htu`** | Payload | The URL of the request, without the query and fragment. |
| **`iat`** | Payload | The time the client created the proof, in seconds since the epoch. |
| **`ath`** | Payload | The base64url-encoded SHA-256 hash of the access token. Present when the request carries an access token. FusionAuth token requests don't include **`ath`**. |
| **`nonce`** | Payload | The nonce from a **DPoP-Nonce** header. Present only when your API requires a nonce. FusionAuth ignores **`nonce`**. |

## Troubleshooting

The following table lists common failures and the usual fix:

| Symptom | Cause | Fix |
|---|---|---|
| The thumbprint doesn't match **`cnf.jkt`** | The client signed the proof with a different key than the key used at the token request. | Make sure the client keeps one key pair for the life of the tokens. Log in again after the client replaces the key. |
| **`ath`** doesn't match | The hash covers the wrong value, or the encoding is wrong. | Hash the exact access token string from the **Authorization** header. Encode the hash as base64url without padding. |
| **`htu`** doesn't match | Your API compares against an internal URL, or the client signed a URL with a query string. | Compare against the public URL without the query and fragment. |
| **`iat`** is out of range | The client clock and the server clock differ. | Sync the server clock. Allow some skew for client devices. |
| FusionAuth returns `invalid_dpop_proof` | FusionAuth rejected a proof sent to FusionAuth. | Check the error description in the response. See the [OAuth Error API](/docs/apis/oauth/oauth-error). |
