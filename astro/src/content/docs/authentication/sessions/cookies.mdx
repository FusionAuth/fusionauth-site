FusionAuth sets cookies in the browser when you use the [[hosted login pages]] or the [hosted backend](/docs/apis/hosted-backend). Some APIs, such as the [[Login API]], also set cookies. The API documentation lists those cookies.

## Domains

FusionAuth sets every cookie on the host that serves FusionAuth. When FusionAuth serves `auth.example.com`, FusionAuth sets cookies for `auth.example.com` and never for `.example.com`. To change the host, put FusionAuth behind a proxy. For more information, see [Proxy FusionAuth](/docs/deploy/production/proxy-setup).

Most FusionAuth cookies use a [SameSite](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Set-Cookie#samesitesamesite-value) value of `Strict` or `Lax`, to protect against [cross-site request forgery](https://owasp.org/www-community/attacks/csrf). The browser leaves those cookies off cross-site requests, except for top-level navigation. A FusionAuth page in an iframe on another site therefore can't read the cookies. FusionAuth marks cookies `Secure` only when FusionAuth serves the page over HTTPS.
