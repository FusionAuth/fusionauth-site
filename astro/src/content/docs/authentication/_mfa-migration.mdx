FusionAuth can import users with authenticator, email, and SMS methods. Set the **`twoFactor`** fields on each user in a request to the [Import Users API](/docs/apis/users/import) for a bulk migration, or the [User API](/docs/apis/users) for a slow migration. The following example adds two email methods:

```json title="The twoFactor object for a user with two email methods"
"twoFactor": {
  "methods": [{
    "method": "email",
    "email": "dinesh@aol.com"
  },
  {
    "method": "email",
    "email": "dinesh@gmail.com"
  }]
}
```

For an authenticator method, include the base64-encoded **`secret`** from the old system, so the user's authenticator app keeps working. The Import Users API also accepts the user's existing **`recoveryCodes`**.

When the old system uses a message-based method that FusionAuth doesn't support, such as push notifications, a [Generic Messenger](/docs/messengers/generic-messenger) may fit. The Generic Messenger sends SMS method codes to a service you run. For any other method, open a [GitHub issue](https://github.com/FusionAuth/fusionauth-issues/issues) that describes your use case.
