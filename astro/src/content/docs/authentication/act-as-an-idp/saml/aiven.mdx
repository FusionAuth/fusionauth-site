Aiven is a cloud data platform. Aiven supports single sign-on with SAML v2 identity providers. With FusionAuth as the identity provider, users log in to Aiven with their FusionAuth accounts. For the general steps for any external application, see [Add Login to an External App](/docs/authentication/act-as-an-idp/add-login-to-external-app).

## Before You Begin

You need:

* An Aiven organization, an Aiven user with the `role:organization:admin` permission, and a verified domain in the organization.
* Admin access to FusionAuth.
* A FusionAuth URL that your users' browsers can reach.
* A test user in the [[Tenant]] you plan to use.
* `bash`, `openssl`, `jq`, and `curl` on the computer where you create the certificate.

## Start Adding FusionAuth in Aiven

Aiven gives you the URLs that FusionAuth needs. To get the URLs:

<Steps>

1. In the [Aiven Console](https://console.aiven.io/), open your organization and click <Breadcrumb>Admin -> Identity providers</Breadcrumb>.
1. Click <Breadcrumb>Add identity provider</Breadcrumb>.
1. Select `FusionAuth` and enter a name, such as `FusionAuth`.
1. Select the verified domain to link to the identity provider.
1. Copy the **Metadata URL** and the **ACS URL**. Leave the Aiven page open.

</Steps>

## Create a Signing Certificate

Aiven doesn't accept the X.509 version 2 certificates that [[Key Master]] generates. Create an X.509 v3 certificate outside FusionAuth, and import the certificate into Key Master with the certificate's private key. A script does both. The script calls the [Keys API](/docs/apis/keys/import-a-key), so the script needs an API key first.

<Steps>

1. In FusionAuth, navigate to <Breadcrumb>Settings -> API Keys</Breadcrumb> and click <IconButton icon="add" />.
1. Set **Name** to `Certificate generator`.
1. In the **Endpoints** list, find `/api/key/import` and enable <Breadcrumb>POST</Breadcrumb>.

   <Screenshot id="authenticate-aiven-api-key-add" height={500} url="/admin/api-key/add" alt="The Add API Key form, with POST enabled for the key import endpoint." />

1. Click <IconButton icon="save" />.
1. On the <Breadcrumb>API Keys</Breadcrumb> page, click the value in the **Key** column of the new API key, and copy the value.
1. Save the following script as `generate-certificate`:

   <ExtractedCode lang="shell" src="example-scripts/v3-certificate/generate-certificate" />

1. Run the script:

   ```shell-session
   bash generate-certificate
   ```

1. Enter the FusionAuth URL, the API key, and a name for the key, such as `Aiven key`:

   ```plaintext title="Example answers to the script prompts"
   Your FusionAuth instance URL (with scheme): https://auth.example.com
   API Key with /api/key/import endpoint:      <your API key>
   Name for the generated key:                 Aiven key
   ```

1. Copy the certificate that the script prints, from `-----BEGIN CERTIFICATE-----` through `-----END CERTIFICATE-----`.

</Steps>

The script creates a certificate that is valid for 10 years. When you finish, delete the `Certificate generator` API key.

## Create the Application

Aiven needs its own [[Application]] in FusionAuth. To create the Application:

<Steps>

1. Navigate to <Breadcrumb>Applications</Breadcrumb> and click <IconButton icon="add" />.
1. Set **Name** to `Aiven`, and select the **Tenant** that holds your users.
1. Select the <Breadcrumb>SAML</Breadcrumb> tab and enable **Enable SAML v2**.
1. Set **Issuer** to the **Metadata URL** from Aiven.
1. Add the **ACS URL** from Aiven to **Authorized redirect URLs**.
1. In the <Breadcrumb>Authentication response</Breadcrumb> section, set **Signing key** to the key that the script created, such as `Aiven key`.
1. Click <IconButton icon="save" />.
1. On the <Breadcrumb>Applications</Breadcrumb> page, open the action menu for the Application and select <Breadcrumb>View</Breadcrumb>.
1. In the **SAML v2 Integration details** section, copy the **Entity Id** and the **Login URL**.

</Steps>

## Finish the Configuration in Aiven

To connect Aiven to FusionAuth:

<Steps>

1. On the Aiven page, set **IDP URL** to the **Login URL** from FusionAuth.
1. Set **Entity ID** to the **Entity Id** from FusionAuth.
1. Paste the certificate from the script into **Certificate**, and click <Breadcrumb>Next</Breadcrumb>.
1. Choose the security options, and click <Breadcrumb>Next</Breadcrumb>. For a description of each option, see [Add SAML identity providers](https://aiven.io/docs/platform/howto/saml/add-identity-providers) in the Aiven documentation.
1. When all users who sign up with FusionAuth belong in one Aiven group, select the group.
1. Click <Breadcrumb>Finish</Breadcrumb>.
1. Copy the **Signup URL**. Users without an Aiven account use the **Signup URL** to create an Aiven account that logs in with FusionAuth. Users with an Aiven account use the **User account link URL** instead.

</Steps>

## Give Users Access

Any user in the Tenant can log in to Aiven by default. To limit login to users with a [[Registration]] for the Application, enable **Require registration to complete OAuth authorization** on the <Breadcrumb>OAuth</Breadcrumb> tab of the Application. The setting applies to SAML v2 logins too. For more information, see [Registrations](/docs/concepts/types/registrations).

## Confirm the Login

To confirm that login works:

<Steps>

1. Open the **Signup URL** in a private browser window.
1. Start the login with FusionAuth from the Aiven page.
1. Confirm that the browser shows the FusionAuth login page.
1. Log in as the test user.
1. Confirm that the browser returns to the Aiven Console and that the test user is logged in.

</Steps>

When the login fails, enable **Enable debug logging** on the <Breadcrumb>SAML</Breadcrumb> tab of the Application and try again. Read the details in <Breadcrumb>System -> Event Log</Breadcrumb>. Turn off debug logging when you finish.
