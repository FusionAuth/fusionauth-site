FusionAuth searches Users and Entities with either the `database` search engine or the `elasticsearch` search engine. The `elasticsearch` search engine works with OpenSearch and Elasticsearch. You can switch engines at any time. For the differences between the engines, see [Search Engines](/docs/users/search).

Every switch takes a restart, so plan for a short outage. For instructions on stopping and starting FusionAuth, see [Start and Stop a Production Instance](/docs/deploy/production/start-and-stop).

The steps on this page set configuration in `fusionauth.properties` or in environment variables. For every search setting, see the [Configuration Reference](/docs/deploy/production/configuration).

## Switch to the Elasticsearch Search Engine

Before you start, install OpenSearch or Elasticsearch, and confirm that FusionAuth can reach the search engine. For instructions, see [Install a Search Engine](/docs/deploy/production/install/search).

Check that each field in your **`data`** objects holds one data type across all objects. The Elasticsearch search engine skips objects with mismatched types when the engine indexes the objects. For more information, see [Data Field Types](/docs/users/search#data-field-types).

<Steps>
1. Stop FusionAuth.

1. Set the search engine type and the search engine URL:

   <Tabs>
   <TabItem label="Configuration file">
   ```properties
   search.type=elasticsearch
   search.servers=http://localhost:9200
   ```
   </TabItem>
   <TabItem label="Environment variables">
   ```shell
   SEARCH_TYPE=elasticsearch
   SEARCH_SERVERS=http://localhost:9200
   ```
   </TabItem>
   </Tabs>

1. Start FusionAuth.

1. In the Admin UI, navigate to <Breadcrumb>System -> About</Breadcrumb>. The **Search** row shows `OpenSearch` or `Elasticsearch`, and the version.

1. Navigate to <Breadcrumb>System -> Reindex</Breadcrumb>, set **Select an index** to `User`, type `REINDEX` in **Confirm**, and click <Breadcrumb>Save</Breadcrumb>. When you use Entities, repeat with `Entity`. The new index is empty, so searches miss existing Users and Entities until the reindex finishes. A reindex takes longer with more Users and more custom data. For more information, see [Reindex](/docs/users/search#reindex).

1. Navigate to <Breadcrumb>Users</Breadcrumb>, and search for a User by email address. The <Breadcrumb>Advanced</Breadcrumb> search link appears below the search field.
</Steps>

## Switch to the Database Search Engine

<Steps>
1. Stop FusionAuth.

1. Set the search engine type to `database`:

   <Tabs>
   <TabItem label="Configuration file">
   ```properties
   search.type=database
   ```
   </TabItem>
   <TabItem label="Environment variables">
   ```shell
   SEARCH_TYPE=database
   ```
   </TabItem>
   </Tabs>

   FusionAuth ignores `search.servers` with the database search engine, so you can leave the setting in place.

1. Start FusionAuth.

1. In the Admin UI, navigate to <Breadcrumb>System -> About</Breadcrumb>. The **Search** row shows `Database`.

1. Navigate to <Breadcrumb>Users</Breadcrumb>, and search for a User by email address.
</Steps>

FusionAuth stops sending data to OpenSearch or Elasticsearch, and you can shut the search engine down. After the switch, requests with the **`query`** parameter return a `400` response, and FusionAuth doesn't support SCIM filters. For the full list of features that need the Elasticsearch search engine, see [Search Engines](/docs/users/search#compare-the-search-engines).
