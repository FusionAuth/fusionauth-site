FusionAuth `1.59.0` and later can gate a user's account until the user verifies a phone number. A gated user can start the login process. The user can't finish login until the user proves ownership of the phone number from registration.

To turn on phone verification gating:

1. Configure a [[Messenger::messenger]].
1. Select the messenger in the Tenant.
1. Turn on phone verification gating in the Tenant.
1. When you want to change the verification message, customize the phone verification template.
1. Turn on [[self-service registration]] in the Application.
1. Add a [[redirect URL]] to the Application.
1. Test the gate.

## Prerequisites

<PlanBlurb plan="starter" />

You need the following:

* FusionAuth `1.59.0` or later. To install FusionAuth, see [Install](/docs/get-started/install). To update an instance, see [Update FusionAuth](/docs/update).
* A paid plan and a license. To buy a plan, see [Pricing](/pricing). To activate an instance, see [Licensing](/docs/concepts/plans-and-limits/licensing).
* A Twilio account. This guide uses a Twilio Messenger. To use another SMS provider, create a [Generic Messenger](/docs/messengers/generic-messenger) instead.

## Gating, Verification, and Pre-Verification

Phone verification is available on every plan. Gating requires a paid plan.

Phone verification updates **`verified`** and **`verifiedReason`** on the user's phone number identity. Your application code can check these fields and block an unverified user.

With gating, FusionAuth blocks the unverified user instead. The [[hosted login pages]] stop the user after login, and FusionAuth issues no JWT until the user verifies the phone number. Gating applies after FusionAuth creates the user.

[Pre-verification](/docs/users/verify/identity-pre-verification-using-phone) requires users to verify a phone number before FusionAuth creates the user.

## Configure the Messenger

This guide uses the Admin UI. You can also configure everything with the API or with [[Kickstart]].

Log in to the Admin UI. Navigate to <Breadcrumb>Settings -> Messengers</Breadcrumb>, click <Breadcrumb>Add Twilio messenger</Breadcrumb>, and enter your Twilio account details. For more information, see [Twilio Messenger](/docs/messengers/twilio-messenger).

## Select the Messenger in the Tenant

Navigate to <Breadcrumb>Tenants -> Your Tenant</Breadcrumb> and select the <Breadcrumb>Identities</Breadcrumb> tab. In the <Breadcrumb>Messenger settings</Breadcrumb> section, select the messenger you created.

<Screenshot id="manage-verification-tenant-messenger" url="/admin/tenant/edit/00000000-0000-0000-0000-f40000000001#identities" showHash height={800} alt="The tenant Identities tab with a messenger selected." />

## Turn On Phone Verification Gating

On the same <Breadcrumb>Identities</Breadcrumb> tab, configure the phone settings:

1. Turn on **Verify identity**.
1. Set **Verification template**. The default `Phone Verification` template works for this guide.
1. Set **Verification strategy**. `ClickableLink` sends an SMS message with a link that verifies the phone number. `FormField` sends a code that the user enters in FusionAuth. This guide uses the default, `FormField`.
1. Set **Unverified behavior** to `Gated`.

The phone settings look like the following:

<Screenshot id="manage-verification-tenant-phone-settings" url="/admin/tenant/edit/00000000-0000-0000-0000-f40000000001#identities" showHash height={1300} alt="The tenant Identities tab with gated phone verification." />

Save the Tenant.

## Customize the Phone Verification Template

When you want to change the verification message, navigate to <Breadcrumb>Customizations -> Message Templates</Breadcrumb>. Click <IconButton icon="edit" /> on the `Phone Verification` template.

Change the text template, then save the template. You can also localize the message. For more information, see [Message Templates](/docs/messengers/message-templates).

## Configure the Application

Navigate to <Breadcrumb>Applications</Breadcrumb> and click <IconButton icon="edit" /> on your Application.

On the <Breadcrumb>Registration</Breadcrumb> tab, go to the <Breadcrumb>Self service registration</Breadcrumb> section. Turn on self-service registration, and set **Login type** to `Phone`. Choose the fields that the registration form displays and requires.

Self-service registration is the simplest way to create a user with an unverified phone number. Other ways of creating users also work with the gate.

<Screenshot id="manage-verification-application-self-service-phone" url="/admin/application/edit?applicationId=00000000-0000-0000-0000-f40000000002&tenantId=00000000-0000-0000-0000-f40000000001#registration" crop="#screenshot-band" cropPadding={0} alt="The application Registration tab with self-service registration enabled for phone numbers.">
  <Highlight selector="#selfRegistrationType-form-row" />
  <Highlight selector="[data-hl='login-type-phone']" />
</Screenshot>

On the <Breadcrumb>OAuth</Breadcrumb> tab, turn on the `Authorization Code` grant. Add a URL to **Authorized redirect URLs**. Any valid URL works for this guide. In production, the code at the redirect URL must exchange the authorization code for a token.

Save the Application. FusionAuth returns to the list of Applications.

Click <IconButton icon="view" /> on your Application to see the Application details.

<Screenshot id="manage-verification-application-details" url="/admin/application/" height={1700} alt="The application details dialog with the login and registration URLs highlighted.">
  <Highlight selector="[data-hl='verification-urls']" />
</Screenshot>

Copy the **Registration URL** and the **OAuth IdP login URL**. The Registration URL looks like `https://local.fusionauth.io/oauth2/register?client_id=85a03867-dccf-4882-adde-1a79aeec50df&response_type=code&redirect_uri=http%3A%2F%2Flocalhost%3A3000%2Foauth-redirect`.

## Test the Gate

Register in a different browser or a private window, so your Admin UI session doesn't interfere with the registration:

1. Open the Registration URL. Fill out the form with a valid phone number. After registration, FusionAuth sends a message that asks you to verify the phone number. The browser shows the phone verification gate page:

    <Screenshot id="manage-verification-phone-gate" url="/oauth2/authorize?client_id=00000000-0000-0000-0000-f40000000002&redirect_uri=https%3A%2F%2Fexample.com&response_type=code&scope=openid" crop=".bg-panel-bg" alt="The phone verification gate page for the form field strategy." />

1. Open a different browser, not a new window of the same browser. Open the OAuth IdP login URL, and log in with the phone number and password of the new user. FusionAuth shows the same phone verification gate page.
1. In the Admin UI, open the new user. A question mark next to the phone number shows that the phone number isn't verified.

    <Screenshot id="manage-verification-phone-unverified-user" url="/admin/user/manage/00000000-0000-0000-0000-f40000000042" width={1600} alt="The user details page with an unverified phone number.">
      <Highlight selector="[data-hl='identity']" />
    </Screenshot>

1. On the gate page, enter the code from the message. FusionAuth finishes the login and redirects to the redirect URL.

FusionAuth issues no JWT until the user verifies the phone number, whichever API or hosted login page the user logs in with. Until then, the user sees the gate page at every login. When your application logs users in with the [Login API](/docs/apis/login), the response status code shows that the user hasn't verified the phone number.

To make the gate page match your application, customize your theme. For more information, see [Themes](/docs/theme).

## The User Object

FusionAuth updates the phone number identity of the User during verification.

When phone verification is off at user creation, **`verified`** is `false` and **`verifiedReason`** is `Disabled`:

<JSON title="User Object With Phone Verification Turned Off Initially JSON" src="registration-gate/user-phone-verification-turned-off-initially.json" />

When phone verification is on at user creation, **`verified`** is `false` and **`verifiedReason`** is `Pending`:

<JSON title="User Object With Phone Verification Turned On Initially JSON" src="registration-gate/user-phone-verification-turned-on-initially.json" />

After the user verifies the phone number, **`verified`** is `true` and **`verifiedReason`** is `Completed`.

The [Import Users API](/docs/apis/users/import) keeps the imported verification values, whatever the verification and gate settings.

## Troubleshooting Phone Verification

### Verification Links and Codes Don't Work

When a link or code from the verification message has expired, check the external identifier durations. Navigate to <Breadcrumb>Tenants -> Your Tenant -> Advanced</Breadcrumb>. In the <Breadcrumb>External identifier durations</Breadcrumb> section, change **Phone verification**. FusionAuth sets a default duration.
