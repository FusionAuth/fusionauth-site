<DeprecatedSince since="1.59.0">FusionAuth deprecated registration verification in `1.59.0`, and will remove registration verification in a future version.</DeprecatedSince>

FusionAuth `1.27.0` and later can gate a user's access to an Application until the user verifies the registration for that Application. A gated user can log in. The user can't continue into the Application until the user clicks the link or enters the code from the registration verification email.

## Choose a Gate

Most applications need only email verification gating. Email verification confirms that the user owns the email address, once per Tenant. For more information, see [Gate Users Until They Verify Their Email](/docs/users/verify/gate-accounts-until-user-email-verified).

Registration verification confirms that the user meant to join one Application. For example, a company named Pied Piper runs two Applications, PiperChat and Not-Hotdog, in one Tenant. The user `jared@piedpiper.com` registers for PiperChat. When the same login later works for Not-Hotdog, the user may be alarmed, especially when the user doesn't know that one company runs both Applications. Registration verification makes the user verify each registration separately. Completing the verification also proves that the user owns the email address.

```mermaid title="One user, jared@piedpiper.com, registered to two Pied Piper applications."
flowchart BT
    User["jared@piedpiper.com"] --> PiperChat["PiperChat"]
    User --> NotHotdog["Not-Hotdog"]
```

To turn on registration verification gating:

1. Configure the Tenant's email server.
1. Turn on registration verification gating in the Application.
1. Turn on [[self-service registration]] in the Application.
1. Add a [[redirect URL]] to the Application.
1. When you want to change the verification email, customize the registration verification template. FusionAuth ships with a default template.
1. Test the gate.

## Prerequisites

<PlanBlurb plan="starter" />

You need the following:

* FusionAuth `1.27.0` or later. To install FusionAuth, see [Install](/docs/get-started/install). To update an instance, see [Update FusionAuth](/docs/update).
* A paid plan and a license. To buy a plan, see [Pricing](/pricing). To activate an instance, see [Licensing](/docs/concepts/plans-and-limits/licensing).
* An SMTP server. To test locally, use a mock email server such as [MailCatcher](https://mailcatcher.me/).

## Gating and Verification

Email verification and registration verification are available on every plan. Gating requires a paid plan.

Registration verification updates **`verified`** on the user's registration. Your application code can check the field and block an unverified user.

With gating, FusionAuth blocks the unverified user instead. The [[hosted login pages]] stop the user after login, and FusionAuth issues no JWT until the user verifies the registration.

## Configure the Tenant Email Server

This guide uses the Admin UI. You can also configure everything with the API or with [[Kickstart]].

Log in to the Admin UI. Navigate to <Breadcrumb>Tenants -> Your Tenant</Breadcrumb> and select the <Breadcrumb>Email</Breadcrumb> tab. In the <Breadcrumb>SMTP settings</Breadcrumb> section, enter your SMTP server details.

<Screenshot id="tenant-smtp-settings" url="/admin/tenant/edit/30663132-6464-6665-3032-326466613934#email" showHash alt="The tenant Email tab with the SMTP settings." />

Send a test email, and confirm that the email arrives. When the email doesn't arrive, see [Troubleshooting Email](/docs/deploy/troubleshoot/troubleshooting#troubleshooting-email).

Save the Tenant.

## Turn On Registration Verification Gating

Navigate to <Breadcrumb>Applications -> Your Application</Breadcrumb> and select the <Breadcrumb>Registration</Breadcrumb> tab. In the <Breadcrumb>Registration verification settings</Breadcrumb> section, configure the following:

1. Turn on **Verify registrations**.
1. Set the verification template. The default `Registration verification` template works for this guide.
1. Set **Verification strategy**. `ClickableLink` sends an email with a link that verifies the user's email address and the user's intent to register for the Application. `FormField` sends a code that the user enters in FusionAuth. This guide uses `ClickableLink`.
1. Set **Unverified behavior** to `Gated`.

The registration verification settings look like the following:

<Screenshot id="manage-verification-application-registration-settings" url="/admin/application/edit?applicationId=00000000-0000-0000-0000-f40000000002&tenantId=00000000-0000-0000-0000-f40000000001#registration" showHash height={1350} alt="The application Registration tab with gated registration verification." />

## Configure the Application

On the same <Breadcrumb>Registration</Breadcrumb> tab, turn on self-service registration. Choose the fields that the registration form displays and requires.

Self-service registration is the simplest way to create a user with an unverified registration. Other ways of creating registrations also work with the gate.

<Screenshot id="manage-verification-application-self-service" url="/admin/application/edit?applicationId=00000000-0000-0000-0000-f40000000002&tenantId=00000000-0000-0000-0000-f40000000001#registration" crop="#screenshot-band" cropPadding={0} alt="The application Registration tab with self-service registration enabled.">
  <Highlight selector="#selfRegistrationType-form-row" />
</Screenshot>

On the <Breadcrumb>OAuth</Breadcrumb> tab, turn on the `Authorization Code` grant. Add a URL to **Authorized redirect URLs**. Any valid URL works for this guide. In production, the code at the redirect URL must exchange the authorization code for a token.

Save the Application. FusionAuth returns to the list of Applications.

Click <IconButton icon="view" /> on your Application to see the Application details.

<Screenshot id="manage-verification-application-details" url="/admin/application/" height={1700} alt="The application details dialog with the login and registration URLs highlighted.">
  <Highlight selector="[data-hl='verification-urls']" />
</Screenshot>

Copy the **Registration URL** and the **OAuth IdP login URL**. The Registration URL looks like `https://local.fusionauth.io/oauth2/register?client_id=85a03867-dccf-4882-adde-1a79aeec50df&response_type=code&redirect_uri=http%3A%2F%2Flocalhost%3A3000%2Foauth-redirect`.

## Customize the Registration Verification Template

When you want to change the verification email, navigate to <Breadcrumb>Customizations -> Email Templates</Breadcrumb>. Click <IconButton icon="edit" /> on the `Registration Verification` template.

Change the HTML and text templates, then save the template. You can also localize the email. For more information, see [Email Templates](/docs/email/email-templates).

## Test the Gate

Register in a different browser or a private window, so your Admin UI session doesn't interfere with the registration:

1. Open the Registration URL. Fill out the form with a valid email address. After registration, FusionAuth sends an email that asks you to verify the registration. The following screenshot shows the email in MailCatcher:

    ![The registration verification email in MailCatcher.](/img/docs/lifecycle/manage-users/verification/verification-registration-email-mailcatcher.png)

    The browser shows the registration verification gate page:

    <Screenshot id="manage-verification-registration-gate-link" url="/oauth2/authorize?client_id=00000000-0000-0000-0000-f40000000002&redirect_uri=https%3A%2F%2Fexample.com&response_type=code&scope=openid" height={600} alt="The registration verification gate page for the clickable link strategy." />

1. Open a different browser, not a new window of the same browser. Open the OAuth IdP login URL, and log in with the email address and password of the new user. FusionAuth shows the same registration verification gate page.
1. In the Admin UI, open the new user and select the <Breadcrumb>Source</Breadcrumb> tab. The registration shows **`verified`** as `false`.

    <Screenshot id="manage-verification-registration-unverified-user" fullPage={true} url="/admin/user/manage/00000000-0000-0000-0000-f40000000043#raw-user" showHash width={1600} alt="The user Source tab with the unverified registration highlighted.">
      <Highlight selector="[data-hl='registration-verified']" />
    </Screenshot>

1. Click the link in the email. Log in again, and FusionAuth redirects to the redirect URL.

FusionAuth issues no JWT until the user verifies the registration, whichever API or hosted login page the user logs in with. Until then, the user sees the gate page at every login. When your application logs users in with the [Login API](/docs/apis/login), the response status code shows that the user hasn't verified the registration.

When **Verification strategy** is `FormField`, the gate page asks for the code from the email instead:

<Screenshot id="manage-verification-registration-gate-code" url="/oauth2/authorize?client_id=00000000-0000-0000-0000-f40000000003&redirect_uri=https%3A%2F%2Fexample.com&response_type=code&scope=openid" height={600} alt="The registration verification gate page for the form field strategy." />

To make the gate page match your application, customize your theme. For more information, see [Themes](/docs/theme).

## The User Object

FusionAuth updates the registration of the User during verification.

When registration verification is off at user creation, **`verified`** on the registration is `true`. FusionAuth treats every registration as verified while registration verification is off:

<JSON title="Registrations Array Showing Verification Set To true/off JSON" src="registration-gate/user-registration-verification-turned-off-initially.json" />

When registration verification is on at user creation, **`verified`** on the registration is `false`:

<JSON title="Registrations Array Showing Verification Set To false/on JSON" src="registration-gate/user-registration-verification-turned-on-initially.json" />

After the user verifies the registration, **`verified`** is `true`.

The [Import Users API](/docs/apis/users/import) keeps the imported verification values, whatever the verification and gate settings.
