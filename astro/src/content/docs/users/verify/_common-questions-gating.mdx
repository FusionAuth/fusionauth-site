### Do Existing Users Get Messages When I Enable a Gate?

No. Enabling a gate sends no messages. Instead, an existing user with an unverified identity must verify the identity at their next login. An identity is unverified when the identity has `verified: false` and `verifiedReason: "Pending"`. During login, the user clicks a link, and FusionAuth then sends the verification message.

When you use Elasticsearch for search, you can find the users that a gate will affect. Navigate to <Breadcrumb>Users</Breadcrumb> and search for `verified: false`. The search matches users with an unverified email address and users with an unverified registration.

<Aside type="note">
User search doesn't index the verification status of phone numbers. You can't search for users with an unverified phone number.
</Aside>

### How Do I Mark an Imported User as Verified?

To verify the email address or phone number of one user in the Admin UI:

1. Navigate to <Breadcrumb>Users</Breadcrumb> and open the details page of the user.
1. Click the down arrow next to <Breadcrumb>Edit user</Breadcrumb>, then select <Breadcrumb>Verify identity</Breadcrumb>.
1. Select the identity and click <Breadcrumb>Confirm</Breadcrumb>.

The Admin UI can't mark a registration as verified. To verify a registration, or to verify many users at once, use the API:

1. Get a verification Id from the [Resend Verification API](/docs/apis/users/resend-verification) for an email address, or from the [Resend Registration Verification API](/docs/apis/registrations/resend-a-user-registration-verification-email) for a registration. Set **`sendVerifyEmail`** or **`sendVerifyRegistrationEmail`** to `false`, so FusionAuth returns the Id without sending an email.
1. Send the verification Id to the [Verify Email API](/docs/apis/users/verify-email) or the [Verify Registration API](/docs/apis/registrations/verify-a-user-registration).

To skip this step in future imports, set **`users[x].verified`** and **`users[x].registrations[x].verified`** in the [Import Users API](/docs/apis/users/import).

### What Happens When I Enable Both Email and Registration Verification?

Email verification confirms that the user owns an email address, once per Tenant. Registration verification confirms that the user opted in to one Application. For example, nine Applications in a Tenant might require only email verification, while a tenth Application also requires registration verification.

When a new user signs up for the tenth Application, FusionAuth sends one email: the registration verification email. Completing registration verification also verifies the email address. When an existing user registers for the tenth Application, FusionAuth sends a registration verification email, even if the user already verified their email address.

When you turn off **Allow implicit verification** in the Tenant, registration verification doesn't verify the email address. Users then verify the registration and the email address separately. The setting is on the <Breadcrumb>Identities</Breadcrumb> tab of the Tenant. See [Identity Verification Settings](/docs/concepts/types/tenants#identity-verification-settings).
