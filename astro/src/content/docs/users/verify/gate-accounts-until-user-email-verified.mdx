FusionAuth `1.27.0` and later can gate a user's account until the user verifies an email address. A gated user can start the login process. The user can't finish login until the user proves ownership of the email address from registration.

To turn on email verification gating:

1. Configure the Tenant's email server.
1. Turn on email verification gating in the Tenant.
1. When you want to change the verification email, customize the email verification template.
1. Turn on [[self-service registration]] in the Application.
1. Add a [[redirect URL]] to the Application.
1. Test the gate.

## Prerequisites

<PlanBlurb plan="starter" />

You need the following:

* FusionAuth `1.27.0` or later. To install FusionAuth, see [Install](/docs/get-started/install). To update an instance, see [Update FusionAuth](/docs/update).
* A paid plan and a license. To buy a plan, see [Pricing](/pricing). To activate an instance, see [Licensing](/docs/concepts/plans-and-limits/licensing).
* An SMTP server. To test locally, use a mock email server such as [MailCatcher](https://mailcatcher.me/).

## Gating, Verification, and Pre-Verification

Email verification and registration verification are available on every plan. Gating requires a paid plan.

Email verification updates **`verified`** and **`verifiedReason`** on the user's email identity. Registration verification updates the same fields on the user's registration. Your application code can check these fields and block an unverified user.

With gating, FusionAuth blocks the unverified user instead. The [[hosted login pages]] stop the user after login, and FusionAuth issues no JWT until the user verifies the email address. Gating applies after FusionAuth creates the user.

[Pre-verification](/docs/users/verify/identity-pre-verification-using-email) requires users to verify an email address before FusionAuth creates the user.

## Configure the Tenant Email Server

This guide uses the Admin UI. You can also configure everything with the API or with [[Kickstart]].

Log in to the Admin UI. Navigate to <Breadcrumb>Tenants -> Your Tenant</Breadcrumb> and select the <Breadcrumb>Email</Breadcrumb> tab. In the <Breadcrumb>SMTP settings</Breadcrumb> section, enter your SMTP server details.

<Screenshot id="tenant-smtp-settings" url="/admin/tenant/edit/30663132-6464-6665-3032-326466613934#email" showHash alt="The tenant Email tab with the SMTP settings." />

Send a test email, and confirm that the email arrives. When the email doesn't arrive, see [Troubleshooting Email](/docs/deploy/troubleshoot/troubleshooting#troubleshooting-email).

Save the Tenant.

## Turn On Email Verification Gating

Navigate to <Breadcrumb>Tenants -> Your Tenant</Breadcrumb> and select the <Breadcrumb>Identities</Breadcrumb> tab. In the <Breadcrumb>Identity verification settings</Breadcrumb> section, configure the email settings:

1. Turn on **Verify identity**.
1. Set **Verification template**. The default `Email verification` template works for this guide.
1. Set **Verification strategy**. `ClickableLink` sends an email with a link that verifies the email address. `FormField` sends a code that the user enters in FusionAuth. This guide uses `ClickableLink`.
1. Set **Unverified behavior** to `Gated`.

The email settings look like the following:

<Screenshot id="manage-verification-tenant-email-settings" url="/admin/tenant/edit/00000000-0000-0000-0000-f40000000001#identities" showHash height={1000} alt="The tenant Identities tab with gated email verification." />

Save the Tenant.

## Customize the Email Verification Template

When you want to change the verification email, navigate to <Breadcrumb>Customizations -> Email Templates</Breadcrumb>. Click <IconButton icon="edit" /> on the `Email Verification` template.

Change the HTML and text templates, then save the template. You can also localize the email. For more information, see [Email Templates](/docs/email/email-templates).

## Configure the Application

Navigate to <Breadcrumb>Applications</Breadcrumb> and click <IconButton icon="edit" /> on your Application.

On the <Breadcrumb>Registration</Breadcrumb> tab, go to the <Breadcrumb>Self service registration</Breadcrumb> section. Turn on self-service registration. Choose the fields that the registration form displays and requires.

Self-service registration is the simplest way to create a user with an unverified email address. Other ways of creating users also work with the gate.

<Screenshot id="manage-verification-application-self-service" url="/admin/application/edit?applicationId=00000000-0000-0000-0000-f40000000002&tenantId=00000000-0000-0000-0000-f40000000001#registration" crop="#screenshot-band" cropPadding={0} alt="The application Registration tab with self-service registration enabled.">
  <Highlight selector="#selfRegistrationType-form-row" />
</Screenshot>

On the <Breadcrumb>OAuth</Breadcrumb> tab, turn on the `Authorization Code` grant. Add a URL to **Authorized redirect URLs**. Any valid URL works for this guide. In production, the code at the redirect URL must exchange the authorization code for a token.

Save the Application. FusionAuth returns to the list of Applications.

Click <IconButton icon="view" /> on your Application to see the Application details.

<Screenshot id="manage-verification-application-details" url="/admin/application/" height={1700} alt="The application details dialog with the login and registration URLs highlighted.">
  <Highlight selector="[data-hl='verification-urls']" />
</Screenshot>

Copy the **Registration URL** and the **OAuth IdP login URL**. The Registration URL looks like `https://local.fusionauth.io/oauth2/register?client_id=85a03867-dccf-4882-adde-1a79aeec50df&response_type=code&redirect_uri=http%3A%2F%2Flocalhost%3A3000%2Foauth-redirect`.

## Test the Gate

Register in a different browser or a private window, so your Admin UI session doesn't interfere with the registration:

1. Open the Registration URL. Fill out the form with a valid email address. After registration, FusionAuth sends an email that asks you to verify the email address. The following screenshot shows the email in MailCatcher:

    ![The verification email in MailCatcher.](/img/docs/lifecycle/manage-users/verification/verification-email-mailcatcher.png)

    The browser shows the email verification gate page:

    <Screenshot id="manage-verification-email-gate-link" url="/oauth2/authorize?client_id=00000000-0000-0000-0000-f40000000002&redirect_uri=https%3A%2F%2Fexample.com&response_type=code&scope=openid" height={600} alt="The email verification gate page for the clickable link strategy." />

1. Open a different browser, not a new window of the same browser. Open the OAuth IdP login URL, and log in with the email address and password of the new user. FusionAuth shows the same email verification gate page.
1. In the Admin UI, open the new user. A question mark next to the email address shows that the email address isn't verified.

    <Screenshot id="manage-verification-email-unverified-user" url="/admin/user/manage/00000000-0000-0000-0000-f40000000041" width={1600} alt="The user details page with an unverified email address.">
      <Highlight selector="[data-hl='identity']" />
    </Screenshot>

1. Click the link in the email. Log in again, and FusionAuth redirects to the redirect URL.

FusionAuth issues no JWT until the user verifies the email address, whichever API or hosted login page the user logs in with. Until then, the user sees the gate page at every login. When your application logs users in with the [Login API](/docs/apis/login), the response status code shows that the user hasn't verified the email address.

When **Verification strategy** is `FormField`, the gate page asks for the code from the email instead:

<Screenshot id="manage-verification-email-gate-code" url="/oauth2/authorize?client_id=00000000-0000-0000-0000-f40000000002&redirect_uri=https%3A%2F%2Fexample.com&response_type=code&scope=openid" height={600} alt="The email verification gate page for the form field strategy." />

To make the gate page match your application, customize your theme. For more information, see [Themes](/docs/theme).

## The User Object

FusionAuth updates the email identity of the User during verification.

When email verification is off at user creation, **`verified`** is `false` and **`verifiedReason`** is `Disabled`:

<JSON title="User Object With Email Verification Turned Off Initially JSON" src="registration-gate/user-email-verification-turned-off-initially.json" />

When email verification is on at user creation, **`verified`** is `false` and **`verifiedReason`** is `Pending`:

<JSON title="User Object With Email Verification Turned On Initially JSON" src="registration-gate/user-email-verification-turned-on-initially.json" />

After the user verifies the email address, **`verified`** is `true` and **`verifiedReason`** is `Completed`. Email verification also sets the User's top-level **`user.verified`** field to `true`. Phone verification doesn't change **`user.verified`**.

The [Import Users API](/docs/apis/users/import) keeps the imported verification values, whatever the verification and gate settings.
