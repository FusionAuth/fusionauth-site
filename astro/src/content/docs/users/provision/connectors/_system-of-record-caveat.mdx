You can use the Connector to authenticate users or to migrate users:

* When the Connector authenticates users, the {props.system_of_record} remains the system of record, which holds the canonical user data.
* When the Connector migrates users, FusionAuth copies each user after the user's first successful login. FusionAuth then becomes the system of record.

For the other differences between the options, see [Connectors](/docs/users/provision/connectors).

When the Connector authenticates users without migrating the users, each login replaces the stored user with the user that the Connector returns. FusionAuth resets the following user attributes at each login:

* Group memberships
* Application registrations
* [[Multi-Factor Authentication::Multi-factor authentication]] methods and recovery codes

For example, when you register a Connector user for an application through the FusionAuth API or the Admin UI, FusionAuth removes the registration at the user's next login.

<Aside type="danger" title="FusionAuth deletes the MFA methods of Connector users at login">
When the Connector doesn't migrate users, FusionAuth doesn't keep the multi-factor authentication methods that users set up in FusionAuth. FusionAuth replaces the methods before the multi-factor authentication check, so the login completes without a challenge. For example, a user who sets up an authenticator app gets no challenge at the next login, and FusionAuth deletes the authenticator app method.

To use FusionAuth multi-factor authentication with Connector users, turn on **Migrate user** in the Connector policy. FusionAuth then keeps the methods and challenges the user at each login.
</Aside>
