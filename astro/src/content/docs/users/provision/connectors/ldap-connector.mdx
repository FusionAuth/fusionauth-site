An [[LDAP]] Connector authenticates users against, or migrates users from, an LDAP server that FusionAuth can reach.

## Configuration

<Screenshot id="migration-ldap-connector-add" url="/admin/connector/add/LDAP" crop="[data-migration-window]" cropPadding={0} chrome={true} alt="The LDAP Connector creation screen." />

### Form Fields

<APIBlock>
  <APIField name="Id" optional>
    An optional UUID. When you omit the Id, FusionAuth generates a unique Id.
  </APIField>
  <APIField name="Name" required>
    A unique name for the Connector. FusionAuth uses the name for display only, and you can change the name later.
  </APIField>
  <APIField name="LDAP URL" required>
    The URL of the LDAP server.
  </APIField>
  <APIField name="Security method" optional>
    The security method for the connection to LDAP. The default, `None`, doesn't encrypt the connection. Use `None` only when another method secures the connection, such as a VPN.
  </APIField>
  <APIField name="Connect timeout" required>
    The connect timeout for requests to LDAP, in milliseconds.
  </APIField>
  <APIField name="Read timeout" required>
    The read timeout for requests to LDAP, in milliseconds.
  </APIField>
  <APIField name="Reconcile lambda" required>
    The lambda that maps the LDAP user to a FusionAuth user.

    To create the lambda, navigate to <Breadcrumb>Customizations -> Lambdas</Breadcrumb>.
  </APIField>
  <APIField name="Enable debug logging" optional>
    When enabled, FusionAuth writes Event Log entries that help you debug integration errors. To view the entries, navigate to <Breadcrumb>System -> Event Log</Breadcrumb>.
  </APIField>
</APIBlock>

### Directory

<Screenshot id="migration-ldap-connector-directory" url="/admin/connector/add/LDAP" crop="#screenshot-band" cropPadding={0} alt="The LDAP Connector Directory tab." />

<APIBlock>
  <APIField name="Base structure" required>
    The directory that FusionAuth searches for users.

    For example, to search the entire directory, use `DC=piedpiper,DC=com`. To search only engineering, add the organization: `OU=engineering,DC=piedpiper,DC=com`.
  </APIField>
  <APIField name="System account DN" required>
    The distinguished name of an entry with read access to the directory.

    For example: `CN=ReadOnlyFusionAuthUser,OU=engineering,DC=piedpiper,DC=com`.
  </APIField>
  <APIField name="System account password" required>
    The password of the **System account DN**.
  </APIField>
  <APIField name="Login identifier attribute" required>
    The attribute that holds the username that the user enters on the login page.

    For example: `uid` or `userPrincipalName`.
  </APIField>

  <APIField name="Identifying attribute" required>
    The attribute that forms the first component of the distinguished name of each directory entry.

    For example: `cn`.
  </APIField>

  <APIField name="Requested attributes" required>
    The directory attributes that LDAP returns for the user. FusionAuth passes the attributes to the reconcile lambda. The lambda converts the attributes to FusionAuth user attributes. Add the attributes one at a time.

    For example: `cn` `givenName` `sn` `userPrincipalName` `mail`
  </APIField>

</APIBlock>

## Using the LDAP Connector

To use an LDAP Connector:

<Steps>

1. Make sure FusionAuth can reach your LDAP server. You might need a VPN, a FusionAuth instance in the same network, or a firewall rule.
1. Choose the LDAP user that FusionAuth connects as.
1. Create an [LDAP Reconcile lambda](/docs/lambdas/reconcile/ldap-connector-reconcile) that maps the directory attributes to FusionAuth user attributes.
1. Configure the Connector in <Breadcrumb>Settings -> Connectors</Breadcrumb>. At a minimum, configure the following settings:
    * The LDAP URL and connection security
    * The reconcile lambda
    * The directory settings
1. Add a Connector policy in <Breadcrumb>Tenants -> Your Tenant -> Connectors</Breadcrumb>. The policy sets the domains that the Connector applies to.

</Steps>

### Using the LDAP Connector as the System of Record

<SystemOfRecordCaveat system_of_record="backing LDAP directory" />

To keep group memberships and application registrations for these users:

1. Store the attributes in the LDAP directory.
1. Add the attributes to **Requested attributes**.
1. Set the user attributes in the [LDAP Reconcile lambda](/docs/lambdas/reconcile/ldap-connector-reconcile).

FusionAuth doesn't push user profile data to LDAP. Data flows only from the Connector into FusionAuth.

To see which Connector is authoritative for a user, check **`connectorId`** on the User object.
