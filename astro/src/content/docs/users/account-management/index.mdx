The self-service account pages let users manage their own accounts. A user can update profile data, change a password, and add or remove MFA methods. FusionAuth hosts the account pages.

## Open the Self-Service Pages

Each Application has an Account URL. To find the Account URL:

<Steps>

1. Navigate to <Breadcrumb>Applications</Breadcrumb> and click <IconButton icon="view" /> on the Application.
1. Copy the **Account URL**.

   <Screenshot id="account-application-details" url="/admin/application/" height={900} alt="The application details dialog showing the Account URL." />

</Steps>

The **Account URL** has the following format:

```uri
https://<your-fusionauth-host>/account/?client_id=<client-id>
```

In your application, link to the Account URL from your navigation.

The account pages are separate from the Admin UI. The <Breadcrumb>Manage</Breadcrumb> page for a user in the Admin UI shows the admin view, not the account pages. To test the account pages, open the Account URL in a private window or a different browser. A private window keeps your admin session out of the way.

### Return to Your Application

<AvailableSince since="1.69.0"/>

The account pages show a <Breadcrumb>Return to application</Breadcrumb> link at the top of the page. By default, the link points to the `Referer` header of the request that opened the account pages. To set the return link, add the `redirect_uri` query parameter to the Account URL:

```uri
https://example.com/account/?client_id=<client_id>&redirect_uri=https://your-app.example.com
```

When a user opens the account pages from the Admin UI, the account pages show no return link.

## Log In to the Account Pages

FusionAuth asks the user to log in before showing the account pages. The user must be registered for the Application.

## Update User Data and Password

To change profile data or a password, the user clicks <Breadcrumb>Edit profile</Breadcrumb> on the account page. The edit page shows the form fields and a <Breadcrumb>Change password</Breadcrumb> toggle.

<Screenshot id="account-edit-password" url="/account/edit?client_id=e9fdb985-9173-4e01-9d73-ac2d60d1dc8e" alt="The account edit form with Change password switched on." />

For more information, see [Updating User Data and Password](/docs/users/account-management/updating-user-data). To add fields to the form, see [Customizing Self-Service Account Management](/docs/users/account-management/customizing-account-management).

## Enable or Disable MFA

To manage MFA methods, the user clicks <Breadcrumb>Manage two-factor</Breadcrumb> on the account page.

<Screenshot id="account-home" url="/account/?client_id=e9fdb985-9173-4e01-9d73-ac2d60d1dc8e" alt="The account page with the edit button and the two-factor and passkey links." />

The two-factor page lists the user's MFA methods and lets the user add a method.

<Screenshot id="account-two-factor" url="/account/two-factor/?client_id=e9fdb985-9173-4e01-9d73-ac2d60d1dc8e" alt="The two-factor page with no methods configured." />

FusionAuth supports the following MFA methods:

* [Authenticator app](/docs/users/account-management/two-factor-authenticator)
* [Email](/docs/users/account-management/two-factor-email)
* [SMS](/docs/users/account-management/two-factor-phone), with optional voice delivery in `1.65.0` and later

When the account pages show a warning instead, the tenant or the Application needs more configuration. For more information, see [Troubleshooting](/docs/users/account-management/troubleshooting).

### Recovery Codes

When a user adds a first MFA method, FusionAuth shows a set of [[Recovery Code::recovery codes]]. Tell users to store the recovery codes in a safe place. A user who loses access to every MFA method, such as after losing a phone, can log in with a recovery code.

<Screenshot id="account-recovery-codes" url="/account/two-factor/enable?client_id=e9fdb985-9173-4e01-9d73-ac2d60d1dc8e" alt="The recovery codes shown after two-factor authentication is enabled." />

## Log Out of the Account Pages

The account pages have a separate session from the FusionAuth SSO session and from your application session. When a user logs out of your application, the account session stays active. On a shared computer, the next person can then open the account pages as that user.

To end the account session, redirect the user to the account logout endpoint with the Application's client Id:

```uri
https://<your-fusionauth-host>/account/logout?client_id=<client-id>
```

To follow the work on ending both sessions together, see [GitHub issue 2298](https://github.com/FusionAuth/fusionauth-issues/issues/2298).
