Write a password hashing plugin when you import users whose passwords use a scheme that FusionAuth doesn't support. With the plugin installed, imported users log in with their existing passwords. For the schemes that FusionAuth supports, see [Password-Hashing Algorithms](/docs/migrate/password-hashes/algorithms).

After the import, keep the custom scheme when the scheme is strong, such as Argon2. When the old system used a weak scheme, rehash the passwords with a stronger scheme. For more information, see [Rehashing User Passwords](#rehashing-user-passwords).

This page covers the plugin code. To set up the project, build the jar, and install the plugin, see [Writing a Plugin](/docs/migrate/password-hashes/writing-a-plugin).

<Aside type="note">
The plugin interface uses the words "encrypt" and "encryptor" for backward compatibility. A Password Encryptor hashes passwords.
</Aside>

## Test the Installed Plugin

After you install the plugin, create a test user with the [Create a User API](/docs/apis/users/create). Set **`encryptionScheme`** to the name of the binding:

```json
{
  "user": {
    "email": "test0@example.com",
    "encryptionScheme": "example-salted-pbkdf2-hmac-sha1-10000",
    "password": "password"
  }
}
```

FusionAuth hashes the password with your Password Encryptor. To confirm that the plugin works, log in as the test user with the [Login API](/docs/apis/login).

## Remove a Plugin

Leave a password hashing plugin installed while any user's password still uses the plugin's scheme. FusionAuth needs the scheme whenever FusionAuth checks or changes that user's password. After you remove the plugin, the following actions fail for that user with an `An unexpected exception occurred.` error:

* Logging in with the password, through the hosted login pages or the [Login API](/docs/apis/login).
* Changing the password.
* Resetting a forgotten password. FusionAuth starts the reset, but setting the new password fails.
* Setting a new password through the [Update a User API](/docs/apis/users/update), even when the request also sets a new **`encryptionScheme`**.

The FusionAuth log records an `UnknownEncryptionSchemeException` that names the missing scheme. To recover, install the plugin again and restart FusionAuth.

### Move Users Off a Scheme

To move users off a plugin's scheme, keep the plugin installed and turn on **Re-hash on login or change** in the Tenant. FusionAuth then rehashes each password with the Tenant's scheme at the user's next login or password change. For more information, see [Rehashing User Passwords](#rehashing-user-passwords).

Some users may not log in again. To move those users, set a random password and a new **`encryptionScheme`** through the [Update a User API](/docs/apis/users/update). The users can then set a password through the forgot password flow.

### Find Users on a Scheme

The [Search for Users API](/docs/apis/users/search) doesn't return the hashing scheme and can't filter on the scheme. To see the scheme of one user, navigate to <Breadcrumb>Users -> Your User -> Manage</Breadcrumb> and open the <Breadcrumb>Source</Breadcrumb> tab.

When you self-host FusionAuth, count the users on each scheme with a database query:

```sql
SELECT password_encryption_scheme, COUNT(*) FROM users GROUP BY password_encryption_scheme;
```

The database schema can change between FusionAuth versions. For more information, see [Export from FusionAuth](/docs/migrate/export).

When you can't query the database, such as on FusionAuth Cloud, write a script that does the following:

1. Call the [Search for Users API](/docs/apis/users/search) with a **`queryString`** of `*`, and collect the User Ids.
1. Call the [Retrieve a User API](/docs/apis/users/retrieve) for each User Id, and count the users by **`encryptionScheme`**.

Add a delay between calls so the script doesn't overload FusionAuth, or run the script outside peak hours.

### Delete the Plugin

When no user or Tenant uses the plugin's scheme, delete the plugin:

<Steps>

1. Confirm that no user uses the plugin's scheme.
1. Confirm that no Tenant uses the plugin's scheme. Call the [Retrieve a Tenant API](/docs/apis/tenants/retrieve-a-tenant) without a Tenant Id to list every Tenant, and check **`tenant.passwordEncryptionConfiguration.encryptionScheme`**.
1. Delete the plugin's jar file from the `plugins` directory on every node.
1. Restart FusionAuth on every node.

</Steps>
