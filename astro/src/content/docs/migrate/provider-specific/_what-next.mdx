After the users move, migrate the other configuration described in [Other Entities](#other-entities). The steps vary by configuration, but follow this pattern:

* Find the matching FusionAuth feature.
* Configure the feature in FusionAuth, either in the Admin UI or with a script that uses the [client libraries](/docs/sdks) or the [APIs](/docs/apis).
* Update your application configuration to use the FusionAuth feature.

Register your users with the right FusionAuth Applications in one of the following ways:

* Add Registrations to the users during the import.
* Create Registrations after the import with the [Registrations API](/docs/apis/registrations).

Change and test each application, whether custom, open source, or commercial, and confirm the following:

* Users can log in.
* The application handles the authorization code redirect.
* Users get the right permissions and roles from the JWT.
* The hosted login pages match the look and feel of the application.

When an application talks to {props.migration_source_name} through a standard OAuth, SAML, or OIDC library, the switch to FusionAuth usually takes few changes.
