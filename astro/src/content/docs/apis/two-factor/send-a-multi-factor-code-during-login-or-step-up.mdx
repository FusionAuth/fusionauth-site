Send a code to finish a multi-factor login or step-up flow. The request requires an existing **`twoFactorId`** and no API key.

Use this API only when you want FusionAuth to send the code. When you send the code out of band, or the user authenticates with a TOTP method, skip this API.

To re-send a code, call this API again with the same method or a different method. Each send invalidates every earlier code for the **`twoFactorId`**.

<Aside type="caution" title="Don't send a JWT with this request">
  When the request includes a JWT, FusionAuth looks up **`methodId`** on the user in the JWT instead of the user in the multi-factor flow. FusionAuth reads the JWT from the `Authorization` header or from the `access_token` cookie. When the JWT belongs to a different user, FusionAuth returns a `400` response code with the `[invalid]methodId` error. A browser sends the `access_token` cookie automatically on same-origin requests, so a stale session from another user can cause the error. When you call this API from a browser, clear the `access_token` cookie or send the request without credentials.
</Aside>

## Request

<API method="POST" uri="/api/two-factor/send/{twoFactorId}" authentication={["none"]} title="Send a multi-factor code to complete a multi-factor login"/>

### Path Parameters

<APIBlock>
  <APIField name="twoFactorId" type="String" required>
    The **`twoFactorId`** that the Login API or the Start Multi-Factor API returns.
  </APIField>
</APIBlock>

### Request Headers

<XFusionauthTenantIdHeaderScopedOperation />

### Request Body

<APIBlock>
  <APIField name="messageType" type="String" optional since="1.65.0" defaults="SMS">
    The message type for a phone-based MFA method. FusionAuth reads **`messageType`** only when the selected MFA method is `sms`.

    The valid values are:

    * `SMS`
    * `Voice`
  </APIField>
  <APIField name="methodId" type="String" required>
    The Id of the MFA method that FusionAuth sends the code with.
  </APIField>
</APIBlock>
