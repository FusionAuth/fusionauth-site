FusionAuth caches API keys for faster lookups. Multi-node deployments share the cache through an internal distributed cache and notifications. A new API key becomes usable after FusionAuth updates the cache, usually in less than one second. When communication between nodes fails, the update can take up to 60 seconds.

When you create an API key with the [API Keys API](/docs/apis/api-keys/create-an-api-key) and use the API key right away, FusionAuth can return a `401`. A `401` usually means the API key isn't valid. In this case, the `401` means the new API key isn't usable yet.

To work around the delay, retry the request with exponential backoff.
