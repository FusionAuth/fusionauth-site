FusionAuth provides REST APIs for login, registration, and User management. The Admin UI uses the same APIs, so you can do anything in the Admin UI through an API.

Before you call an API, read about [API Authentication](/docs/apis/authentication) and [API Errors](/docs/apis/errors).

## APIs

Unless an API documents otherwise, the API expects a JSON request body. Set the `Content-Type` header on every request with a body:

```plaintext options="wrap" title="Content-Type Header"
Content-Type: application/json
```

## Status Codes

Each API page lists the status codes that the API returns, with a reason for each code. The following status codes apply to most APIs:

| Code | Description |
|------|-------------|
| 200  | The request succeeded. The response body contains JSON unless the API documents otherwise. |
| 400  | The request isn't valid. The response contains an [Errors](/docs/apis/errors) JSON object with the specific errors. |
| 401  | FusionAuth didn't authorize the request. The Authorization header is missing, the API key isn't valid, or the API key doesn't have permission for this endpoint and method. The response is empty. For more information, see [Unauthorized Responses](/docs/apis/authentication#unauthorized-responses). |
| 404  | The requested object doesn't exist. The response is empty. |
| 405  | The URI doesn't allow the HTTP method of the request. For example, when an API supports only `POST` and you send a `GET` request, FusionAuth returns `405`. The response is empty. |
| 413  | The request body is larger than the maximum request size, which is 128 MB by default. The response is empty. For more information, see `fusionauth-app.http.max-request-size` in the [Configuration reference](/docs/deploy/production/configuration). |
| 500  | FusionAuth had an internal error and logged a stack trace in the FusionAuth log files. The response usually contains an [Errors](/docs/apis/errors) JSON object with the `[Exception]` general error code. On MySQL, a **`data`** field larger than the database column also returns `500`. For more information, see [Data Field Sizes](/docs/concepts/plans-and-limits/limitations#data-field-sizes). For any other `500` response, open a [GitHub Issue](https://github.com/FusionAuth/fusionauth-issues/issues). |
| 501  | FusionAuth doesn't implement the HTTP method of the request. |
| 503  | FusionAuth can't complete the request because of the current rate of requests. Retry the request later. |
| 512  | A lambda invocation failed during the API request. FusionAuth creates an Event Log with details of the exception. To view the Event Log, navigate to <Breadcrumb>System -> Event Log</Breadcrumb>. |

## The PATCH HTTP Method

FusionAuth supports the following `PATCH` options. To choose an option, set the `Content-Type` header of the request:

| Option | Content-Type | Array Behavior | Available Since |
|--------|--------------|----------------|-----------------|
| Original | `application/json` | Varies by API and field. Some arrays append, and others replace. For example, FusionAuth appends to **`user.preferredLanguages`** but replaces **`registration.roles`**. | `1.12.0` |
| [JSON Patch (RFC 6902)](https://www.rfc-editor.org/rfc/rfc6902) | `application/json-patch+json` | Operations in the request describe each change. | `1.39.0` |
| [JSON Merge Patch (RFC 7396)](https://www.rfc-editor.org/rfc/rfc7396) | `application/merge-patch+json` | An array in the request replaces the existing array. | `1.39.0` |

The client libraries support only the original option. FusionAuth may deprecate the original option in the future. Before you rely on the array behavior of the original option for an API, read the API documentation and test the request. To change an array predictably without JSON Patch or JSON Merge Patch, `GET` the object, then `PUT` the full object.

When a request changes only object fields, and no arrays, all `PATCH` options produce the same result.

#### Original

With the original `PATCH` method, from before `1.39.0`, the safest way to remove the `dev` role is to `GET` the Group, remove the role from the **`roleIds`** array, and `PUT` the full Group:

```json title="PUT Request JSON"
{
  "group": {
    "name": "Paid employees",
    "data": {}
  },
  "roleIds": [
    "0a15cfdd-e231-4de4-9411-6d1015e05d99"
  ]
}
```

#### JSON Patch

JSON Patch uses operations to add, remove, replace, move, copy, and test values in a JSON object. For the full list of operations, see [RFC 6902](https://www.rfc-editor.org/rfc/rfc6902). To build a request, try the [JSON Patch builder](https://json-patch-builder-online.github.io/).

Send a `PATCH` request with a `Content-Type` of `application/json-patch+json` and the following body:

```json title="JSON Patch Request JSON"
[
  {
    "op": "remove",
    "path": "/roleIds/1"
  }
]
```

The `remove` operation deletes the second value of the **`roleIds`** array, which holds the `dev` role. To find the index of the value, you might need a separate `GET` request first.

One JSON Patch request can make several precise changes to an object. The request body is a list of operations, so the body doesn't match the structure of the object you change.

#### JSON Merge Patch

JSON Merge Patch updates an object with a body that matches the structure of the object. For the full merge behavior, see [RFC 7396](https://www.rfc-editor.org/rfc/rfc7396).

Send a `PATCH` request with a `Content-Type` of `application/merge-patch+json` and the following body:

```json title="JSON Merge Patch Request JSON"
{
  "roleIds": [
    "0a15cfdd-e231-4de4-9411-6d1015e05d99"
  ]
}
```

The **`roleIds`** array in the request replaces the existing array, which removes the `dev` role.

## Explore the APIs

To try the APIs, use a self-hosted instance or the [Sandbox](https://sandbox.fusionauth.io). For sample requests, see the [FusionAuth Postman collection](https://www.postman.com/fusionauth).

## Backwards Compatibility

FusionAuth keeps APIs and features backwards compatible when possible. Before FusionAuth removes an API or feature, FusionAuth deprecates the API or feature first. For more information, see the [Deprecation Policy](/docs/update/deprecation-policy).

### Errors After Configuration Changes

<Aside type="caution" title="New configuration can take a few seconds to apply">
FusionAuth caches configuration, such as Applications, Identity Providers, Tenants, and Keys. After you create or update configuration, FusionAuth reloads the cache in the background. When you make many changes in a short time, FusionAuth batches the reloads, and a reload can take a few seconds.
</Aside>

Until the reload finishes, requests that use the new configuration can fail or use the old configuration. For example:

* The Token endpoint returns `invalid_client` for a new Application.
* The Identity Provider Login API returns `[InvalidIdentityProviderId]` for a new Identity Provider.
* A login uses the old settings of an updated Identity Provider.

When you script setup with the API, retry failed requests with exponential backoff, or wait after the last configuration change.
