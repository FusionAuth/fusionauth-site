<span id="openid-configuration"></span>

The OpenID metadata describing the configuration as defined by [Section 3. OpenID Provider Metadata](https://openid.net/specs/openid-connect-discovery-1_0.html#ProviderMetadata).


## Request

Returns the well known OpenID Configuration JSON document

<API method="GET" uri="/{tenantId}/.well-known/openid-configuration"/>

<API method="GET" uri="/.well-known/openid-configuration/{tenantId}"/>

<API method="GET" uri="/.well-known/openid-configuration"/>

### URL segment

<APIBlock>
  <APIField name="tenantId" type="UUID" required since="1.46.0">
    The tenant identifier.
  </APIField>
</APIBlock>

### Path Parameters

<APIBlock>
  <APIField name="tenantId" type="UUID" optional since="1.8.0">
    The tenant identifier.
    If provided then a specific issuer will be returned, when this property is not provided the default tenant Id will be used.
  </APIField>
</APIBlock>

## Response

The response for this request should always return a `200` with a JSON body.

<AvailableSince since="1.70.0">
The `authorization_endpoint`, `device_authorization_endpoint`, `end_session_endpoint`, and `token_endpoint` values end with the Tenant Id, such as `https://piedpiper.fusionauth.io/oauth2/authorize/{tenantId}`. When the request doesn't identify a Tenant, the default Tenant is used.

The `client_id_metadata_document_supported` value is `true` when your license includes [Client ID Metadata Documents (CIMD)](/docs/lifecycle/authenticate-users/oauth/client-registration#client-id-metadata-documents) and the Tenant has at least one [CIMD domain](/docs/get-started/core-concepts/types/cimd-domains). Otherwise, it is `false`.
</AvailableSince>
