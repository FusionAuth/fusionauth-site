<AvailableSince since="1.6.0"/>

A SAML v2 Identity Provider connects FusionAuth to an external SAML v2 login system. FusionAuth can show a <Breadcrumb>Login with ...</Breadcrumb> button for the Identity Provider on the FusionAuth login page. The properties of the Identity Provider control the button.

A SAML v2 Identity Provider can list one or more domains. Domains let employees log in with corporate credentials from any company identity solution that supports SAML v2. FusionAuth calls an Identity Provider with domains a Domain Based Identity Provider. When an Identity Provider has domains, the FusionAuth login page hides the <Breadcrumb>Login with ...</Breadcrumb> button and shows only the `email` field at first. After the user enters an email address, FusionAuth compares the domain of the address to the domains of the Identity Provider. FusionAuth then logs the user in locally, or redirects the user to the Identity Provider.

FusionAuth reads the email address, unique Id, and username of the user from the [[SAML assertion]], based on the claim fields of the Identity Provider. The linking strategy decides how FusionAuth matches the user. To use other claims from the SAML response, assign a [SAML v2 Reconcile Lambda](/docs/lambdas/reconcile/samlv2-response-reconcile) to the Identity Provider.

## Start a SAML v2 Login Request

<AvailableSince since="1.19.0"/>

Use this API to start a SAML v2 login from your own login page instead of the FusionAuth hosted login pages.

Each SAML v2 AuthN request needs a unique request Id. This API records the Id before the login starts, so FusionAuth can reject a replayed SAML response. FusionAuth generates the Id, or you can provide your own Id in **`data.requestId`**.

Put the **`code`** from the response in the `ID` attribute of the SAML AuthN request that you send to the SAML v2 Identity Provider. The SAML v2 Identity Provider returns the code in the `InResponseTo` attribute of the SAML response, and FusionAuth checks the code when you call the [Complete a SAML v2 Login](#complete-a-saml-v2-login) API.

```mermaid title="Request flow when your own login page uses a SAML v2 Identity Provider."
sequenceDiagram
    participant App as Your Application
    participant FusionAuth
    participant IdP as SAML v2 Identity Provider
    App ->> FusionAuth : POST /api/identity-provider/start
    FusionAuth ->> App : code
    App ->> IdP : AuthN request with ID set to the code
    IdP ->> App : Form POST with a SAMLResponse whose InResponseTo is the code
    App ->> FusionAuth : POST /api/identity-provider/login with data.samlResponse
    FusionAuth ->> App : User object
```

### Request

Start a SAML v2 login to get the code that completes the login.

<API method="POST" uri="/api/identity-provider/start" authentication={["none"]} title="Start a login request"/>

#### Request Body

<IdentityProviderStartRequestBody idp_display_name={idp_display_name}

## Complete a SAML v2 Login

Use this API to complete a SAML v2 login from your own login page, after the user logs in with a SAML v2 Identity Provider. When you use the FusionAuth hosted login pages, you don't need this API.

For example, your login page can show a <Breadcrumb>Login with Pied Piper</Breadcrumb> button for a third-party SAML v2 Identity Provider. After the user logs in, the SAML v2 Identity Provider sends the user back to your application with a form `POST`. The form `POST` contains a `SAMLResponse` parameter. Pass the `SAMLResponse` to this API, and FusionAuth completes the login and reconciles the user.
