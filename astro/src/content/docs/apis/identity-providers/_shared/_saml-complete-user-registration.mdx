
Depending on the [linking strategy](/docs/authentication/identity-providers/linking-strategies), the user doesn't need to exist in FusionAuth before you call this API. FusionAuth reads the user's information from the `SAMLResponse`. When the user doesn't exist, FusionAuth can create the user.

When **`createRegistration`** is enabled for the Identity Provider and the user has no Registration for the Application, FusionAuth creates the Registration. FusionAuth gives the new Registration the default roles of the Application.

When **`createRegistration`** is disabled, FusionAuth doesn't create a missing Registration. When you provision users by hand before the users log in with the Identity Provider, disable **`createRegistration`**.
