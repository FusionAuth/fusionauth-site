
Use this API to complete a {props.idp_display_name} login after you authenticate a user with the {props.idp_display_name} API. When you use the FusionAuth login UI with the {props.idp_display_name} button, you don't call this API directly.

Use this API when you build your own login page with the {props.idp_display_name} login button and need to complete the login with FusionAuth.

<If condition={props.idp_display_name !== 'HYPR'}>
For example, you could add a "Login with {props.idp_display_name}" button to your own login page and complete the {props.idp_display_name} authentication. {props.idp_display_name} then returns {props.token_text_with_article} to you. Pass that {props.token_text} to FusionAuth with this API. FusionAuth then completes the login workflow and reconciles the user to FusionAuth.

Depending on the configured [linking strategy](/docs/authentication/identity-providers/linking-strategies), the user doesn't need to exist in FusionAuth before you call this API. FusionAuth uses the {props.token_text} from {props.idp_display_name} to retrieve the user's email address or username. When the user doesn't exist in FusionAuth yet, FusionAuth may create the user.
</If>

<If condition={props.idp_display_name === 'HYPR'}>
The user must exist in FusionAuth before you call this API. You must also [Start the HYPR Login Request](#start-the-hypr-login-request) before you call this API.
</If>

When **`createRegistration`** is enabled for this Identity Provider and the user doesn't have a Registration for this Application, FusionAuth creates a Registration for the user automatically. FusionAuth assigns the user any default roles configured for the Application.

When **`createRegistration`** is not enabled, FusionAuth doesn't create a Registration for a user who doesn't have one. Use this setting when you want to provision users manually and then let those users log in with {props.idp_display_name}.
