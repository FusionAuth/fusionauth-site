  <APIField name="identityProvider.domains" type="Array<String>" optional>
    An optional list of domains for this OpenID Connect Identity Provider. When you set domains, FusionAuth converts the login form to a domain-based login form. A domain-based login form first asks the user for an email address. FusionAuth then uses the email address to decide whether to use an OpenID Connect IdP. When FusionAuth uses an OpenID Connect IdP, FusionAuth redirects the browser to the authorization endpoint of that IdP. Otherwise, the form reveals the password field so that the user can log in with FusionAuth.

    The expected name of the claim from the IdP that contains the email address.

  </APIField>
  <APIField name="identityProvider.oauth2.emailVerifiedClaim" type="String" optional defaults="email_verified" since="1.48.0">
    The expected name of the claim from the IdP that indicates whether the email is verified.

    FusionAuth uses the first occurrence of this claim. FusionAuth checks the UserInfo response first. FusionAuth then checks the `id_token`, when present and when FusionAuth can verify the signature.

    When **`identityProvider.linkingStrategy`** is `LinkByEmail` or `LinkByEmailForExistingUser`, and this claim is present with a value of `false`, FusionAuth doesn't establish a link. FusionAuth returns an error that says FusionAuth can't establish a link with an unverified email address.
  </APIField>
  <APIField name="identityProvider.oauth2.issuer" type="String" optional>
