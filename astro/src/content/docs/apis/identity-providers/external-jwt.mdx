An External JWT Identity Provider logs in users with JWTs that an external system issues. The Identity Provider defines the claims in the JWT, and how the claims map to fields of the FusionAuth User. The Identity Provider has no login page. To log in a user, send the JWT to [Complete the External JWT Login](#complete-the-external-jwt-login) or to the [Reconcile API](/docs/apis/jwt/reconcile-a-jwt-using-the-external-jwt-provider). Both APIs take the same request and return the same response.

<ExternalJwtProviderWarning />

FusionAuth validates the JWT signature with the verification keys of the Identity Provider, and checks that the JWT hasn't expired. FusionAuth then reconciles the user that the JWT represents, so the user exists in FusionAuth and has current data.

When the login request includes **`data.refresh_token`**, FusionAuth stores the value in the **`token`** field of the user's link to the Identity Provider. Use the value to call the external system on behalf of the user. For more information, see the [Link API](/docs/apis/identity-providers/links).

## Complete the External JWT Login

Log in a user with a JWT that an external system issued. The [Reconcile API](/docs/apis/jwt/reconcile-a-jwt-using-the-external-jwt-provider) takes the same request and returns the same response.

The user doesn't need to exist in FusionAuth before the login. The [linking strategy](/docs/authentication/identity-providers/linking-strategies) decides whether FusionAuth creates the user from the JWT claims.

When **`createRegistration`** is enabled for the Application in the Identity Provider, FusionAuth registers a user who has no [[Registration]] for the Application. FusionAuth then assigns the default roles of the Application. When **`createRegistration`** is disabled, FusionAuth doesn't register the user, and the response has a `202` status code. To let only users that you register in advance log in, disable **`createRegistration`**.

### Request

Send the JWT in **`data.token`**.
