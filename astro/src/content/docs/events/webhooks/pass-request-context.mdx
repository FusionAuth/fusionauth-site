You can attach your own data to a FusionAuth API request, such as a trace Id or the name of the service that made the call. FusionAuth copies the data into the events the request triggers. Your webhook can then tie each event back to the API call that caused the event, without a second API call.

The data travels in the **`eventInfo.data`** field of the request body. FusionAuth delivers the data, without changes, as **`event.info.data`** in the webhook payload.

```mermaid title="FusionAuth copies eventInfo.data from an API request into the event that the request triggers."
sequenceDiagram
    participant Service as Your service
    participant FusionAuth
    participant Webhook as Your webhook
    Service ->> FusionAuth : POST /api/user with eventInfo.data
    FusionAuth -->> Service : 200 OK
    FusionAuth ->> Webhook : user.create event with event.info.data
```

## Prerequisites

* A FusionAuth API key with permission to call the API you use.
* A webhook that listens for the events the request triggers, with those events enabled on the Tenant. For more information, see [Write a Webhook](/docs/events/webhooks/writing-a-webhook).
* A shared secret in the webhook's `Authorization` header, so your webhook can reject events that don't come from FusionAuth. For more information, see [Secure Webhooks](/docs/events/webhooks/securing).

## Which Requests Accept Context

Most calls to the User, Registration, Login, Logout, JWT, and Two Factor APIs carry **`eventInfo`** into events. A call carries the field when the call's request body reference lists **`eventInfo`**. For example, the Tenant and Application APIs list **`eventInfo`** for updates, but not for creates.

The following requests don't carry **`eventInfo.data`** into events:

* The Group and Entity APIs don't accept **`eventInfo`**. Events from those APIs never include **`event.info.data`**.
* The Identity Provider Link API ignores **`eventInfo`** in the request.
* Logins through the hosted login pages don't take **`eventInfo`** from your application. FusionAuth fills in **`event.info`** from the browser request instead.

## Other Event Info Fields

**`eventInfo`** also accepts details about the end user, such as **`ipAddress`**, **`userAgent`**, and **`deviceName`**. When your server calls FusionAuth on behalf of an end user, set those values from the end user's request. Otherwise, events and login records show the address of your server. FusionAuth always sets **`event.info.location`** from the IP address, and ignores a **`location`** in the request. For the full list of fields, see the [Create a User](/docs/apis/users/create) request body.
