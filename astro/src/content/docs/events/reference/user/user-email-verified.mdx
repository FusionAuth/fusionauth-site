## When FusionAuth Sends the Event

FusionAuth sends the event when a user's email address changes from unverified to verified. The following actions verify an email address:

* The user completes the email verification workflow, or you call the [Verify Email API](/docs/apis/users/verify-email).
* The user completes another workflow that FusionAuth emailed to the address, such as forgot password. This implicit verification happens only when the Tenant has **`tenant.emailConfiguration.implicitEmailVerificationAllowed`** set to `true`.

FusionAuth doesn't send the event for an email address that FusionAuth already treats as verified. When the Tenant doesn't require email verification, FusionAuth treats every email address as verified as soon as you add the address, so the event never fires. The same applies when you create the user with **`skipVerification`** set to `true`. In both cases, **`user.identities[x].verifiedReason`** shows why FusionAuth skipped verification. For more information, see the [User response body](/docs/apis/users/retrieve#response-body).
