This guide provides step-by-step instructions for basic operations in the FusionAuth Admin UI for individuals who support end users (e.g. a customer service representative resetting a password).

This guide also contains information about customizing Admin UI forms for developers who build tools for customer service representatives.

## Add a Support User

To add a support user:

<Steps>
1. Follow the instructions in the [Add a New User](#add-a-new-user) section below to create a support user account.
1. As a user with the `user_manager` role, follow the instructions in the [Assign a Role to an Existing User](#assign-a-role-to-an-existing-user) section, assigning the support user account the `user_support_viewer` or `user_support_manager` role.
1. The support user should now be able to access the Admin UI with the appropriate privileges.
</Steps>

### Support User Roles

Support users are likely to be assigned one of the following roles:

* `user_support_viewer`: Can view user information in the Admin UI, but cannot make any changes.
* `user_support_manager`: A special role tuned for tier 1 technical support personnel with a mix of capabilities, including reading user information and writing non-admin user information.

<Aside type="tip">
For more information about roles in FusionAuth, see [roles](/docs/get-started/core-concepts/types/roles#fusionauth-admin-ui-roles).
</Aside>

### Privilege Escalation

<Aside type="caution">
Prefer the `user_support_manager` role to the `user_manager` role to avoid undesired privilege escalation.
</Aside>

If you grant someone the `user_manager` role, they can then create a user, set the user's email address and password, and grant that user the `admin` or any other FusionAuth role. They could then log in as that user and have `admin` privileges.

This is working as designed, as the `user_manager` role provides full control of all users. Read more about this design choice in this [GitHub issue](https://github.com/FusionAuth/fusionauth-issues/issues/2170).

To prevent this escalation, use the `user_support_manager` role, which can add users, but cannot register a user for the FusionAuth admin application.

## Add A New User

To add a user, you need one of the following roles:

* `user_manager`
* `user_support_manager`
* `admin`

<Steps>
1. Log in to the Admin UI using your admin credentials and select <Breadcrumb>Users</Breadcrumb> from the left sidebar of the dashboard.

   ![image](/img/docs/operate/deploy/users-tab.png)

1. Click on the green <Icon name="plus" /> icon to open the **Add User** form:

   ![image](/img/docs/operate/deploy/new-user-form.png)

1. Complete the fields for the new user. You can choose to set the user's password or let the user set their own password by toggling the <Breadcrumb>Send email to set up password</Breadcrumb> button.

1. Click on the <Icon name="save" /> icon in the top right corner to create the user.
</Steps>

## Send A Password Reset

Use the Password Reset operation to help an end user regain access to their account.

<Steps>
1. Log in to the Admin UI.
1. Navigate to <Breadcrumb>Users</Breadcrumb> and search for the user whose password needs to be reset.
1. Click on the <Icon name="user" /> icon to open the user's details page.
1. Click on the down arrow next to the <Breadcrumb>Edit user</Breadcrumb> button to open a dropdown with user management options.
1. Select <Breadcrumb>Send password reset</Breadcrumb> to send password reset instructions to the end user by email.

   ![image](/img/docs/operate/deploy/send-password-reset.png)

1. Confirm the password reset by clicking <Breadcrumb>Submit</Breadcrumb> in the popup.

   ![image](/img/docs/operate/deploy/confirm-reset.png)
</Steps>

## Verify User Information

You might need to verify a user's information for security purposes or to ensure up-to-date user data.

<Steps>
1. Log in to the Admin UI.
1. Navigate to <Breadcrumb>Users</Breadcrumb> and search for the user whose information needs to be updated.
1. Click on the <Icon name="user" /> icon to open the user's details page.
1. Here you can view user information such as  **Email** address, **Mobile Phone** number, **Birthdate**, and **Username**.

   ![image](/img/docs/operate/deploy/verify.png)

1. To update the information, click the <Breadcrumb>Edit user</Breadcrumb> button to open the <Breadcrumb>Edit User</Breadcrumb> form.

   ![image](/img/docs/operate/deploy/edit-user.png)

1. To save your changes, click the <Icon name="save" /> icon.
</Steps>

## Log A User Out

You might need to log a user out of their account for security reasons, following a data breach, or to perform system maintenance. 

<Steps>
1. Log in to the Admin UI using your admin credentials.
1. Navigate to <Breadcrumb>Users</Breadcrumb> and search for the user who needs to be logged out.
1. Click on the <Icon name="user" /> icon to open the user's details page.
1. Select the <Breadcrumb>Sessions</Breadcrumb> tab to view the user's current sessions.
1. Click on the <Icon name="trash" /> icon to delete a single session or <Breadcrumb>Delete all sessions</Breadcrumb> to clear all the user's sessions and the user will be logged out.

   ![image](/img/docs/operate/deploy/sessions.png)
</Steps>

## Delete A User

<Aside type="caution">
The Delete user action is destructive and cannot be reversed. Instead, FusionAuth recommends that you lock (deactivate) the user which is not destructive and may be reversed. Navigate to [Lock Or Unlock A User Account](#lock-or-unlock-a-user-account) for instructions on locking and unlocking an account.
</Aside>

## Assign a Role to an Existing User

To assign a role to an existing user, you need one of the following roles:

* `user_manager`
* `admin`

<Steps>
1. On the <Breadcrumb>Users</Breadcrumb> page, search for the user you will assign the role to and click on the <Icon name="user" /> icon in the action column to open the user details page.

1. Scroll down and click the **Add registration** button.

   ![image](/img/docs/operate/deploy/add-registration.png)

1. Select an **Application** if you have configured multiple applications.

   ![image](/img/docs/operate/deploy/select-application.png)

1. On the <Breadcrumb>Add User Registration</Breadcrumb> page, scroll down to the **Roles**. Select the role to assign to the user, in this case, **User support manager (user_support_manager)**.

   ![image](/img/docs/operate/deploy/roles.png)

1. To assign the new roles to the user, click the <Icon name="save" /> icon.
</Steps>

## Remove an MFA Method with the `mfa_deleter` Role

If your support team needs to remove a user's MFA method without requiring the user's one-time code, assign the `mfa_deleter` role.

This role allows support personnel to remove a user's MFA method from the <Breadcrumb>Users -> Manage User -> Multi-Factor</Breadcrumb> tab by clicking the disable button and confirming removal.

### Guardrails for `mfa_deleter`

FusionAuth applies additional safeguards to this role:

* The target user cannot be registered to the FusionAuth admin application.
* The target user must be notifiable through at least one verified primary identity and a configured tenant template:
  * verified email + `tenant.emailConfiguration.adminTwoFactorMethodRemoveEmailTemplateId`
  * verified phone number + `tenant.phoneConfiguration.adminTwoFactorMethodRemoveTemplateId`

If these conditions are not met, MFA removal is blocked in the Admin UI.

<Aside type="caution">
Do not combine `mfa_deleter` with roles that can modify tenant configuration (for example, `email_template_manager`, `message_template_manager`, `tenant_manager`). A user who can both remove MFA methods and change tenant notification templates can weaken these safeguards.
</Aside>

## User Management Outside of the Admin UI

If you want to create your own customer user support forms because custom Admin UI forms don't meet your needs, you can use the [APIs](/docs/apis/) or one of the [Client Libraries](/docs/sdks/) to build any workflow you desire.

For instance, suppose you wanted to take the following actions in one screen:

1. Create a user
1. Add them to a group
1. Verify their identity against an external database
1. Register them to an application with a role based on their identity
1. Ensure they had first name, last name and favorite color set

In this case, a custom form built against the FusionAuth APIs is the best path forward. The Admin UI, while flexible, is not capable of this level of customization.
