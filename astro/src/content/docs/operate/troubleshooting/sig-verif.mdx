## Do I care about this?

1. Do you rotate JWT signing keys in FusionAuth?
2. Do you use SAML IDPs?
3. Do you use external JWT IDPs?
4. Do your lambdas modify any of the following claims? `tid`, `iss`, `aud`
5. (Uncommon) Do you mint JWTs outside of FusionAuth that you submit to FusionAuth endpoints for authentication or introspection?

If you answered yes to any of these questions, please visit **each section**.

## Section 1 - JWT Signing Key Rotation

### Before the upgrade

Before the 1.69.0 upgrade, use Key Master or APIs in your FusionAuth instance to find all old keys that are present AND still need to be trusted for JWT signing, IDPs, etc. Make note of those key Ids.

The keys you are trying to find are all old keys that were previously configured as the *Access token signing key* or *Id token signing key* on the tenant or application, but have since been rotated out in favor of a new key.

A table like this one might be helpful to note/jot down the keys.

| Tenant or Application | Tenant/Application Id                | Key Id                               | Needed for access, Id tokens, or both |
| --------------------- | ------------------------------------ | ------------------------------------ | ------------------------------------- |
| Tenant                | 32306536-3036-6431-3865-646430303332 | f1b86ee2-32de-429a-88a4-979b8dcb81f1 | Both                                  |

### After the upgrade

Find each tenant or application and Key Id that you previously recorded and add them to the

*Access token verification keys* or *Id token verification keys* setting on the JWT tab as appropriate.

See [core concepts](/docs/get-started/core-concepts/tenants#jwt) or [Tenant API](/docs/apis/tenants/create-a-tenant) for more information. The setting is the same at the application level if you use application JWT overrides.

The [key rotation](/docs/operate/secure/key-rotation) docs have also been updated that explain how this process should work going forward.
