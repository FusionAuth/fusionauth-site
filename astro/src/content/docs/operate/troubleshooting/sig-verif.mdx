## When should I use this guide?

Read and plan BEFORE you upgrade to 1.69.0.

## How do I know if this affects me?

1. Do you rotate JWT signing keys per the [key rotation documentation](/docs/operate/secure/key-rotation)?
2. Do you use FusionAuth with external SAML IDPs?
3. Do you use FusionAuth as a SAML IDP for your applications (which are SPs)?
4. Do you use external JWT IDPs?
5. Do your Application JWT Access Token/Id Token populate lambdas modify any of the following claims? `aud`, `iss`?
6. (Uncommon) Do you mint JWTs outside of FusionAuth that you submit to FusionAuth endpoints for authentication or introspection?

If you answered yes to any of these questions, please visit **each section number that corresponds with this list**.

## Section 1 - JWT Signing Key Rotation

### Before the upgrade

Before the 1.69.0 upgrade, use Key Master or APIs in your FusionAuth instance to find all old keys that are present AND still need to be trusted for JWT signing, IDPs, etc. Make note of those key Ids.

<Aside type="note">
    Consider your access token TTL. If your token TTL is 60 minutes (FusionAuth's default) and you rotated your keys 2 weeks ago, then there is nothing you need to do.
</Aside>

The keys you are trying to find are all old keys that were previously configured as the *Access token signing key* or *Id token signing key* on the tenant or application, but have since been rotated out in favor of a new key. Keep naming conventions, etc. you might have used in mind for this purpose.

A table like this one might be helpful to note/jot down the keys.

| Tenant or Application | Tenant/Application Id                | Key Id                               | Needed for access, Id tokens, or both |
| --------------------- | ------------------------------------ | ------------------------------------ | ------------------------------------- |
| Tenant                | 32306536-3036-6431-3865-646430303332 | f1b86ee2-32de-429a-88a4-979b8dcb81f1 | Both                                  |

### After the upgrade

Find each tenant or application and Key Id that you previously recorded and add them to the *Access token verification keys* or *Id token verification keys* setting on the JWT tab as appropriate.

See [core concepts](/docs/get-started/core-concepts/tenants#jwt) or [Tenant API](/docs/apis/tenants/create-a-tenant) for more information. The setting is the same at the application level if you use application JWT overrides.

The [key rotation](/docs/operate/secure/key-rotation) docs have also been updated that explain how this process should work going forward.

## Section 4 - External JWT IDPs

### Before the upgrade

FusionAuth 1.69.0 will **require** a *Default verification key* to be configured on the JWT tab to indicate which External IDP JWTs should be considered trusted.

Set a value for this now.

### After the upgrade

If you DO NOT use key rotation - no immediate changes are required.

If you DO already use key rotation or you intend to start - you will need to change your processes per the [key rotation](/docs/operate/secure/key-rotation) document. This means you will need to ensure ALL keys that need to be trusted, at the same time, are present in the `identityProvider.verificationKeyIds` setting for the IDP. This field replaces the previous `identityProvider.defaultKeyId` field.
