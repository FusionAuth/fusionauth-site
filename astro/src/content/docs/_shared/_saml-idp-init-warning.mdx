FusionAuth doesn't recommend this type of login, because an unsolicited authentication response from a third-party Identity Provider (IdP) carries risk.

In an SP-initiated login, FusionAuth is the service provider (SP), and receives the SAML Authentication Response in reply to an authentication request. FusionAuth can then validate certain parameters, and accept only a response to a request that FusionAuth started. In an IdP-initiated login, the third-party IdP sends FusionAuth a SAML Authentication Response without any request or context. FusionAuth didn't start the login, so FusionAuth can verify less, and must allow a cross-site request from the third party.

When you need this type of login for a legacy integration, or when the user experience matters most, you can enable the feature.
