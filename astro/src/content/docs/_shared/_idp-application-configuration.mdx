To enable {props.identity_provider ?? 'an Identity Provider'} for an Application or [CIMD domain](/docs/authentication/identity-providers/applications-and-overrides#cimd-clients):

<Steps>

1. In the Admin UI, navigate to <Breadcrumb>Settings -> Identity Providers</Breadcrumb>.

1. Click the arrow next to the add button, and select {props.identity_provider ? <Breadcrumb>{props.identity_provider}</Breadcrumb> : 'your Identity Provider'}.

1. Select the Tenant for the Identity Provider, or select `Global identity provider`. You can't change the scope later. For more information, see [Identity Provider Scope](/docs/authentication/identity-providers/identity-provider-scope).

1. Fill out the form. Your identity provider supplies most of the values. For a description of each field, see <a href={props.details_link ?? '/docs/authentication/identity-providers/'}>{props.details_link ? 'Form Fields' : 'the guide for your Identity Provider'}</a>.

1. On the <Breadcrumb>Applications</Breadcrumb> tab, turn on **Enabled** for each Application or CIMD domain that uses the Identity Provider.

1. To register new users for the Application with the Application's default roles, turn on **Create registration**. When **Create registration** is off, a user needs a registration for the Application before the user can log in through the Identity Provider.

1. Click <IconButton icon="save" />.

</Steps>

<If condition={!props.no_login_button}>
The login page of each enabled Application then shows a login button for the Identity Provider. An Identity Provider with managed domains asks for the user's email address instead of showing a button.
</If>
