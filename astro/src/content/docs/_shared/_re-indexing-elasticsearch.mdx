A reindex rebuilds the search index from the database. Reindex in the following cases:

* You switch from the database search engine to the Elasticsearch search engine.
* You restore FusionAuth from a database backup, or start FusionAuth on a copy of the database.
* The search engine was unavailable while Users or Entities changed. Changes made during the outage don't reach the index after the search engine recovers, so searches return stale results until you reindex.
* FusionAuth support asks you to reindex.

To reindex in the Admin UI, navigate to <Breadcrumb>System -> Reindex</Breadcrumb>. Set **Select an index** to `User` or `Entity`, type `REINDEX` in **Confirm**, and click <Breadcrumb>Save</Breadcrumb>. The menu item appears only with the Elasticsearch search engine. To reindex from code, call the [Rebuild the Elasticsearch Index API](/docs/apis/system/rebuild-the-elasticsearch-index), and track progress with the [Retrieve the Status of an Index Rebuild API](/docs/apis/system/retrieve-the-status-of-an-index-rebuild).

<Aside type="caution">
A reindex reads every User and Entity from the database. On a large install, a reindex takes a long time and adds load to the database and the search engine. Run a reindex only when you need one.
</Aside>
