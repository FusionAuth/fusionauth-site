Each page in this section covers one email template: when FusionAuth sends the email, where you assign the template, an example, and every replacement variable the template receives. To write and manage templates, see [Create an Email Template](/docs/email/email-templates).

## Default and Example Templates

FusionAuth ships default templates for many workflows. A new FusionAuth instance lists the defaults in <Breadcrumb>Customizations -> Email Templates</Breadcrumb>, with names that start with `[FusionAuth Default]`. An instance set up with [Kickstart](/docs/get-started/develop/kickstart) has no defaults, so add the templates you need in the Kickstart file. The page for each of those templates shows the default.

FusionAuth ships no default for the other templates, such as Email Update and Password Update. FusionAuth sends those emails only after you create a template and assign the template. The page for each of those templates shows an example to start from.

## Retrieve the Templates as Files

The default templates live in [`extractedcode/templates-email`](https://github.com/FusionAuth/fusionauth-site/tree/main/astro/extractedcode/templates-email) in the docs repository, and the examples live in [`extractedcode/templates-email-examples`](https://github.com/FusionAuth/fusionauth-site/tree/main/astro/extractedcode/templates-email-examples). To download every default template at once:

```shell-session
npx degit FusionAuth/fusionauth-site/astro/extractedcode/templates-email templates-email
```

Without Node, pull the same folder out of a repository tarball:

```shell-session
curl -L https://github.com/FusionAuth/fusionauth-site/archive/refs/heads/main.tar.gz \
  | tar -xz --strip-components=4 fusionauth-site-main/astro/extractedcode/templates-email
```

Either command writes the templates into a `templates-email` directory. To download the examples, replace `templates-email` with `templates-email-examples` in either command.

## Replacement Variables

Every template receives **`tenant`** and **`baseUrl`**. Most templates also receive **`user`**, and receive **`application`** when the request that sends the email identifies an Application. Templates that FusionAuth sends for an event also receive **`event`**, the same object a webhook receives for that event.

A variable can be missing or `null`, so check optional values with the FreeMarker `??` operator, or give a default with `!`:

```ftl
[#if application??]
  Welcome to ${application.name}.
[/#if]
Hello ${user.firstName!'there'}.
```
