Most teams run FusionAuth in more places than production:

* A local instance on each developer machine.
* Short-lived instances that start and stop with each CI run.
* A long-lived staging instance that mirrors production.

Each environment needs a reliable way to reach a known configuration.

## Choose a Setup Tool

Use [Kickstart](/docs/get-started/develop/kickstart) for local and CI instances. [[Kickstart]] only runs on an instance with no API keys, users, or tenants, so every new instance starts from the same configuration. To reset a local instance, delete the database and restart FusionAuth.

Use [Terraform](/docs/deploy/production/terraform) for staging and production. A staging instance lives as long as production does and needs ongoing changes. Kickstart can't apply changes to an instance that already has configuration. Apply the same Terraform configuration to staging first, then to production. For more about keeping environments in sync, see [Deploy](/docs/deploy).

## Update Test Instances

Update local and CI instances whenever you update production. Test against the new version before production does. See [Update a Development Instance](/docs/update/dev-instance).
