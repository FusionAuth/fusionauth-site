The [FusionAuth Terraform provider](https://registry.terraform.io/providers/fusionauth/fusionauth/latest) manages FusionAuth configuration as Terraform resources. This guide creates a Tenant and an Application with Terraform. Then the guide brings the default Tenant and the FusionAuth Application under Terraform management. To decide what belongs in Terraform, see [Manage FusionAuth Configuration Across Environments](/docs/deploy).

Before you begin, install or set up:

* A running FusionAuth instance. To start an instance locally, see [Docker](/docs/get-started/install).
* [Terraform](https://developer.hashicorp.com/terraform/install) 1.5 or later, or [OpenTofu](https://opentofu.org/docs/intro/install/) 1.6 or later.

The [example repository](https://github.com/fusionauth/fusionauth-example-terraform) contains the configuration from this guide.

## Create Resources

### Get an API Key

Terraform calls the FusionAuth API with an API key. Terraform can't create the first key.

Create the key at <Breadcrumb>Settings -> API Keys</Breadcrumb>. A key with no endpoints selected can call every API. To limit what Terraform can change, select only the endpoints for the resources that Terraform manages. See [Managing API Keys](/docs/apis/authentication#managing-api-keys).

```shell-session

```

### Apply the Configuration

Preview the changes, then apply the changes:

```shell-session
terraform plan && terraform apply
```

Terraform lists the five resources to create and asks for confirmation. After the apply finishes, the `Forum` Application appears at <Breadcrumb>Applications</Breadcrumb>.

To change a resource later, edit `main.tf`. Then run `terraform plan` and `terraform apply` again. To delete a resource, remove the resource from `main.tf` and apply.

## Manage the Default Resources

The default Tenant and the FusionAuth Application exist before Terraform runs, so Terraform can't create these resources. To change the settings of a default resource, import the resource. To use a default resource without changing the resource, [reference the resource with a data source](#reference-a-resource-without-managing-it).

### Import the Default Resources

1. Find the Id of the default Tenant at <Breadcrumb>Tenants</Breadcrumb>. The FusionAuth Application has the Id `3c219e58-ed0e-4b18-ad48-f4f92793ae32` on every instance.
   <Screenshot id="operate-default-tenant-id" url="/admin/tenant/" alt="The details of the default Tenant, with the Tenant Id." height={1100} />
1. Add an [import block](https://developer.hashicorp.com/terraform/language/import) and a resource for the default Tenant and for the FusionAuth Application. Give each resource only the required arguments. Replace `<default-tenant-id>` with the Id of the default Tenant:
   <ExtractedCode src="example-terraform/main.snippet.importFirstPlan.tf" lang="hcl" title="Import the default resources" />
1. Run `terraform plan`. For each setting the configuration leaves out, the provider plans a change to a default value. The plan lists every value that differs from the instance:
   ```plaintext title="Output"
     # fusionauth_tenant.default will be updated in-place
     # (imported from "d7d09513-a3f5-401c-9685-34ab6c552453")
     ~ resource "fusionauth_tenant" "default" {
     ...
         ~ email_configuration {
     ...
             - default_from_name                                = "FusionAuth" -> null
     ...
             - implicit_email_verification_allowed              = true -> null
     ...
   Plan: 2 to import, 0 to add, 2 to change, 0 to destroy.
   ```
1. Copy each current value into the configuration. The current value is on the left of the arrow.
1. Run `terraform plan` again. Repeat the previous step until the plan shows `0 to change`. On a new instance, the configuration looks like this:
   <ExtractedCode src="example-terraform/main.snippet.importReconciled.tf" lang="hcl" title="Import the default resources with the current values" />
1. Run `terraform apply` to finish the import.

The values depend on the FusionAuth version and on any changes made in the Admin UI. Copy the values from the plan for your instance, not from the example.

<Aside type="caution">
FusionAuth doesn't allow deleting the default Tenant or the FusionAuth Application. With `prevent_destroy` set, Terraform stops at the plan. Without `prevent_destroy`, the apply fails partway through.
</Aside>

Keep the import blocks in the configuration. The blocks record that these resources came from FusionAuth, not from Terraform.

## Handle Changes Made Outside Terraform

A change made in the Admin UI or through the API doesn't update the Terraform configuration. The next `terraform apply` reverts the change. Run `terraform plan` first to see what the apply reverts.

To keep all changes in Terraform, limit who can change configuration in the Admin UI. See [Admin UI roles](/docs/concepts/types/roles#admin-ui-roles).

Some changes are expected. For example, an app might store settings in the **data** field of the FusionAuth Application that represents the app. List fields like **data** in [`ignore_changes`](https://developer.hashicorp.com/terraform/language/meta-arguments/lifecycle#ignore_changes), as the `Forum` Application does:

```hcl title="Ignore changes to the data field"
lifecycle {
  ignore_changes = [data]
}
```

To create a resource with Terraform but never update the resource, use `ignore_changes = all`.

## Protect Secrets

Terraform state contains secrets, such as OAuth client secrets and API keys. Before sharing state with a team, store the state in an encrypted backend with restricted access. See [Secrets](/docs/deploy#secrets).

To create more API keys with Terraform, use the `fusionauth_api_key` resource. With Terraform 1.11 or later, set the key with the [write-only](https://developer.hashicorp.com/terraform/language/manage-sensitive-data/write-only) `key_wo` argument. Terraform doesn't store write-only values in state.

## Limitations

<TerraformLimitations />

The provider supports most of the FusionAuth API. Support for a new feature can arrive a few weeks after the FusionAuth release. To request a missing resource or argument, open an issue in the [provider repository](https://github.com/fusionauth/terraform-provider-fusionauth). Until then, manage that part of the configuration with a [script](/docs/deploy#scripts).
