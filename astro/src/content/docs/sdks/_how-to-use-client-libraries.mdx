### Choose a Use Case

Client libraries wrap the [REST API](/docs/apis). You can use a client library for two tasks.

The main task is calling the FusionAuth APIs from code. You get auto-completion and typed objects, which helps when you script configuration, automate common tasks, or copy existing Applications and Groups. The API documentation lists the JSON structure of every request and which fields each call requires. When you need the details, read the API documentation and the library source code.

The secondary task is exchanging an authorization code for tokens in the Authorization Code grant. For this task, use an OAuth library for your language instead. For a list of libraries, see the [community curated list](https://oauth.net/code/).

Client libraries don't provide higher level functionality such as token management. To request that functionality, comment on or upvote the [open issue](https://github.com/FusionAuth/fusionauth-issues/issues/1674).

When a client library doesn't fit your needs, call the REST API directly.

### Requests and Responses

Each library maps a request object to the JSON that the matching API method requires. Depending on the API call, the request object is a set of string parameters or a complex object. When you use a language without static typing, read the API documentation for the operation to learn the expected fields.

Each library returns a response object with these fields:

* A status that matches the HTTP status code from the API. The status is `-1` when no HTTP request succeeded.
* A JSON success object when the call succeeds.
* A JSON error object with a message when the status is `4xx` or `5xx`.
* An exception object when the library sent no request or the server returned no usable response.

### Use Separate Clients for API Key Scopes

When a script calls endpoints with different API key scopes, create one client instance per scope. For example, Entities accept a tenant-scoped API key, but Entity Types and Lambdas require a global API key.

Follow these rules when your library lets you set a Tenant Id on the client instance:

* Set the Tenant Id on the tenant-scoped client only.
* Don't change the Tenant Id on a shared client between calls.
* Don't send a tenant header to a global-only endpoint. The endpoint [fails with a `401`](/docs/apis/authentication#global-api-key-authentication).
