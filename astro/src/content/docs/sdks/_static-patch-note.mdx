<AvailableSince since="1.14.0"/>

`PATCH` operations modify only parts of an object in FusionAuth. The {props.client_library_language} client library is statically typed, so the library doesn't use strongly typed objects for a `PATCH` request. Instead, you pass a hash, dictionary, or map of key value pairs. Build a multi-level dictionary that creates JSON with nested keys. Otherwise the `PATCH` request fails.

For example, to change only the name of an Application with `PATCH`, send this JSON:

```json title="Example PATCH Application JSON"
{
  "application": {
     "name": "hooli-bought-us"
   }
}
```

A typed request object serializes with empty arrays and other default values. Those values change the object in ways you don't expect. Nested key value pairs avoid the problem.

This limitation comes from the current implementation of the {props.client_library_language} client library and FusionAuth `PATCH` support. To support typed objects, the domain objects would need no default values, and the serializer would need to omit empty objects, empty arrays, and other empty values.

To use typed objects today, retrieve the object, modify the object in memory, and then update the object. This sequence works the same as a single `PATCH` operation.

For more information about future support, see the [open issue to handle `PATCH` requests with more nuance](https://github.com/FusionAuth/fusionauth-issues/issues/3020). The issue may add options for configuring a JSON serializer to allow typed domain objects with `PATCH`.
