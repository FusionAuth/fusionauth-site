The React SDK manages authentication state for your React application. The SDK provides functions to log in, register, and log out users, and you can configure the SDK to refresh tokens and fetch user information automatically.

<WebSdkOverview framework="React" />

## Install

For a full tutorial on FusionAuth and React, see the [FusionAuth React Quickstart](/docs/quickstarts/spa/react).

To install the SDK with npm, run:

```shell-session
npm install @fusionauth/react-sdk
```

To install the SDK with Yarn, run:

```shell-session
yarn add @fusionauth/react-sdk
```

## Configure the SDK

Wrap your application with `FusionAuthProvider`:

```jsx
import ReactDOM from 'react-dom/client';
import { FusionAuthProviderConfig, FusionAuthProvider } from '@fusionauth/react-sdk';

const config: FusionAuthProviderConfig = {
  clientId: "", // Your application's FusionAuth client Id
  redirectUri: "", // The URI that the user is directed to after the login/register/logout action
  serverUrl: "", // The url of the server that performs the token exchange
  shouldAutoFetchUserInfo: true, // Automatically fetch userInfo when logged in. Defaults to false.
  shouldAutoRefresh: true, // Enables automatic token refresh. Defaults to false.
  onRedirect: (state?: string) => { }, // Optional callback invoked upon redirect back from login or register.
  // useDpop: true, // Opt-in to DPoP mode. See "Use DPoP Mode" below. Defaults to false.
};

ReactDOM.createRoot(document.getElementById("my-app")).render(
  <FusionAuthProvider {...config}>
    <App />
  </FusionAuthProvider>
)
```

For a full list of configuration options, see [Web SDK Configuration](/docs/sdks/web-sdk-configuration).

### Configure with Next.js

When you use [Next.js](https://nextjs.org/), install [`next-client-cookies`](https://github.com/moshest/next-client-cookies?tab=readme-ov-file#install). Then pass `useCookies` in the config object as `nextCookieAdapter`:

```jsx
'use client'

import { useCookies } from 'next-client-cookies';

export default function Providers({ children }) {
  return (
    <FusionAuthProvider {...config} nextCookieAdapter={useCookies}>
      {children}
    </FusionAuthProvider>
  );
}
```

Wrap your layout in the `<CookiesProvider/>` from `next-client-cookies/server`. For more information about context providers in Next.js, see the Vercel guide to [rendering third-party context providers in server components](https://vercel.com/guides/react-context-state-management-nextjs#rendering-third-party-context-providers-in-server-components).

## Usage

### Use the useFusionAuth Hook

After you wrap your application in `FusionAuthProvider`, call `useFusionAuth` in any component:

```jsx
import { useFusionAuth } from '@fusionauth/react-sdk';

function MyComponent() {
  const {
    isLoggedIn,
    isFetchingUserInfo,
    startLogin,
    startRegister,
    userInfo
  } = useFusionAuth()

  if (isFetchingUserInfo) {
    return <p>Loading...</p>
  }

  if (!isLoggedIn) {
    return (
      <div>
        <button onClick={startLogin}>Login</button>
        <p>or</p>
        <button onClick={startRegister}>Register</button>
      </div>
    );
  }

  if (userInfo?.given_name) {
    return <p>Welcome {userInfo.given_name}!</p>
  }
}
```

You can also use the `withFusionAuth` higher-order component to access the SDK.

### Pass State Through Login

The `startLogin` and `startRegister` functions accept an optional string parameter named `state`. The SDK passes the value to the `onRedirect` callback on your `FusionAuthProviderConfig`. You can pass any value. A common choice is the page the user was on before login, so your application can return the user to that page after authentication.

### Protect Content

The `RequireAuth` component hides content from unauthorized users. Set the optional `withRole` prop to require a specific role. When you pass an array of roles, the user needs at least one of the roles. The `Unauthenticated` component shows content only to users who are not logged in.

```jsx
import { RequireAuth, useFusionAuth } from '@fusionauth/react-sdk';

const UserNameDisplay = () => {
  const { userInfo } = useFusionAuth();

  return (
    <>
      <RequireAuth>
        <p>User: {userInfo.given_name}</p> // Only displays if user is authenticated
      </RequireAuth>

      <Unauthenticated>
        <p>Please log in to view this page</p>
      </Unauthenticated>
    </>
  );
};

const AdminPanel = () => (
  <RequireAuth withRole="admin">
    <button>Delete User</button> // Only displays if user is authenticated and has 'admin' role
  </RequireAuth>
);
```

### Use the Pre-Built Buttons

The SDK includes pre-built login, logout, and registration buttons:

```jsx
import {
  FusionAuthLoginButton,
  FusionAuthLogoutButton,
  FusionAuthRegisterButton
} from '@fusionauth/react-sdk';

export const LoginPage = () => (
  <>
    <h1>Welcome, please log in or register</h1>
    <FusionAuthLoginButton />
    <FusionAuthRegisterButton />
  </>
);

export const AccountPage = () => (
  <>
    <h1>Hello, user!</h1>
    <FusionAuthLogoutButton />
  </>
);
```

## Use DPoP Mode

By default, the SDK calls a hosted backend that stores tokens in [[HttpOnly cookies]]. In DPoP mode, the SDK calls FusionAuth endpoints directly and binds tokens to a private key that the browser generates, per [RFC 9449](https://datatracker.ietf.org/doc/html/rfc9449). To enable DPoP mode, set `useDpop` to `true` on `FusionAuthProviderConfig`. The default is `false`.

The following configuration enables DPoP mode:

```jsx
const config: FusionAuthProviderConfig = {
  clientId: "",
  redirectUri: "",
  serverUrl: "",
  useDpop: true, // Opt-in to DPoP mode.
  dpopTokenStorage: 'localStorage', // 'localStorage' (default, persists across reloads) or 'memory'.
};
```

When `useDpop` is `true`, `useFusionAuth()` also returns `dpopFetch`, `generateProof`, and `getAccessToken`. These values are `undefined` when `useDpop` is `false` or missing.

The following code calls an API with each function:

```jsx
const { dpopFetch, generateProof, getAccessToken } = useFusionAuth();

// Recommended: attaches DPoP headers DPoP headers and retries nonce errors automatically.
const response = await dpopFetch('https://api.example.com/data', { method: 'GET' });

// Advanced: for axios or other HTTP libraries that can't use dpopFetch.
const accessToken = getAccessToken();
const proof = await generateProof('https://api.example.com/data', 'GET', accessToken);
// axios.get('https://api.example.com/data', {
//   headers: { Authorization: `DPoP ${accessToken}`, DPoP: proof }
// });
```
