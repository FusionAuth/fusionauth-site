The SDK sends users to the FusionAuth hosted login pages, which you can style with a [theme](/docs/theme). After login, FusionAuth sends users back to your {props.framework} application.

By default, the SDK uses the [hosted backend](/docs/apis/hosted-backend) on your FusionAuth instance, so your application needs no server code. The hosted backend exchanges the authorization code for tokens and stores the tokens in [[HttpOnly cookies]]:

* `app.at` holds the [access token](/docs/authentication/oauth/tokens#access-token). Your APIs read the access token to authorize requests.
* `app.rt` holds the [refresh token](/docs/authentication/oauth/tokens#refresh-token). The SDK uses the refresh token to get a new access token.

To run the token exchange on your own server instead, see [Use Your Own Backend](/docs/sdks/web-sdk-configuration#use-your-own-backend). To keep tokens in the browser and bind the tokens to a key, use [DPoP mode](#call-apis-in-dpop-mode).
