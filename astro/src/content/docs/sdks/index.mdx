Client libraries and SDKs help you integrate your application with FusionAuth. All FusionAuth client libraries are open source and hosted on the FusionAuth [GitHub account](https://github.com/FusionAuth). You can fork the libraries, change them, and read the code to learn how they work.

To generate your own client or browse endpoints and schemas, see the [OpenAPI specification](/docs/apis/openapi).

## SDKs Versus Client Libraries

A client library is a thin wrapper over the FusionAuth APIs. A client library covers all public FusionAuth API endpoints. Developers assemble the pieces to extend or manipulate FusionAuth to meet their needs.

Use a client library to manage FusionAuth from code. For example, you can rotate client secrets on a schedule. You can also use a client library to build login experiences that differ from the experiences FusionAuth offers out of the box. For example, you can prompt for a username, look up the User, show a custom password field, and then ask for a favorite color.

An SDK is an opinionated set of higher level constructs that focuses on a subset of functionality. SDKs help you finish common tasks quickly. SDKs usually target front end developers who work with mobile, React, Vue, Angular, or JavaScript.

An SDK provides:

* A button or function for logging in.
* A button or function for logging out.
* A button or function for registering a User.
* A filter or other way to examine roles and limit displayed information to a role or set of roles.
* A way to refresh a token without asking the User to re-authenticate.
* Secure access token and refresh token storage.

SDKs need minimal customization. To get both the simplicity of an SDK and the fine-grained control of a client library, use an SDK and a client library in the same application.
