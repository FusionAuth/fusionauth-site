The .NET Core client library integrates FusionAuth with your .NET Core application. The source code is in the [.NET Core client GitHub repository](https://github.com/FusionAuth/fusionauth-netcore-client).

## Install

Install the [`FusionAuth.Client` NuGet package](https://www.nuget.org/packages/FusionAuth.Client/):

```bash
Install-Package FusionAuth.Client
```

## FusionAuth Templates for .NET

FusionAuth publishes .NET templates as a [NuGet package](https://www.nuget.org/packages/FusionAuth.Templates/). The templates create new secured .NET applications from the .NET CLI or Visual Studio. The new applications use FusionAuth for authentication and authorization, and the applications use only standard .NET security libraries.

The package includes the following templates:

* `fusionauthblazorserver` creates a Blazor Server application.
* `fusionauthmvcwebapp` creates an MVC application.
* `fusionauthwebapi` creates a Web API application.

### Requirements

Before you use the templates, make sure you have:

* A FusionAuth installation. For more information, see [Install FusionAuth](/docs/get-started/install).
* The .NET Core 7.0 SDK or later.
* Visual Studio 2022 for Mac or Windows, version 17.6 or later, to create projects from Visual Studio. This requirement is optional.

### Install the Templates

Run the following command in a terminal:

```bash
dotnet new install FusionAuth.Templates::1.0.0
```

The templates then appear in the .NET CLI and Visual Studio. The installation works the same on Windows and macOS.

### Set Up FusionAuth

To create a valid Application in FusionAuth, use the [Kickstart file](https://github.com/FusionAuth/fusionauth-example-client-libraries/tree/main/kickstart/kickstart.json) from the example repository. For setup instructions, see the [templates README](https://github.com/FusionAuth/fusionauth-example-client-libraries/tree/main/dotnet/templates/README.md). For more information about Kickstart, see [Kickstart](/docs/get-started/develop/kickstart).

When you don't use the Kickstart file, create the Application manually with the values in the `kickstart.json` file.

The Kickstart file is designed for the first startup of FusionAuth, such as with `docker compose up`.

The Kickstart file assumes that your .NET project runs on `HTTPS` on port `5001`. When your project runs on a different port, update the **`authorizedRedirectURL`** and **`logoutURL`** variables in the `kickstart.json` file. Visual Studio picks a random port when port `5001` is in use, and IIS or another web server can use a different port too. At any time after the Kickstart file runs, you can also update the URLs on the <Breadcrumb>OAuth</Breadcrumb> tab of the Application settings in the Admin UI. For more information, see [Applications](/docs/concepts/types/applications#oauth).

### Handle the Client Secret

Some templates prompt for a FusionAuth Client Secret when you create a project. Use a non-sensitive secret from a local FusionAuth installation. When you use the Kickstart file, the Client Secret is `change-this-in-production-to-be-a-real-secret`.

Don't enter a production or sensitive Client Secret at the prompt. The template stores the secret in plain text in the `appsettings.Development.json` file, and the file may end up committed to your repository.

In production, provide the Client Secret with one of the secure methods that Microsoft recommends. To use an environment variable, set the platform-independent key `FusionAuth__ClientSecret`. For more information, see [Safe storage of app secrets in development in ASP.NET Core](https://learn.microsoft.com/en-us/aspnet/core/security/app-secrets?view=aspnetcore-7.0&tabs=windows) and the [environment variable instructions](https://learn.microsoft.com/en-us/aspnet/core/security/app-secrets?view=aspnetcore-7.0&tabs=windows#environment-variables).

### Create a Project

Create a project with the .NET CLI, Visual Studio for macOS, or Visual Studio for Windows.

#### .NET CLI

Navigate to your new project directory and run the following command:

```bash
dotnet new [template-name] [options]
```

Replace `[template-name]` with one of the template names listed above. Use `[options]` to provide your FusionAuth URL and FusionAuth Application Client Id. The following options are available:

* **`--issuer`** is the fully qualified URL of your FusionAuth server. The default value is `http://localhost:9011`.
* **`--client-id`** is the [Client Id](/docs/concepts/types/applications) of your Application. The default value is `3c219e58-ed0e-4b18-ad48-f4f92793ae32`.
* **`--port`** is the HTTPS port that [Kestrel](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/servers/kestrel?view=aspnetcore-7.0) uses. The default value is `5001`. After installation, you can change the port in the `appsettings.Development.json` file in the project root directory and in the `launchSettings.json` file in the `Properties` directory.

#### Visual Studio for macOS

The templates require Visual Studio for macOS version 17.6 or later. To create a project:

1. Create or open a Solution.
1. Select <Breadcrumb>File -> New Project</Breadcrumb>.
1. In the <Breadcrumb>New Project</Breadcrumb> dialog, select <Breadcrumb>Custom</Breadcrumb> from the left-hand menu.
1. Select the FusionAuth template you want to use and click <Breadcrumb>Continue</Breadcrumb>.
1. Enter the fully qualified URL of your FusionAuth server and the Client Id of your FusionAuth Application, and click <Breadcrumb>Continue</Breadcrumb>.
1. Set the project name and click <Breadcrumb>Create</Breadcrumb>.

#### Visual Studio for Windows

The templates require Visual Studio for Windows version 17.6 or later. To create a project:

1. Create or open a Solution.
1. Select <Breadcrumb>File -> New Project</Breadcrumb>.
1. In the <Breadcrumb>New Project</Breadcrumb> dialog, select `FusionAuth` from the **All project types** dropdown.
1. Select the FusionAuth template you want to use.
1. Set the project name and click <Breadcrumb>Next</Breadcrumb>.
1. Enter the fully qualified URL of your FusionAuth server and the Client Id of your FusionAuth Application.
1. Click <Breadcrumb>Create</Breadcrumb>.

### Test a Project

For instructions on testing projects that you create from the templates, see the testing section of the [templates README](https://github.com/FusionAuth/fusionauth-example-client-libraries/tree/main/dotnet/templates/README.md).

### Uninstall the Templates

Run the following command:

```bash
dotnet new uninstall FusionAuth.Templates
```

Then restart Visual Studio for the change to take effect.
