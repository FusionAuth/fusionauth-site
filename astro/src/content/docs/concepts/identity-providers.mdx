An Identity Provider lets users log in to FusionAuth with an account from a third party, such as Google, Okta, or a corporate SAML server. The third party checks the user's credentials. FusionAuth then logs the user in to your application and issues FusionAuth tokens. This approach is often called [[identity federation]].

Users don't create a password in FusionAuth. Your application still integrates with FusionAuth only, so your application code stays the same for every provider.

To set up a provider, see [Add an Identity Provider](/docs/authentication/identity-providers).

## How Login Works

The following diagram shows a login through an Identity Provider on the [[hosted login pages]]:

```mermaid title="Login with an external Identity Provider through the FusionAuth hosted login pages."
sequenceDiagram
    participant User as User's Browser
    participant App as Application
    participant FusionAuth
    participant IdP as Identity Provider
    User ->> App : Requests login
    App ->> User : Redirects to FusionAuth
    User ->> FusionAuth : Clicks the Identity Provider button
    FusionAuth ->> User : Redirects to the Identity Provider
    User ->> IdP : Logs in
    IdP ->> User : Redirects to FusionAuth with a code or assertion
    User ->> FusionAuth : Sends the code or assertion
    FusionAuth ->> FusionAuth : Validates the response
    FusionAuth ->> FusionAuth : Links or creates the FusionAuth user
    FusionAuth ->> User : Redirects to the Application with an authorization code
    User ->> App : Sends the authorization code
    App ->> FusionAuth : Exchanges the code for tokens
```

The application sends the user to FusionAuth, and the user picks a provider on the FusionAuth login page. The provider authenticates the user and sends the user back to FusionAuth. FusionAuth validates the response. For an OpenID Connect or OAuth provider, FusionAuth exchanges the code for tokens at the provider. FusionAuth then finds or creates the FusionAuth user. Finally, FusionAuth completes a standard OAuth login with the application. The application never talks to the provider.

## How FusionAuth Links Users

FusionAuth stores a [[Account Link::link]] between the user's identity at the provider and a FusionAuth user. On later logins, FusionAuth uses the link to find the same FusionAuth user.

A linking strategy decides how FusionAuth matches a new external identity to a FusionAuth user. For example, FusionAuth can link on a matching email address, or create a new user for every new identity. For the full list, see [Linking Strategies](/docs/authentication/identity-providers#linking-strategies).

## Integration Options

You can use an Identity Provider in the following ways:

* On the hosted login pages, FusionAuth shows a button for each provider and handles the redirects. You enable each provider per Application.
* On your own login page, your application calls the provider directly. Your application then sends the provider's code or token to the Complete Login API, and FusionAuth returns the user and tokens. For the API for each provider, see [Identity Providers APIs](/docs/apis/identity-providers).

The External JWT Identity Provider works only through the API. When your application already has a JWT from a third party, the External JWT Identity Provider exchanges that JWT for a FusionAuth login.
