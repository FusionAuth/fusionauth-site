Registrations in FusionAuth are the link between [Users](/docs/concepts/types/users) and [Applications](/docs/concepts/types/applications).

A User can have zero or more registrations. Each registration can have zero or more [roles](/docs/concepts/types/roles) associated with it. 


The [registrations API](/docs/apis/registrations) documents the allowed attributes of a User registration.

If a User exists in a [tenant](/docs/concepts/types/roles) and attempts to authenticate against an [Application](/docs/concepts/types/applications), but are not registered, the [authentication will succeed but they will not be authorized](/docs/concepts/authentication-authorization).

## Core Concepts Relationships

A Registration links one User to one Application. The Registration holds the Roles the User has in that Application. For the full model, see [Core Types](/docs/concepts/types).

```mermaid title="A Registration links a User to an Application and holds the User's Roles in that Application."
flowchart LR
    User -->|Has| Registration
    Registration -->|For| Application
    Registration -->|Holds| Role
```
