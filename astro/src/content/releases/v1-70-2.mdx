import Item from 'src/components/docs/release-notes/ReleaseNotesItem.astro';

<Item category="enhancement">
Improved refresh token reaping efficiency by cleaning expired refresh tokens more often.
</Item>

<Item category="enhancement">
The JWT populate lambda now has the Application populated in `context.application`, when available. `context.application` will be `null` in cases where you are not authenticating a user against an Application, for example, an `/api/login` call with no `applicationId`.
</Item>

<Item category="fix">
  When a user has a large number of Applications, editing the IdP configuration via the Admin UI becomes slow. The save button is now correctly disabled until the page has completed loading.
</Item>

<Item category="fix" since="1.70.1">
  In 1.70.0, the [OpenID Configuration](/docs/apis/oauth/openid-configuration) endpoint started adding the Tenant Id to the end of the **authorization_endpoint**, **device_authorization_endpoint**, **end_session_endpoint**, and **token_endpoint** values, even when the request doesn't specify a Tenant. This is a tenant specific endpoint and if you are using it for a non-default tenant case, you should supply the correct tenant Id to the openid-configuration endpoint. That said, in 1.70.2, if no tenant Id is supplied to the openid-configuration endpoint, the previous behavior of not including tenant Id on the **authorization_endpoint**, **device_authorization_endpoint**, **end_session_endpoint**, and **token_endpoint** is now restored.
</Item>
