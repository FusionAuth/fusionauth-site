<Item category="fix" since="1.69.2">
    Fixed an issue with passwordless logins where non-encoded query parameters cause an HTTP 403 error on `/confirmation-required` pages. This issue only affects customers that use the [Passwordless APIs](/docs/apis/passwordless/start-passwordless-login) directly to build an `/oauth2/passwordless` link (without encoding the query parameters) or customers that have modified their email/message templates and removed `value?url` from the state list that is used to build the URL.
</Item>
