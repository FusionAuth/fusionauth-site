<Item category="breaking-change">
Tightened restrictions around which keys may be used to verify JWTs and SAML payloads. You **must update your configuration before upgrading to `1.69.0`** if your instance meets any of the following criteria:

* you have recently rotated JWT signing keys according to the [key rotation documentation](/docs/operate/secure/key-rotation)
* you use an external [SAML](/docs/lifecycle/authenticate-users/identity-providers/overview-samlv2) or [JWT](/docs/lifecycle/authenticate-users/identity-providers/external-jwt/) Identity Provider (IdP) that rotates signing keys
* you use [FusionAuth as a SAML IdP](/docs/lifecycle/authenticate-users/saml) with required signing of authentication or logout requests and have rotated keys recently

For a full list of required changes, see the [migration guide](/docs/operate/troubleshooting/1-69-0-migration-guide).
</Item>

<Item category="new-feature" issue="3504">
Added an AI Agent Entity type. This entity type has one permission, `call`, which allows something to call the agent.
</Item>

<Item category="new-feature" issue="3162">
Added a webhook that captures creation of, updates to, and deletion of Entities.
</Item>

<Item category="enhancement">
Added explicit parameters to tenants, applications, and IDPs to support key rotation. See [the 1.69.0 migration guide](/docs/operate/troubleshooting/1-69-0-migration-guide) for more information. This also changes this recommended key rotation process. See the [key rotation documentation](/docs/operate/secure/key-rotation) for more information.
</Item>

<Item category="enhancement" issue="2807">
Added events to the [Audit Log](/docs/apis/audit-logs) that capture adding a user to a group and removing a user from a group.
</Item>

<Item category="enhancement" issue="3209">
Added support for overriding the SAML v2 service provider (SP) EntityId using **`identityProvider.issuer`** on standard SAML v2 identity providers (IdPs).

When configured, FusionAuth uses this value as the SP EntityId and expects the same value in the SAML assertion Audience.
</Item>

<Item category="enhancement" issue="3485">
Added a link from self-service account edit back to the source application. Advanced themes used to have to add a backlink manually, and simple themes dead-ended; now your users don't have to close the tab, they can return to your app.
</Item>

<Item category="enhancement" issue="3542">
Added support for sending a pre-hashed password to FusionAuth when changing a user's password with the [User API](/docs/apis/users/change-password). Use the `passwordFieldType` field to specify a `hashed` value, then pass values for `user.encryptionScheme`, `user.factor`, `user.password`, and `user.salt`. The [Import API](/docs/apis/users/import) already supports this configuration.
</Item>

<Item category="enhancement" issue="1383">
Added support for the `iss` OAuth 2.0 Authorization Server Issuer Identification standard, [RFC 9207](https://datatracker.ietf.org/doc/html/rfc9207).
</Item>

<Item category="fix" issue="3523" since="1.68.0">
Fixed an issue where the Impossible Travel [Risk Signal](/docs/lifecycle/authenticate-users/risk-signals) always returned status `LOW` if the instance had not yet fetched the IP geolocation dataset. Now, the signal does not report any value if the dataset has not yet been fetched.
</Item>

<Item category="fix" issue="3533" since="1.68.0">
Fixed an issue that could prevent a user from completing a registration missing required fields for a [social IdP](/docs/lifecycle/authenticate-users/identity-providers/).

<Item category="fix" issue="3538" since="1.68.0">
Fixed an issue that could prevent a custom form field label from appearing on a registration form.
</Item>

<Item category="fix" issue="2743" since="1.50.1">
Fixed an issue that could prevent a inactive IdP from displaying correctly in the Admin UI.
</Item>

<Item category="fix" issue="3089" since="1.57.0">
Fixed an issue where User MFA method validation did not check for duplicates when providing an `id` for the method. This allowed a user to add the same email account or phone number multiple times.

<Item category="fix" issue="3222" since="1.53.0">
Fixed an issue where a Generic Connector configured with a Login Validation Lambda would _always_ fail on first login for each user with `Unexpected FusionAuth error`.

<Item category="fix" issue="3525" since="1.68.0">
Fixed an issue where enabling "Email Plus content" on a consent failed to send an email with an error: `Cannot read field "baseURL" because "tenant" is null`.
</Item>

<Item category="fix" issue="3508" since="1.67.1">
Fixed an issue where, in account self-service, clicking the <Breadcrumb>Change password</Breadcrumb> repeatedly would disconnect the toggle state from the password change section visibility.

Fixed an issue where the default Enterprise User SCIM schema `meta.location` field contains a duplicate path segment, making it invalid.

<Item category="fix" issue="3385" since="1.63.0">
