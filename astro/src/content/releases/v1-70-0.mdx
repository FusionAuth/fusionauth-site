This migration adds a primary key to FusionAuth tables (that require one) for PostgreSQL logical replication, for example during a blue-green database migration.
</ReleaseNotesDBMigrate>

<Item category="new-feature">
Added support for [OAuth 2.0 Token Exchange](/docs/lifecycle/authenticate-users/oauth/token-exchange) ([RFC 8693](https://datatracker.ietf.org/doc/html/rfc8693)). A service can exchange a token it received for a new access token that targets a different service, while preserving the original user as the subject and recording the calling service as the actor. To set up an exchange, see [Delegate Access With Token Exchange](/docs/lifecycle/authenticate-users/oauth/token-exchange-delegation).
</Item>

<Item category="new-feature">
Added support for [Client ID Metadata Documents (CIMD)](/docs/lifecycle/authenticate-users/oauth/client-registration#client-id-metadata-documents). A client can describe itself in a JSON document hosted at its `client_id` URL, and FusionAuth registers it the first time it connects. This lets clients such as AI chat apps connect to your MCP server without manual Application setup.
</Item>

<Item category="new-feature">
Added support for [JSON-formatted log output](/docs/operate/troubleshooting#json-log-output) on `stdout`.
</Item>

<Item category="enhancement">
The [OpenID Configuration](/docs/apis/oauth/openid-configuration) endpoint now adds the Tenant Id to the end of the **authorization_endpoint**, **device_authorization_endpoint**, **end_session_endpoint**, and **token_endpoint** values, even when the request doesn't specify a Tenant. These endpoints now accept the Tenant Id as an optional URL segment. If a proxy or firewall in front of FusionAuth only allows exact paths such as `/oauth2/token`, update it to allow the Tenant Id segment.

The response also includes a new **client_id_metadata_document_supported** value.
</Item>

<Item category="enhancement">
Increased the default values for the following [database configuration](/docs/reference/configuration) settings:

* `database.maximum-pool-size` from `20` to `40`
* `database.connection-timeout` from `2,000` milliseconds to `30,000` milliseconds

If you set these values explicitly, FusionAuth continues to use your values.
</Item>
