For backward compatibility, a `PATCH` request with a `Content-Type` of `application/json` accepts the same body as the `PUT` request. FusionAuth merges the request into the existing object:

* FusionAuth keeps every field that the request leaves out, so send only the fields you want to change.
* FusionAuth merges a map, such as **`data`**, by key. To remove a key, set the key to `null`.
* FusionAuth appends the values in a request array to the existing array, unless this API documents otherwise. An empty array leaves the existing array unchanged, so you can't remove values from an appending array.
* FusionAuth adds each object in an array of objects as a new element. FusionAuth doesn't match the object to an existing element by Id or by position.
* Don't send a value that an array of Ids already contains, such as a key Id or a Tenant Id. Some of these arrays then return a `500` status code.
* Don't set an array to `null`. Depending on the field, FusionAuth clears the array or returns a `500` status code.

To remove values from an array, `PUT` the full object, or set the `Content-Type` to one of the following media types:

* `application/json-patch+json` for [JSON Patch (RFC 6902)](https://www.rfc-editor.org/rfc/rfc6902)
* `application/merge-patch+json` for [JSON Merge Patch (RFC 7396)](https://www.rfc-editor.org/rfc/rfc7396)

For more information, see [The PATCH HTTP Method](/docs/apis#the-patch-http-method).
